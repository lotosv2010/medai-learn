## 一、结论摘要

1. **候选池收敛到 3 个，不是 6 个。** 合规先行——数据不出境 → 只剩 DeepSeek Flash、DeepSeek V4 Pro、通义 Qwen3.8 Flash 三个可用选项；Qwen3.8 Max 与两个 Claude 模型因成本或出境问题不进候选池。
2. **默认方案：DeepSeek Flash 打底 + V4 Pro 兜底，70/30 路由。** 成长期场景（日均 1 万次）月成本 ¥1560，比全走 V4 Pro 省 52%。缓存命中 80% 时可再往下降（详见第四节）。
3. **单看单价会选错，且错在「看起来更便宜」的方向。** Claude Haiku 5.5 的裸单价最低，但它用新 tokenizer（同文本多约 30% token），补齐后是 ¥0.00212 对 DeepSeek Flash 的 ¥0.0020——**反而更贵**；而它数据出境，医疗场景直接出局。

## 三、成本测算（三个工作负载）

计算公式：`单次 = (输入 token × 输入价 + 输出 token × 输出价) / 1e6`，`月 = 单次 × 日均 × 30`。

| 模型 | 每次成本 | 日成本 | 月成本 |
|---|---|---|---|
| DeepSeek Flash | ¥0.0020 | ¥2 | ¥60 |
| DeepSeek V4 Pro | ¥0.0076 | ¥8 | ¥229 |
| Qwen3.8 Flash | ¥0.0019 | ¥2 | ¥56 |
| Qwen3.8 Max | ¥0.02 | ¥24 | ¥724 |
| Claude Haiku 5.5 | ¥0.0016 | ¥2 | ¥49 |
| Claude Sonnet 5.5 | ¥0.03 | ¥33 | ¥980 |

### 场景 B：成长期（日均 10000 次，输入 1200 / 输出 400）

| 模型 | 每次成本 | 日成本 | 月成本 |
|---|---|---|---|
| DeepSeek Flash | ¥0.0028 | ¥28 | ¥840 |
| DeepSeek V4 Pro | ¥0.01 | ¥108 | ¥3240 |
| Qwen3.8 Flash | ¥0.0026 | ¥26 | ¥786 |
| Qwen3.8 Max | ¥0.03 | ¥341 | ¥1.02 万 |

| Claude Sonnet 5.5 | ¥0.05 | ¥454 | ¥1.36 万 |

### 场景 C：RAG 真实形态（日均 10000 次，输入 5000 / 输出 250）

这一组是本项目真实会遇到的形态——说明书片段占了输入的大头。

| 模型 | 每次成本 | 月成本 |
|---|---|---|

**读法：输入从 1200 涨到 5000，DeepSeek Flash 的月成本从 ¥840 涨到 ¥1800，翻一倍多。** 在长输入任务上，「少放检索片段」比「换模型」有效得多。

## 四、缓存与路由测算

### 缓存（场景 B，输入 1200 / 输出 400，日均 1 万）

| 模型 | 命中率 0% | 命中率 50% | 命中率 80% |
|---|---|---|---|
| DeepSeek Flash | ¥840 | ¥664 | ¥558 |
| Claude Sonnet 5.5 | ¥1.36 万 | ¥1.12 万 | ¥9747 |

结论：**输入价越贵，缓存的绝对节省越大，但相对节省接近**（两者都约 1/3）。缓存对「固定 System Prompt + 固定说明书」这类场景是必选项，不是优化项。

### 路由（场景 B）

| 方案 | 月成本 | 相对全用强模型 |
|---|---|---|
| 全部走 DeepSeek V4 Pro | ¥3240 | 100% |
| 70/30 → Flash + V4 Pro | ¥1560 | 48% |
| 全部走 Claude Sonnet 5.5 | ¥1.36 万 | 100% |
| 70/30 → Flash + Sonnet | ¥4678 | 34% |

结论：**同厂商双档省 52%，跨厂商省 66%。** 但跨厂商要吸收两套 API 的差异（错误格式、限流、流式协议），这部分工作量在阶段二的「多模型抽象」里解决。

**路由不是免费的**：判断成本（规则或分类器有误判率）、一致性成本（同用户两轮落到不同模型，风格会跳）、运维成本（两套 key / 限额 / 降级链）。判据不是「能省多少」，是「省下的钱够不够覆盖误判损失」。误判的代价是非对称的——复杂问题误判到小模型是答错，必须做成单向可升级。

## 五、四维选型决策表

顺序不可反：合规 → 复杂度 → 上下文 → 成本。

| 维度 | 判断规则 | 本项目的结论 |
|---|---|---|
| 合规 | 数据能否出境？不能则只看境内 / 私有化 | 患者信息可能入 prompt → **两个 Claude 模型出局** |
| 复杂度 | 多步推算 vs 抽取分类 | 剂量折算、相互作用 → **走 V4 Pro 思考档**；其余走 Flash |
| 上下文 | 单轮短问答 32K 够，长文档 128K 起 | RAG 说明书片段 3000 token 量级，**1M 窗口绰绰有余**，但窗口大 ≠ 该塞满（见第 01 篇 Lost in the Middle） |
| 成本 | 每次成本 × 日均 × 30 | 场景 B 下 **Flash + V4 Pro 路由 = ¥1560/月**，是可行解 |

按任务分派的落地建议：

| 任务类型 | 建议模型 | 理由 |
|---|---|---|
| 药品分类、禁忌查询、一句话提醒 | DeepSeek Flash | 单步事实问答，开思考是浪费 |
| 剂量折算、相互作用判断、多步推算 | DeepSeek V4 Pro（思考档） | 有「中途发现想错了」的空间 |
| 长说明书摘要、跨段信息整合 | DeepSeek Flash（长输入 + 短输出） | 输入便宜，且不需要推理档 |
| 高并发兜底 | 通义 Qwen3.8 Flash | 与 DeepSeek 互为备份，同价位同能力档 |

**不选 Qwen3.8 Max 的理由**：能力档比 Flash 高一档，但单价是 Flash 的 13 倍，在本项目的任务分布上（70% 简单问答）拿不到对应的收益。如果将来出现「需要强推理 + 不能开思考档」的场景，再重新评估。

## 六、与 ADR-0002 的关系

`docs/decisions/0002-ai-model-strategy.md`（2025-01-01）定的主力模型是 Claude，降级链是 Claude → GPT-4o-mini → 通义千问 Plus。

本文档**不推翻 ADR，也不与之冲突**，两点说明：

1. **ADR 定的是「默认值」，本文档给的是「按任务与合规重算的依据」。** ADR 的 Claude 决策基于 200K 长上下文与「不确定时倾向拒答」的特性，那两条理由现在依然成立；但它的成本条款写的是「Phase 1 先硬编码，Phase 2 再实现路由」，本文档正是 Phase 2 之前必须有的那张账。
2. **有一处实质性冲突需要走新 ADR**：ADR 未把「数据出境」作为硬门槛处理，而本文档把合规排在选型第一位。若产品确认 prompt 中会出现患者信息，则 Claude 系出局，ADR 的主力模型需要重新议。**建议提一份新 ADR 记录这个变更，而不是直接改代码。**
