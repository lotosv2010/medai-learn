# 一、软件生命周期
## 可行性分析报告和软件开发计划
+ 产出可行性分析报告

## 需求分析阶段
+ 由软件分析师来做，需要懂技术也需要懂业务
+ 分析出软件需要完成什么功能
+ 产出需求分析说明书和初步的用户手册

## 软件设计(概要设计和详细设计)
+ 由架构师/项目经理来做
+ 根据团队技术基础确定用什么技术栈(Java/Node/Php)
+ 确定部署的操作系统
+ 使用什么数据库(oracle/mysql/sqlserver)
+ 设计数据库表
+ 选择团队成员
+ 产出软件设计文档

## 编码工作
+ 开发人员来做
+ 把设计编成代码
+ 产出源代码以及清单

## 测试阶段
+ 由测试工程师进行
+ 分为白盒测试(单元测试)和黑盒测试(功能测试)
+ 产出测试报告

## 实施和运维
+ 由实施工程师执行
+ 把项目按照需要安装和配置好，让客户使用并解决简单问题
+ 产出软件维护报告

# 二、软件开发模型
## 瀑布模型
+ 瀑布模型(Waterfall Model)是一个项目开发架构
+ 开发过程是通过设计一系列阶段顺序展开的，从系统需求分析开始直到产品发布和维护，每个阶段都会产生循环反馈
+ 如果有信息未被覆盖或者发现了问题，那么最好"返回"上一个阶段并进行适当的修改，项目开发进程从一个阶段"流动"到下一个阶段，这就是瀑布模型名称的由来

# 四、模型图
## 用例图(Use Case Diagram)
+ 用例图建模最主要的功能是表达系统的功能性需求或行为
+ 参互者：参与者指定是与系统交互的角色，可以是人，也可以是事物或其他系统
+ 用例是系统为参与者提供的功能，用例名称一般是一个带有动作性的词语

## 类图(Class Diagram)
+ 类图(Class Diagram)描述类的静态结构，定义类以及描述类之间的联系，如关联、依赖、聚合等，还包括类的内部结构(类的属性和操作)
+ 类图是一种静态模型类型，一个类图根据系统中的类以及各个类之间的关系描述系统的静态结构
+ 类图包含七个元素
    - 类(Class)
    - 接口(Interface)
    - 协作(Collaboration)
    - 依赖关系(Dependency)
    - 泛化关系(Generalization)
    - 关联关系(Association)
    - 实现关系(Realization)

### 类的表示
| **类型** | **示例** |
| --- | --- |
| 属性格式 | name: attribute type = default value |
| 操作格式 | name(parameter list): type of value returned |


### 对象图(Object Diagram)
+ 对象描述一组对象和他们之间的关系，它是系统状态的某一时刻的快照，它的使用相当有限，它主要用于了解系统在某个特定时刻的具体状况和数据结构
+ 对象表示方法和类图大致相同，对象图中的对象属性可以有具体值，类图中的一个类可以对应成对象图中的多个对象，例如：部门的自关联就可以对应成多个部门之间的关联

#### 关联关系(Association)
+ 关联关系实际上就是类与类之间的关系，他是依赖关系的特例
+ 关联关系比依赖关系的关系更强
+ 关联具有导航性，即双向关系或单向关系，表示关系在那一方维护
+ 关联具有多重性，如
    - `1`：表示有且仅有一个
    - `0...`：表示0或多个
    - `0,1`：表示0或1个
    - `n..m`：表示n到m个都可以
    - `m...`：表示至少m个

#### 聚合关系(Aggregation)
+ 聚合关系表示是整体和部分的关系，整体与部分可以分开
+ 聚合关系是关联关系的特例，所以它具有关联的导向性和多重性
+ 聚合的双方生命周期是独立的

### 代码实现
```typescript
class Water {}

class Animal {
  public name?: string;
  public age?: number;
  // 类的依赖关系在代码中的表示是属性关系，这就是依赖关系
  public water?: Water;
  public eat() {}
  public drink() {}
}

// 接口是行为的抽象
interface Eggs {
  layEggs(): number;
}

class Bird extends Animal implements Eggs{
  public swing?: number;
  public fly() {}
  layEggs(): number {
    return 2;
  }
}

class TangDuckFather {}
class TangDuckFriend{}
class TangDuckWife{}
class TangDuckChild{}
class TangDuckHouse{}
class TangDuck extends Bird {
  public father?: TangDuckFather;
  public friends?: Array<TangDuckFriend>;
  public wife?: TangDuckWife;
  public children?: Array<TangDuckChild>;
  public house?: Array<TangDuckHouse>;
}

class Wing {}
class WildGoose extends Bird {
  public wings?: Wing[];
}
class WildGooseGroup {
  public wildGoose?: WildGoose[];
}
```

## 时序图(**<font style="color:rgb(59, 69, 78);">Sequence</font>** Diagram)
+ 时序图强调消息时间顺序的交互图
+ 时序图描述系统中类与类之间的交互，它将这些交互建模换成消息交互
+ 时序图用于描述对象之间如何随着时间进行协作
+ 时序图有活动者(Actor)、对象(Object)、消息(Message)、生命线(Lifeline)和控制焦点(Focus Of Control)组成
+ 不同元素不同表示
    - 对象：一个矩形，对象名称下有下划线
    - 消息：方向箭头表示，调用时实线，返回消息时虚线
    - 生命线：纵向的虚线表示
    - 控制焦点：纵向的矩形，也就是活动条(Activation Bar)

## 协作图(<font style="color:rgb(51, 51, 51);">Communication</font> Diagram)
+ 协作图是时序图的一种变种
+ 协作图强调的是发送和接收消息的对象之间的组织结构
+ 协作图显示了一系列对象和在这些对象之间的联系以及对象之间发送和接收的消息
+ 时序图主要侧重于对象间消息传递在时间上的先后关系，而协作图则侧重于对象间以及对象和角色交互的静态关系

## 组件图(<font style="color:rgb(34, 34, 34);">Component</font> Diagram)
+ 组件图用来建立系统的各个组件之间的关系，它们是通过软件或者文件组织在一起，使用组件图可以帮助读者了解某个功能位于软件包中的那个位置，以及各个版本之间组件包含哪些功能

## 部署图(D<font style="color:rgb(34, 34, 34);">eployment</font> Diagram)
+ 部署图是来帮助读者了解软件中各个组件运行硬件什么位置，以及这些硬件之间的交互关系
+ 节点：用来表示一种硬件，可以是服务器，计算机等，节点的符号是一个三维盒子，在左上角包含节点名称
+ 通信关联：节点通过通信关联建立彼此的关系，采用从节点到节点绘制实线表示关联
