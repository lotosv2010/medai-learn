# <font style="color:rgb(51, 51, 51);">为什么需要设计数据库</font>
## <font style="color:rgb(51, 51, 51);">良好的数据库设计</font>
+ <font style="color:rgb(51, 51, 51);">节省数据的存储空间</font>
+ <font style="color:rgb(51, 51, 51);">能够保证数据的完整性</font>
+ <font style="color:rgb(51, 51, 51);">方便进行数据库系统的开发</font>

## <font style="color:rgb(51, 51, 51);">糟糕的数据库设计</font>
+ <font style="color:rgb(51, 51, 51);">数据冗余，存储空间浪费</font>
+ <font style="color:rgb(51, 51, 51);">内存空间浪费</font>
+ <font style="color:rgb(51, 51, 51);">数据和更新插入异常</font>

# <font style="color:rgb(51, 51, 51);">软件项目开发周期中的数据库设计</font>
+ <font style="color:rgb(51, 51, 51);">需求分析阶段: 分析客户的业务和数据处理需求</font>
+ <font style="color:rgb(51, 51, 51);">概要设计阶段： 设计数据库的E-R模型图，确认需求的正确和完整性</font>
+ <font style="color:rgb(51, 51, 51);">详细设计阶段： 应用三大范式审核数据库</font>
+ <font style="color:rgb(51, 51, 51);">代码编写阶段： 物理实现数据库，编码实现应用</font>
+ <font style="color:rgb(51, 51, 51);">软件测试阶段</font>
+ <font style="color:rgb(51, 51, 51);">安装部署</font>

> <font style="color:rgb(119, 119, 119);">现实世界->信息世界->数据库模型图->数据库</font>
>

# <font style="color:rgb(51, 51, 51);">设计数据库的步骤</font>
## <font style="color:rgb(51, 51, 51);">收集信息</font>
+ <font style="color:rgb(51, 51, 51);">与相关人员进行交流、访谈充分了解用户需求，理解数据库需要完成的任务</font>

## <font style="color:rgb(51, 51, 51);">标示实体(Entity)</font>
+ <font style="color:rgb(51, 51, 51);">标识数据库要管理的关键对象或者实体，实体一般是名词</font>

## <font style="color:rgb(51, 51, 51);">标示实体的属性(Attribute)</font>
## <font style="color:rgb(51, 51, 51);">标示实体之间的关系(RelationShip)</font>
# <font style="color:rgb(51, 51, 51);">数据库ER图</font>
+ <font style="color:rgb(51, 51, 51);">ER图：实体关系图，简记E-R图，是指以实体、关系、属性三个基本概念概括数据的基本结构，从而描述静态数据结构的概念模式</font>

## <font style="color:rgb(51, 51, 51);">ER图的实体（entity）</font>
+ <font style="color:rgb(51, 51, 51);">ER图的实体（entity）即数据模型中的数据对象，例如人、学生、音乐都可以作为一个数据对象，用长方体来表示</font>

## <font style="color:rgb(51, 51, 51);"> ER图的属性（attribute）</font>
+ <font style="color:rgb(51, 51, 51);">ER图的属性（attribute）即数据对象所具有的属性，例如学生具有姓名、学号、年级等属性，用椭圆形表示</font>
+ <font style="color:rgb(51, 51, 51);">属性分为唯一属性（ unique attribute）和非唯一属性</font>
+ <font style="color:rgb(51, 51, 51);">唯一属性指的是唯一可用来标识该实体实例或者成员的属性，用下划线表示，一般来讲实体都至少有一个唯一属性。</font>

## <font style="color:rgb(51, 51, 51);">ER图的关系（relationship）</font>
+ <font style="color:rgb(51, 51, 51);">ER图的关系（relationship）用来表现数据对象与数据对象之间的联系</font>
+ <font style="color:rgb(51, 51, 51);">例如学生的实体和成绩表的实体之间有一定的联系，每个学生都有自己的成绩表，这就是一种关系，关系用菱形来表示。</font>

## <font style="color:rgb(51, 51, 51);">ER图中关联关系</font>
### <font style="color:rgb(51, 51, 51);">1对1 (1:1)</font>
+ <font style="color:rgb(51, 51, 51);">1对1关系是指对于实体集A与实体集B，A中的每一个实体至多与B中一个实体有关系；反之，在实体集B中的每个实体至多与实体集A中一个实体有关系。</font>

### <font style="color:rgb(51, 51, 51);">1对多（1:N）</font>
+ <font style="color:rgb(51, 51, 51);">1对多关系是指实体集A与实体集B中至少有N(N>0)个实体有关系；并且实体集B中每一个实体至多与实体集A中一个实体有关系。</font>

+ <font style="color:rgb(51, 51, 51);">多对多关系是指实体集A中的每一个实体与实体集B中至少有M(M>0)个实体有关系，并且实体集B中的每一个实体与实体集A中的至少N（N>0）个实体有关系。</font>

# <font style="color:rgb(51, 51, 51);">数据库设计三大范式</font>
## <font style="color:rgb(51, 51, 51);">不合理的表设计</font>
+ <font style="color:rgb(51, 51, 51);">信息重复</font>
+ <font style="color:rgb(51, 51, 51);">更新异常</font>
+ <font style="color:rgb(51, 51, 51);">插入异常</font>
+ <font style="color:rgb(51, 51, 51);">删除异常</font>

## <font style="color:rgb(51, 51, 51);">三大范式</font>
### <font style="color:rgb(51, 51, 51);">第一范式（1NF）</font>
+ <font style="color:rgb(51, 51, 51);">数据表中的每一列（每个字段）必须是不可拆分的最小单元，也就是确保每一列的原子性；</font>

### <font style="color:rgb(51, 51, 51);">第二范式（2NF）</font>
+ <font style="color:rgb(51, 51, 51);">满足1NF后，要求表中的所有列，都必须依赖于主键，而不能有任何一列与主键没有关系，也就是说一个表只描述一件事情</font>

### <font style="color:rgb(51, 51, 51);">第三范式（3NF）</font>
+ <font style="color:rgb(51, 51, 51);">必须先满足第二范式（2NF），要求：表中的每一列只与主键直接相关而不是间接相关，(表中的每一列只能依赖于主键)</font>
+ <font style="color:rgb(51, 51, 51);">数据不能存在传递关系,即每个属性都跟主键有直接关系而不是间接关系</font>

### <font style="color:rgb(51, 51, 51);">如何更好的区分三大范式</font>
+ <font style="color:rgb(51, 51, 51);">第一范式和第二范式的区别在于有没有分出两张表,第二范式是说一张表中包含了所种不同的实体属性，那么要必须分成多张表</font>
+ <font style="color:rgb(51, 51, 51);">第三范式是要求已经分成了多张表，那么一张表中只能有另一张表中的id（主键），而不能有其他的任何信息（其他的信息一律用外键在另一表的主键看查询）。</font>

# <font style="color:rgb(51, 51, 51);">RBAC</font>
+ <font style="color:rgb(51, 51, 51);">基于角色的权限访问控制（Role-Based Access Control）</font>
+ <font style="color:rgb(51, 51, 51);">RBAC（Role-Based Access Control，基于角色的访问控制），就是用户通过角色与权限进行关联</font>
+ <font style="color:rgb(51, 51, 51);">简单地说，一个用户拥有若干角色，每一个角色拥有若干权限。这样，就构造成“用户-角色-权限-资源”的授权模型</font>
+ <font style="color:rgb(51, 51, 51);">在这种模型中，用户与角色之间，角色与权限之间，权限与资源之间一般是多对多的关系。</font>
+ <font style="color:rgb(51, 51, 51);">在RBAC中最重要的概念包括：用户(User)，角色(Role)，权限(Permission)，资源(Resource)</font>

## 安全原则
+ <font style="color:rgb(51, 51, 51);">最小权限原则之所以被RBAC所支持，是因为RBAC可以将其角色配置成其完成任务所需要的最小的权限集</font>
+ <font style="color:rgb(51, 51, 51);">责任分离原则可以通过调用相互独立互斥的角色来共同完成敏感的任务而体现，比如要求一个计帐员和财务管理员共参与同一过帐。</font>
+ <font style="color:rgb(51, 51, 51);">数据抽象可以通过权限的抽象来体现，如财务操作用借款、存款等抽象权限，而不用操作系统提供的典型的读、写、执行权限</font>

# <font style="color:rgb(51, 51, 51);">事务</font>
## <font style="color:rgb(51, 51, 51);">为什么需要事务</font>
+ <font style="color:rgb(51, 51, 51);">银行转账问题</font>
+ <font style="color:rgb(51, 51, 51);">A账户资金减少</font>
+ <font style="color:rgb(51, 51, 51);">B账户资金增加</font>

```sql
create database bank;
use bank;
create table account
(
  name varchar(64),
  balance decimal(10,2)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
insert into account(name,balance) values('张三',100);
insert into account(name,balance) values('李四',100);

update account set balance = balance - 10 where name = '张三';
update account set balance = balance + 10 where name = '李四';
```

## <font style="color:rgb(51, 51, 51);">什么是事务</font>
+ <font style="color:rgb(51, 51, 51);">事务是作为单个逻辑工作单元执行的一系列操作</font>
+ <font style="color:rgb(51, 51, 51);">多个操作作为一个整体向系统提交，要么都执行，要么都不执行</font>
+ <font style="color:rgb(51, 51, 51);">事务是一个不可分割的工作逻辑单元</font>

> <font style="color:rgb(119, 119, 119);">转账过程就是一个整体，它需要两条UPDATE语句，如果任何一个出错，则整个转账业务取消，两个账户的余额都恢复到原来的数据，确保总余额不变</font>
>

## <font style="color:rgb(51, 51, 51);">事务的特性</font>
+ <font style="color:rgb(51, 51, 51);">原子性(Atomicity) 事务是一个完整的操作，事务各个部分是不可分的，要么都执行，要么都不执行</font>
+ <font style="color:rgb(51, 51, 51);">一致性(Consistency) 当事务完成后，数据必须处理完整的状态</font>
+ <font style="color:rgb(51, 51, 51);">隔离性(Isolation) 并发事务彼此隔离、独立，它不应该以任何方式依赖于其它事务</font>
+ <font style="color:rgb(51, 51, 51);">持久性(Durability) 事务完成后，它对数据库的修改被永久保持</font>

## <font style="color:rgb(51, 51, 51);">如何创建事务</font>
+ <font style="color:rgb(51, 51, 51);">开始事务</font><font style="color:rgb(51, 51, 51);"> </font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">START TRANSACTION</font>`<font style="color:rgb(51, 51, 51);"> </font><font style="color:rgb(51, 51, 51);">或者</font><font style="color:rgb(51, 51, 51);"> </font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">BEGIN</font>`
+ <font style="color:rgb(51, 51, 51);">提交事务</font><font style="color:rgb(51, 51, 51);"> </font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">COMMIT</font>`
+ <font style="color:rgb(51, 51, 51);">回滚或者说撤销事务</font><font style="color:rgb(51, 51, 51);"> </font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">ROLLBACK</font>`

```plain
BEGIN;
update account set balance = balance - 10 where name = '张三';
ROLLBACK;
```

+ <font style="color:rgb(51, 51, 51);">默认情况下，每条单独的SQL语句视为一个事务</font>
+ <font style="color:rgb(51, 51, 51);">关闭默认提交状态后，可手动开启、关闭事务</font>
+ <font style="color:rgb(51, 51, 51);">关闭/开启自动提交状态</font><font style="color:rgb(51, 51, 51);"> </font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">SET autocommit=0|1</font>`<font style="color:rgb(51, 51, 51);"> </font><font style="color:rgb(51, 51, 51);">0关闭 1开启</font>

> <font style="color:rgb(119, 119, 119);">关闭自动提交后，从下一条SQL语句开始开启新的事务，需要使用COMMIT或ROLLBACK结束该事务</font>
>

# <font style="color:rgb(51, 51, 51);">锁</font>
+ <font style="color:rgb(51, 51, 51);">锁时计算机协调多个进程或线程并发访问某一资源的机制</font>

## <font style="color:rgb(51, 51, 51);">锁的分类</font>
+ <font style="color:rgb(51, 51, 51);">从对数据库操作的类型分，分为读锁和写锁</font>
    - <font style="color:rgb(51, 51, 51);">读锁（共享锁）：针对同一份数据，多个读操作可以同时进行而不会互相影响</font>
    - <font style="color:rgb(51, 51, 51);">写锁（排它锁）：当前写操作没有完成前，它会阻断其他写锁和读锁</font>
+ <font style="color:rgb(51, 51, 51);">从对数据操作的粒度分，分为</font>
    - <font style="color:rgb(51, 51, 51);">表锁</font>
    - <font style="color:rgb(51, 51, 51);">行锁</font>

## <font style="color:rgb(51, 51, 51);">表锁</font>
+ <font style="color:rgb(51, 51, 51);">表锁偏向</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">MyISAM</font>`<font style="color:rgb(51, 51, 51);">存储引擎，开销小，加锁快，锁定粒度大，发生锁冲突的概率最高，并发度最低</font>

##### <font style="color:rgb(51, 51, 51);">更新丢失（Lost Update）</font>
+ <font style="color:rgb(51, 51, 51);">当两个或多个事务选择同一行，然后基于最初选定的值更新该行时，由于每个事务都不知道其他事务的存在，就会发生丢失更新问题–最后的更新覆盖了由其他事务所做的更新。</font>
+ <font style="color:rgb(51, 51, 51);">后面的事务覆盖了前面的值,这是正常现象</font>

##### <font style="color:rgb(51, 51, 51);">脏读（Dirty Reads）</font>
+ <font style="color:rgb(51, 51, 51);">一个事务正在对一条记录做修改，在这个事务完成并提交前，这条记录的数据就处于不一致的状态；这时，另一个事务也来读取同一条记录，如果不加控制，第二个事务读取了这些</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">脏</font>`<font style="color:rgb(51, 51, 51);">数据，并据此作进一步的处理，就会产生未提交的数据依赖关系。这种现象被形象的叫做</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">脏读</font>`<font style="color:rgb(51, 51, 51);">。</font>
+ <font style="color:rgb(51, 51, 51);">一句话：事务A读取到了事务B已经修改但尚未提交的数据，还在这个数据基础上做了操作。此时，如果B事务回滚，A读取的数据无效，不符合一致性要求。</font>
+ <font style="color:rgb(51, 51, 51);">脏读是事务B里面修改了数据 ,这是不正常的</font>
+ <font style="color:rgb(51, 51, 51);">解决办法：如果在第一个事务提交前，任何其他事务不可读取其修改过的值，则可 以避免该问题。</font>

##### <font style="color:rgb(51, 51, 51);">幻读（Phantom Reads）</font>
+ <font style="color:rgb(51, 51, 51);">一个事务按相同的查询条件重新读取以前检索过的数据，却发现其他事务插入了满足其查询条件的新数据，这种现象就称为"幻读"。</font>
+ <font style="color:rgb(51, 51, 51);">一句话：事务A读取到了事务B提交的新增数据，不符合隔离性</font>
+ <font style="color:rgb(51, 51, 51);">幻读是事务B里面新增了数据,这是不正常的</font>

#### <font style="color:rgb(51, 51, 51);">事务隔离五种级别</font>
+ <font style="color:rgb(51, 51, 51);">read uncommitted : 读取尚未提交的数据 ：就是脏读</font>
+ <font style="color:rgb(51, 51, 51);">read committed：读取已经提交的数据 ：可以解决脏读</font>
+ <font style="color:rgb(51, 51, 51);">repeatable read：可重读读取：可以解决脏读和不可重复读 ---mysql默认的</font>
+ <font style="color:rgb(51, 51, 51);">serializable：串行化：可以解决 脏读、不可重复读和幻读---相当于锁表</font>
+ <font style="color:rgb(51, 51, 51);">Innodb的默认事务隔离级别是重复读</font><font style="color:rgb(51, 51, 51);"> </font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">repeatable read</font>`

```sql
SELECT @@tx_isolation;
set session transaction isolation level
set session transaction isolation level read uncommitted;
```
