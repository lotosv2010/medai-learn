# 04 — 模型选型与成本估算

对应文章：第 04 篇《模型图谱与选型：把成本算清楚（阶段一收官）》

## 要验证什么

纯计算，不调 API。写一个成本估算器：

**输入**：日均调用量 1000 次 / 平均输入 800 token / 平均输出 300 token（另一组成长期：10000 次 / 1200 / 400）

**输出 1**：一张表，6 个候选模型的「每次成本 / 日成本 / 月成本」

**输出 2**：缓存命中率分别为 0% / 50% / 80% 时的月成本变化

**输出 3**：加入模型路由后（70% 简单任务走小模型 + 30% 复杂任务走大模型）的成本对比，分「同厂商双档」与「跨厂商」两组

预期看到：单价差十几倍的模型，月成本差一个数量级；缓存命中 80% 能把输入成本压掉大半；路由能再省一半以上。

## 数据口径

`prices.ts` 里 6 条价格全部 `verified: true`，核对日期 **2026-11-02**，每条都有 `sourceNote` 写明来源：

- DeepSeek 两条：官方定价页，取**非高峰档**（高峰时段价格翻倍）
- Claude 两条：官方定价页美元价，按 1 USD = 7.1 CNY 折算
- 通义两条：官方页抓不到价格表，取 **OpenRouter 挂牌价**折算，`sourceNote` 已标注「以百炼控制台为准」

价格是快照。跑之前建议先点开 `priceUrl` 复一遍，改完把 `verified` 保持 true、更新 `sourceNote` 里的日期。

## 这张表和 ADR-0002 的关系

`docs/decisions/0002-ai-model-strategy.md` 定的主力模型是 Claude（2025-01-01 的决策）。**本表是「候选池」，不是「已选主力」**——它给的是按任务、合规、成本重算的依据，不替代 ADR。

两者不矛盾的地方：ADR 说「Phase 1 先硬编码 Claude，Phase 2 再实现路由」；本实验做的正是 Phase 2 之前必须有的那张账。若结论与 ADR 冲突，正确做法是提一份新的 ADR，而不是悄悄改代码。

## 怎么跑

```bash
pnpm --filter @medai/labs cost
```

不需要任何 API key。脚本会先打印「花费 ¥0」和价格核对日期。

## 看到什么算成功

- 三组表（单模型 / 缓存 / 路由）都打印完整，**日成本列有值**，没有 `undefined`
- 你能用一句话说出结论：**成本是设计出来的，不是省出来的**
- 你能指出至少一个反直觉的数字：比如 Claude Haiku 5.5 的单次成本比 DeepSeek Flash 还低
