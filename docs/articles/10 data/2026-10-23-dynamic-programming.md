### DP 为什么是面试的分水岭

先说清楚为什么值得专门花一篇讲 DP。

**第一，它考的是建模，不是记忆**。面试官出 DP 题，想看的不是你能不能默写出 `dp[i] = dp[i-1] + dp[i-2]`，而是你面对一个全新问题时，能不能**从暴力解法出发，一步步推出状态定义和转移方程**。这个能力骗不了人——没练过的候选人，会在「状态怎么定义」这一步卡住。

**第二，它的狙击面极广**。动态规划几乎覆盖所有大厂算法面试：简单如爬楼梯、不同路径，中等如最长递增子序列、零钱兑换，困难如编辑距离、正则匹配、股票系列。**你可以不会写红黑树，但你不能不会 DP**——因为 DP 出现频率太高，且一旦考到，往往是那道决定生死的题。

**第三，5-10 年经验者的优势在这里能放大**。你每天在 React、Git、构建工具里「使用」DP 的思想（虽然你没意识到），理解「最优子结构」「状态转移」这些概念时，可以对照真实工程，比应届生死记硬背要快得多。这一篇后面的「前端工程落地」会专门把 Git diff、虚拟 DOM diff 和 DP 对上号。

## 一、场景切入：编辑距离与代码分割

在讲定义之前，先看两个真实场景——你会发现 DP 根本不是「课本上的抽象算法」，它就在你的日常工具里。

### 药品名纠错：编辑距离

🔧 **真实场景**：在药品电商的搜索框里，用户输入「阿莫西琳」想找「阿莫西林」。系统怎么做纠错推荐？一个核心手段就是**计算编辑距离**：把两个字符串变成彼此所需要的最少操作次数。

「阿莫西林」和「阿莫西琳」只差最后一个字（林 vs 琳），编辑距离恰好是 **1**。把编辑距离 ≤ 1 甚至 ≤ 2 的药品名都作为「你是不是想找」的候选返回，这就是搜索纠错的最常见实现。

那什么是编辑距离？对于两个字符串 A 和 B，允许三种操作：

- **插入**一个字符
- **删除**一个字符
- **替换**一个字符

编辑距离，就是**把 A 变成 B 所需的最少操作次数**。「阿莫西林」→「阿莫西琳」，只要把最后一个「林」替换成「琳」，1 步搞定，所以距离是 1。

这个朴素的定义里藏着一个问题：**「最少操作次数」怎么求？** 你可以试试替换、插入、删除各种组合，但组合是爆炸的。这就是 DP 要解决的问题——**LeetCode 72 编辑距离**，本文第七节会完整推导。

### Git diff 就是编辑距离的变体

你每天都在用 `git diff` 看两个版本的代码差异——它本质上是**编辑距离算法的变体**。

Git 用的算法叫 **Myers diff**（由 Eugene Myers 在 1986 年提出），它把「把版本 A 的文本改成版本 B」建模成一张编辑图上的最短路径问题：每条「保留字符」「插入字符」「删除字符」的边权重不同，找到总权重最小的那条路径。这和编辑距离 DP 的目标完全一致——**都是求「从一个串变到另一个串的最小编辑代价」**。

所以面试时如果被问到「你知道 Git diff 怎么实现的吗」，能答出「本质是编辑距离 / Myers 差分算法，在编辑图上求最短路径」，就是一个非常亮的加分点。

### 代码分割：一个被忽略的 DP 问题

第二个场景更贴近前端构建优化。

🔧 **真实场景**：大型前端项目打包时，需要做**代码分割（code splitting）**——把成千上万个模块分到若干个 chunk 里。分包策略要权衡两件事：公共模块尽量抽出来复用（减少总体积），但 chunk 数量又不能太多（减少请求开销）。「怎么分包让用户总体加载时间最短」，这其实是一个**带约束的优化问题**。

而这类「**在若干选项里做出选择，使某个总代价最小/最大**」的问题，正是 DP 最擅长建模的形态——就像背包问题里「每件物品选或不选，使总价值最大」。这个呼应会一直留到第八节「前端工程落地」。

**看到这里，你应该有一个直觉了**：那些「看起来要穷举所有方案」的优化问题，往往能用一张表、一个递推公式优雅地解决。这就是动态规划。

## 二、动态规划是什么

### 一句话定义

动态规划（Dynamic Programming）是一种**算法设计方法**，核心思想是：

> **把一个复杂问题分解为若干个「相互重叠」的子问题，通过反复求解这些子问题，来求解原问题。**

拆开看两个关键词：

- **分解**：把大问题拆成规模更小的、结构相同的问题
- **相互重叠**：这是关键——拆出来的子问题之间**不是各算各的，而是有大量重复**。正因为重复，我们才可以把子问题的答案「记下来」，下次用到时直接取，避免重算

### 动态规划的两步

DP 的执行逻辑非常简洁，就两步：

**第一步：定义子问题**。想清楚「大问题」和「小问题」的关系，写出**状态转移方程**（也叫递推公式）。这是 DP 最难、也最核心的一步。

**第二步：反复执行**。按从小到大的顺序，依次把每个子问题的答案算出来（自底向上）。

### 从斐波那契看 DP 的动机

最好的入门例子还是斐波那契，因为它的重叠子问题肉眼可见。

斐波那契的定义是：

```
F(0) = 0
F(1) = 1
F(n) = F(n-1) + F(n-2)   （n ≥ 2）
```

**定义子问题**：`F(n)` 就是第 n 个斐波那契数。**反复执行**：从 2 循环到 n，每一步用 `F(i) = F(i-1) + F(i-2)` 算出来。

但注意——如果你直接用递归写：

```typescript
function fib(n: number): number {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);   // 👈 每次都重新算一遍
}
```

`fib(40)` 会直接卡死。为什么？看这张调用图就明白了：

![斐波那契数列：重复子问题的调用示意（发布前请自行转存素材库）](https://cdn.nlark.com/yuque/0/2022/png/738210/1641657086691-20c4dad2-b217-49b0-b028-eecf02d9fff6.png)

上面这张图是笔记里的斐波那契示意图。注意 `FIBONACCI[N] = FIBONACCI[N-1] + FIBONACCI[N-2]` 这个递归式——`fib(n-1)` 和 `fib(n-2)` 会**共享大量下层子问题**。算 `fib(5)` 要算 `fib(4)` 和 `fib(3)`；算 `fib(4)` 又要算 `fib(3)` 和 `fib(2)`——`fib(3)` 被算了两次，越往下重复越多，重复次数呈指数增长。

**这就是「重叠子问题」**：明明只有 n 个子问题（`fib(0)` 到 `fib(n)`），朴素递归却算了大约 2ⁿ 次。DP 的解法就是**把每个子问题的答案存下来，算一次就不再重算**——这篇后面会看到，DP 表和记忆化都能做到这一点，把 O(2ⁿ) 一举降到 O(n)。

> 💬 **面试官**：说说你对动态规划的理解？
>
> ✅ 标准答案：动态规划是把问题分解为**相互重叠**的子问题、通过反复求解子问题来解决原问题的算法设计方法。它的执行分两步：先**定义子问题**（写出状态转移方程），再**自底向上反复执行**。和朴素递归相比，DP 通过「记录并复用子问题的解」消除了重叠子问题的重复计算，把指数级复杂度降到多项式级。
>
> 🎁 加分答案：能点出 **「重叠子问题」是 DP 区别于其他方法的核心特征**——正因为子问题会重复出现，「记忆」才有价值；如果子问题彼此独立、从不重复（比如归并排序），那叫分治，缓存反而浪费空间。再深一层可以提 DP 的两个必要条件：**最优子结构**（大问题最优解由子问题最优解构成）和**无后效性**（子问题答案一旦确定就不再改变）——这是判断一道题能不能用 DP 的准绳，下一节详细展开。

## 三、DP vs 分而治之（关键辨析）

这一节是理解 DP 的**分水岭**，也是面试最容易考出区别度的地方。

很多人会把 DP 和分治（分而治之，Divide and Conquer）搞混——因为它们都是「把大问题拆成小问题」。但两者的**本质差异**只有一个词：**子问题是否重叠**。

```
分而治之（Divide and Conquer）       动态规划（Dynamic Programming）
─────────────────────────           ─────────────────────────
  大问题                              大问题
   /   \                               /   \
 子A   子B     ← 子A、子B 相互独立      子A   子B    ← 子A、子B 共享下层子问题
 / \   / \      各算各的，不共享       / \   / \
...  ...  ...                       ...  ...  ...
                                     ↑ 重叠部分只需算一次，然后复用
```

**分治的子问题相互独立**：拆出来的子问题之间没有公共部分，各算各的，算完合并就行——**不需要缓存**，因为没有重复。

**DP 的子问题相互重叠**：拆出来的子问题之间共享大量更小的子问题——**必须缓存**，否则重复计算会指数爆炸。

### 两个对照例子

**斐波那契是 DP**：`fib(5)` 拆出 `fib(4)` 和 `fib(3)`，而 `fib(4)` 又要用到 `fib(3)`——`fib(3)` 是两者共享的子问题，重叠，所以是 DP。

**翻转二叉树是分治**：翻转一棵二叉树，就是「递归翻转左子树 + 递归翻转右子树 + 交换左右孩子」。左子树的翻转和右子树的翻转**互相不干扰、不共享节点**，各算各的——子问题独立，所以是分治，场景不需要任何缓存。

笔记里这张图把两者的分野标得很清楚：

![动态规划 vs 分而治之：子问题重叠 vs 独立的对比（发布前请自行转存素材库）](https://cdn.nlark.com/yuque/0/2022/png/738210/1641658446759-0c494403-b45a-4096-a850-c949ef122ec4.png)

这张图来自笔记，画的是动态规划范式的全貌——**重叠子问题**（Overlapping Subproblems）是这个范式成立的前提，而它的两条实现路径正好对应本篇主线的中间两步：**记忆化（Memoization，自顶向下）** 和 **递推填表（Tabulation，自底向上）**。看到这两个词，你就应该想到「四步推导法」里的第 2 步和第 3 步——它们本质是同一件事的两种写法。

> 💬 **面试官**：动态规划和分而治之有什么区别？怎么判断一道题该用哪种？
>
> ✅ 标准答案：核心区别在**子问题是否重叠**。分治的子问题**相互独立**，各算各的、结果无需复用，所以不需要缓存；DP 的子问题**相互重叠**（有公共的更小子问题），必须把已算过的答案缓存起来复用，否则重复计算会指数爆炸。判断方法：画出递归树，如果不同分支会走到相同的子问题，就是 DP；如果每个子问题只被访问一次，就是分治。
>
> 🎁 加分答案：能补两点——① **分治一定有「合并」步**（子问题解组合成原问题解，如归并排序的 merge、翻转二叉树的交换），而 DP 通常是「递推」而非「合并」，因为子问题解直接通过转移方程汇总；② 分治和 DP 都基于递归，**记忆化其实就是「给分治的递归加一层缓存」**——这也解释了为什么说「所有 DP 都能从暴力递归推出来」，第 12 篇讲的记忆化，正是分治到 DP 的过渡桥梁。

## 四、适用 DP 的两个必要条件

不是所有「能拆成子问题」的题都能用 DP。**DP 有严格的适用条件**，判断错了，写出来的状态转移方程可能就是错的。两个必要条件必须同时满足：

### 条件一：最优子结构（Optimal Substructure）

**大问题的最优解，一定由子问题的最优解构成。**

换句话说：问题的「最优解」可以从它的「子问题最优解」递归地构造出来。比如爬楼梯，爬到第 n 阶的最优（最少或最多）方案数，就是由「爬到第 n-1 阶」和「爬到第 n-2 阶」的方案数相加得到——子问题的最优解直接拼出了大问题的最优解。

如果一个问题**不满足最优子结构**，那就无法用「小问题最优 → 大问题最优」来转移，DP 直接失效。

### 条件二：无后效性（No After-effect）

**一旦某个状态确定，它就不会被后续的决策改变。**

这句话是 DP 的灵魂。它的意思是：当你在推导 `dp[i]` 时，你只需要关心 `dp[i-1]`、`dp[i-2]` 这些「过去」已经确定的值，**不需要关心 `dp[i]` 是怎么一步步走到今天的**。过去的路径被「压缩」进了状态值里，不再影响未来。

举个**反例**加深理解：假设一道题的状态是「当前剩余体力」，但体力值还会受「之前走过哪些路」影响——那这个「剩余体力」就等于没记录完整的历史信息，后续无法独立决策，这就是**有后效性**，DP 不适用（这类问题往往要靠更复杂的状态设计，或者干脆换算法）。

**好的 DP 状态设计，一定做到「包含推导后续所需的所有信息，且不包含多余的历史」**。这也是为什么 DP 最难的一步是「定义状态」——状态定得对不对，就看它是否满足无后效性。

> 💬 **面试官**：拿到一道题，你怎么判断它能不能用动态规划？
>
> ✅ 标准答案：看两个条件是否同时满足。一是**最优子结构**——大问题的最优解能由子问题的最优解推出；二是**无后效性**——某个状态一旦确定，就不会被后续决策影响，未来只依赖当前状态、不依赖到达该状态的历史路径。两个条件都满足，就可以尝试定义状态和转移方程。
>
> 🎁 加分答案：能补充「怎么找状态」的实操经验——**状态就是「带着哪些信息往前走」**，定义状态时问自己三件事：① 这个变量能不能唯一描述「当前局面」；② 从当前局面出发，后面的决策需要知道哪些信息；③ 这些信息是否会因为「怎么到达当前局面」而不同（如果有，就是有后效性，状态设计有问题）。能举一个**有后效性的反例**（比如「走过的路径影响后续可选项」的问题），说明你理解的不只是背下来的一句话，而是判断标准本身。

## 五、四步推导法（核心方法论）

前面讲了 DP 是什么、什么时候能用，现在进入**本文最核心的方法论**——**四步推导法**。

这是本篇的灵魂，也是我建议你面对任何 DP 题都固定执行的流程。**不要一上来就想状态转移方程**（那是新手最容易卡住的地方），而是老老实实走这四步，让方程自然浮现出来。

```
第 1 步  暴力递归    →  先写朴素递归，确认「递推关系」到底长什么样
第 2 步  记忆化      →  加 Map 缓存，消除重叠子问题的重复计算（自顶向下）
第 3 步  DP 表       →  把记忆化翻译成循环，消除递归栈开销（自底向上）
第 4 步  空间优化    →  转移只依赖相邻项时，用滚动数组把 O(n²) 降到 O(n)
```

为什么要按这个顺序？因为**它的每一步都是「上一步的机械改良」**——你不需要凭空想出 DP 表怎么写，只要把第 1 步的递归理顺，第 2 步加缓存、第 3 步改循环、第 4 步压空间，都是水到渠成的动作。**这四步走完，一道 DP 题就彻底透了。**

### 用「爬楼梯」完整演示四步

以 **LeetCode 70 爬楼梯**为例：一次可以爬 1 阶或 2 阶，问爬到第 n 阶有多少种方法。

先想清楚「爬到第 n 阶的方法数」跟什么有关：**你要么是从第 n-1 阶爬 1 阶上来的，要么是从第 n-2 阶爬 2 阶上来的**。所以：

```
F(n) = F(n-1) + F(n-2)
```

这就是递推关系。下面按四步走一遍。

**第 1 步：暴力递归**。直接把递推关系写成递归——`climb(i) = climb(i-1) + climb(i-2)`。问题很明显：`climb(i)` 会被反复计算，指数级爆炸，和斐波那契一样。

**第 2 步：记忆化**。加一个 `Map`（或数组）缓存 `climb(i)` 的结果，算过的直接返回。复杂度从 O(2ⁿ) 降到 O(n)。

**第 3 步：DP 表（自底向上）**。既然 `i` 是严格递增地算出来的，那递归 + 缓存就可以直接改成循环：

```typescript
// 爬楼梯 —— 自底向上 DP 表
// ○ 时间复杂度：O(n)
// ○ 空间复杂度：O(n)
export function climbStairs(n: number): number {
  if (n <= 2) return n;
  const dp: number[] = [1, 1]; // dp[0]=1, dp[1]=1：n 为 0 和 1 时的方法个数
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}
```

**第 4 步：空间优化**。观察转移 `dp[i] = dp[i-1] + dp[i-2]`——**每一项只依赖前两项**，前面更早的值算完就再也用不到了。那就没必要开整个数组，用两个变量滚动即可：

```typescript
// 爬楼梯 —— 滚动变量优化
// ○ 时间复杂度：O(n)
// ○ 空间复杂度：O(1)
export function climbStairs2(n: number): number {
  if (n <= 2) return n;
  let dp0 = 1,
    dp1 = 1; // 分别代表 dp[i-2] 和 dp[i-1]
  for (let i = 2; i <= n; i++) {
    const temp = dp0;   // 滚：旧 dp0 挪到 dp1 的位置
    dp0 = dp1;
    dp1 = dp1 + temp;   // dp[i] = dp[i-1] + dp[i-2]
  }
  return dp1;
}
```

空间复杂度从 O(n) 降到了 **O(1)**——这就是「滚动数组」思想，也是第 4 步的价值。

## 六、经典 DP 模型

掌握了四步推导法，接下来要建立**题型的识别能力**。DP 题目虽然千变万化，但绝大多数都能归到四个经典模型里。**认出模型，就认出了解法**。

### 线性 DP

**特征**：状态是**一维**的，`dp[i]` 表示「处理到第 i 个位置时的最优解」，转移只依赖前一个或前几个状态。

**代表题**：最长递增子序列（LIS）、最长公共子序列（LCS）、爬楼梯、打家劫舍。

线性 DP 是最基础、最高频的一类。爬楼梯是纯线性 DP（`dp[i] = dp[i-1] + dp[i-2]`）；LIS、LCS 则升级为**二维** dp 表（两个序列各占一维），是线性 DP 的重要变体。本文第七节会重点讲 LIS 和 LCS。

### 区间 DP

**特征**：状态是**区间 `dp[i][j]`**，表示「区间 `[i, j]` 上的最优解」。转移时，**枚举区间的「分割点 k」**，把大区间拆成两个子区间求解。

**代表题**：矩阵链乘、最优括号化（给一串数字加括号，使运算结果最大/最小）。

区间 DP 的要点是**遍历顺序**：因为 `dp[i][j]` 依赖比它短的区间，所以必须**按区间长度从小到大**枚举，先算短区间、再算长区间。

### 背包 DP

**特征**：有若干「物品」，每件物品**选或不选**，在容量约束下求最大价值。这是 DP 里辨识度最高、也最容易考倒人的模型。

**两兄弟**：

- **0-1 背包**：每件物品**只能选一次**（选了就没了）
- **完全背包**：每件物品**可以选无限次**（选了还能再选）

两者的状态定义和转移方程**几乎一样**，但**遍历顺序不同**——这是面试的高频陷阱，本文第七节会专门用「零钱兑换」讲透。

### 状态机 DP

**特征**：把状态定义为「**当前处于哪种阶段**」，状态之间通过「动作」转移。最典型的是**买卖股票系列**。

**代表题**：121/122/123/188 买卖股票。

以「买卖股票含冷冻期」为例，一天有两种状态：**持有股票**和**不持有股票**。用 `hold[i]` 和 `sold[i]` 分别表示第 i 天处于这两种状态的最大收益，转移就是「今天买入/卖出/什么都不做」的选择——**状态机 DP 的本质是把「决策过程」画成一张状态转移图，然后在图上做 DP**。

### 四大模型速查

| 模型 | 状态定义 | 转移特征 | 代表题 |
|------|---------|---------|--------|
| 线性 DP | `dp[i]`（一维） | 依赖前一两项 | 爬楼梯 / LIS / LCS |
| 区间 DP | `dp[i][j]`（区间） | 枚举分割点 k | 矩阵链乘 / 回文子串 |
| 背包 DP | `dp[i][j]`（容量） | 选或不选 | 0-1 背包 / 零钱兑换 |
| 状态机 DP | `dp[i][state]` | 状态间转移 | 买卖股票系列 |

## 七、高频题精讲

这一节用四步推导法打通 5 道高频题。每道题都按「思路 → 状态定义 → 代码 → 复杂度」展开，其中**编辑距离是本文的最高潮**，会带你把 DP 表一行行填出来。

### 198 打家劫舍（线性 DP + 相邻约束）

**题意**：一条街上的房屋各有金额，相邻两间不能同时偷，求能偷到的最大金额。

**状态定义**：设 `f(k)` 表示**从前 k 间房能偷到的最大金额**，`Ak` 是第 k 间的钱数。每间房有两种选择：

- **偷第 k 间**：那第 k-1 间就不能偷，最大是 `f(k-2) + Ak`
- **不偷第 k 间**：最大金额等于 `f(k-1)`

取两者较大值，得到状态转移方程：

```
f(k) = max(f(k-2) + Ak, f(k-1))
```

**完整代码**（笔记原代码）：

```typescript
// todo 打家劫舍
// 方法一
// ○ 时间复杂度：O(n)
// ○ 空间复杂度：O(n)
export function rob(nums: number[]): number {
  console.time('打家劫舍耗时');
  if (!nums.length) return 0;
  const dp: number[] = [0, nums[0]]; // dp[0]=0（没有房子），dp[1]=第一间的钱
  for (let i = 2; i <= nums.length; i++) {
    dp[i] = Math.max(dp[i - 2] + nums[i - 1], dp[i - 1]);
  }
  console.timeEnd('打家劫舍耗时');
  return dp.pop()!;   // dp 末尾即最大金额
}

// 方法二
// ○ 时间复杂度：O(n)
// ○ 空间复杂度：O(1)
export function rob2(nums: number[]): number {
  console.time('打家劫舍耗时');
  if (!nums.length) return 0;
  let dp0 = 0,
    dp1 = nums[0]; // dp0 = f(k-2)，dp1 = f(k-1)
  for (let i = 2; i <= nums.length; i++) {
    const dp2 = Math.max(dp0 + nums[i - 1], dp1);
    dp0 = dp1;
    dp1 = dp2;
  }
  console.timeEnd('打家劫舍耗时');
  return dp1;
}
```

> 说明：笔记原代码里写的是 `const dp: any[] = ...` 和 `return dp.pop()`，为符合项目「禁止 any」与严格模式规范，这里修正为 `number[]` 和 `dp.pop()!`——逻辑完全一致。

### 300 最长递增子序列（LIS）

**题意**：求数组中最长严格递增子序列的长度（子序列不要求连续）。

**状态定义**：设 `dp[i]` 表示**以 `nums[i]` 结尾**的最长递增子序列长度。注意「以 `nums[i]` 结尾」这个限定——它保证了无后效性。

**转移**：`dp[i]` 要接在前面的某个 `nums[j]`（`j < i` 且 `nums[j] < nums[i]`）后面，取最长的那条：

```
dp[i] = max(dp[j]) + 1   （对所有 j < i 且 nums[j] < nums[i]）
```

最终答案是 `max(dp[0..n-1])`。

```typescript
// 300 最长递增子序列 —— O(n²)
export function lengthOfLIS(nums: number[]): number {
  const n = nums.length;
  if (n === 0) return 0;
  const dp = new Array<number>(n).fill(1); // 每个元素自身至少构成长度 1
  let res = 1;
  for (let i = 1; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
    res = Math.max(res, dp[i]);
  }
  return res;
}
```

**复杂度**：时间 O(n²)、空间 O(n)。

**进阶优化（面试加分）**：LIS 还有 **O(n log n)** 的解法——维护一个「tails 数组」，`tails[k]` 表示长度为 `k+1` 的递增子序列的**最小结尾值**。遍历每个数时，用**二分查找**找到它在 tails 中应替换的位置。这个优化把内层 O(n) 的线性扫描换成 O(log n) 的二分，是 LIS 的经典考点，能主动说出来就很加分。

> 💬 **面试官**：LIS 的状态为什么定义成「以 nums[i] 结尾」，而不是「前 i 个元素的最长递增子序列」？
>
> ✅ 标准答案：因为递增子序列的**排序依赖相邻元素的大小关系**。如果定义成「前 i 个元素的最长递增子序列」，无法知道这个子序列的**结尾值**是多少，也就无法判断 `nums[i]` 能不能接上去，转移方程写不出来。定义为「以 `nums[i]` 结尾」，结尾值就确定了，才能比较 `nums[j] < nums[i]`——这也再次体现了「状态要包含推导后续所需的全部信息」这个无后效性要求。

### 1143 最长公共子序列（LCS）

**题意**：求两个字符串的最长公共子序列长度（不要求连续）。

**状态定义**：`dp[i][j]` 表示 **`text1` 前 i 个字符**和 **`text2` 前 j 个字符**的最长公共子序列长度。这是一个**二维线性 DP**。

**转移**：比较 `text1[i-1]` 和 `text2[j-1]`（下标从 0 起，所以是 `i-1`、`j-1`）：

- **字符相同**：这个字符一定贡献给公共子序列，`dp[i][j] = dp[i-1][j-1] + 1`
- **字符不同**：两个字符不可能同时在公共子序列里，取「丢掉 `text1` 一个字符」或「丢掉 `text2` 一个字符」的较大值，`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`

```typescript
// 1143 最长公共子序列
export function longestCommonSubsequence(text1: string, text2: string): number {
  const m = text1.length,
    n = text2.length;
  // dp[i][j]：text1 前 i 个、text2 前 j 个字符的 LCS 长度
  const dp: number[][] = Array.from({ length: m + 1 }, () =>
    new Array<number>(n + 1).fill(0)
  );
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i - 1] === text2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;   // 👈 字符相同，接上
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]); // 丢一个字符
      }
    }
  }
  return dp[m][n];
}
```

**复杂度**：时间 O(m·n)、空间 O(m·n)。

LCS 是理解二维 DP 的钥匙——一旦你搞懂了 `dp[i][j]` 依赖 **左、上、左上**三个方向，编辑距离就水到渠成了。

### 72 编辑距离（四步推导 + DP 表可视化）

这是本文的重头戏，也是面试里 DP 的天花板题之一。题意：给定两个单词 `word1` 和 `word2`，返回把 `word1` 变成 `word2` 的最少操作数，允许**插入、删除、替换**三种操作。

**四步推导**：

**第 1 步（暴力递归思路）**：想象你站在两个字符串的末尾往前看。**定义状态 `dp[i][j]`：把 `word1` 的前 i 个字符变成 `word2` 的前 j 个字符所需的最少操作数。**

看最后一个字符 `word1[i-1]` 和 `word2[j-1]`：

- **相同**：这个字符不用动，问题缩小为 `dp[i-1][j-1]`
- **不同**：必须操作一次，三种操作各有对应：
  - **替换**：把 `word1[i-1]` 改成 `word2[j-1]`，然后两边都缩小，`dp[i-1][j-1] + 1`
  - **删除**：删掉 `word1[i-1]`（`word1` 缩小，`word2` 不动），`dp[i-1][j] + 1`
  - **插入**：在 `word1` 里插入一个等于 `word2[j-1]` 的字符（`word2` 缩小，`word1` 不动），`dp[i][j-1] + 1`

三种操作取最小，得到状态转移方程：

```
若 word1[i-1] == word2[j-1]：
    dp[i][j] = dp[i-1][j-1]
否则：
    dp[i][j] = min(
        dp[i-1][j-1],   // 替换
        dp[i-1][j],     // 删除 word1[i-1]
        dp[i][j-1]      // 插入
    ) + 1
```

**边界条件（base case）**：这是最容易写错的地方。

- `dp[i][0] = i`：`word1` 前 i 个字符变成空串，只能全删掉，需要 i 次
- `dp[0][j] = j`：空串变成 `word2` 前 j 个字符，只能全插入，需要 j 次

**第 2 步 / 第 3 步（记忆化 → DP 表）**：因为 `dp[i][j]` 只依赖**左、上、左上**三个更小的状态，所以可以自底向上、按 `i` 从小到大、`j` 从小到大填表。

**DP 表可视化**：以 `word1 = "horse"`、`word2 = "ros"` 为例（编辑距离 = 3），把表填出来：

```
        ""   r    o    s
   ""    0    1    2    3      ← dp[0][j] = j（全插入）
   h     1    1    2    3
   o     2    2    1    2
   r     3    2    2    2
   s     4    3    3    2
   e     5    4    4    3      ← dp[5][3] = 3，即答案
```

看几个关键格子理解转移：

- `dp[1][1]`（"h" → "r"）：字符不同，取 `min(dp[0][0], dp[0][1], dp[1][0]) + 1 = min(0,1,1)+1 = 1`，即替换一次
- `dp[2][1]`（"ho" → "r"）：取 `min(dp[1][0], dp[1][1], dp[2][0]) + 1 = min(1,1,2)+1 = 2`
- `dp[2][2]`（"ho" → "ro"）：末尾 `o == o`，直接 `dp[1][1] = 1`——**字符相同时不做 +1**，这一步很多人会漏

**代码实现**：

```typescript
// 72 编辑距离
export function minDistance(word1: string, word2: string): number {
  const m = word1.length,
    n = word2.length;
  // dp[i][j]：word1 前 i 个字符 变成 word2 前 j 个字符 的最少操作数
  const dp: number[][] = Array.from({ length: m + 1 }, () =>
    new Array<number>(n + 1).fill(0)
  );
  // base case
  for (let i = 0; i <= m; i++) dp[i][0] = i; // 全删除
  for (let j = 0; j <= n; j++) dp[0][j] = j; // 全插入

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1];        // 相同，不操作
      } else {
        dp[i][j] =
          Math.min(
            dp[i - 1][j - 1],  // 替换
            dp[i - 1][j],      // 删除
            dp[i][j - 1]       // 插入
          ) + 1;
      }
    }
  }
  return dp[m][n];
}
```

**第 4 步（空间优化）**：`dp[i][j]` 只依赖上一行和当前行，所以可以用**两个一维数组**（或一个数组 + 一个临时变量保存左上角）把空间从 O(m·n) 降到 O(n)。这就是「滚动数组」在二维 DP 上的应用。

**复杂度**：O(m·n) 时间；空间 O(m·n)，优化后 O(n)。

> 💬 **面试官**：编辑距离的状态转移方程是什么？增、删、改三种操作分别对应哪一项？
>
> ✅ 标准答案：定义 `dp[i][j]` 为把 `word1` 前 i 个字符变成 `word2` 前 j 个字符的最少操作数。若两字符相同，`dp[i][j] = dp[i-1][j-1]`；否则 `dp[i][j] = min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1]) + 1`。三项分别是：**替换**（`dp[i-1][j-1]`，两边各缩小一个）、**删除**（`dp[i-1][j]`，`word1` 少一个字符）、**插入**（`dp[i][j-1]`，`word2` 少一个字符）。边界 `dp[i][0]=i`、`dp[0][j]=j`。
>
> 🎁 加分答案：能补两点——① **「删除」和「插入」的对称性**：`word1` 删一个字符，等价于 `word2` 里多了一个字符，所以 `dp[i-1][j]`（删）和 `dp[i][j-1]`（插）本质是一对镜像操作，理解这一点方程就不用死记；② 能主动提到**空间优化**：用滚动数组把二维降到一维，注意用变量暂存「左上角」`dp[i-1][j-1]`，因为它在被覆盖前还有用——这是二维 DP 空间优化的通用技巧。**再深一步**可以联系工程：`git diff` 的 Myers 算法本质就是在编辑图上找最短路径，与编辑距离同源。

### 322 零钱兑换 / 518 零钱兑换 II（完全背包与遍历顺序）

**题意**：给一组硬币面额和总金额，求：
- **322 零钱兑换**：凑出总金额所需的**最少硬币数**（求最值）
- **518 零钱兑换 II**：凑出总金额的**组合数**（求方案数）

这两个是**完全背包**的经典代表——每种硬币可以**用无限次**。

**状态定义**：`dp[j]` 表示凑出金额 j 的最少硬币数（322）或组合数（518）。转移是把硬币**一个个「放进去」**：

```
322：dp[j] = min(dp[j], dp[j - coin] + 1)
518：dp[j] = dp[j] + dp[j - coin]
```

**关键的遍历顺序差异**——这是面试最爱考的坑：

```typescript
// 322 零钱兑换 —— 完全背包求「最少硬币数」
export function coinChange(coins: number[], amount: number): number {
  const dp = new Array<number>(amount + 1).fill(Infinity);
  dp[0] = 0; // 凑金额 0 需要 0 枚
  for (const coin of coins) {          // 外层遍历硬币
    for (let j = coin; j <= amount; j++) {   // 👈 金额正序遍历！
      dp[j] = Math.min(dp[j], dp[j - coin] + 1);
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}

// 518 零钱兑换 II —— 完全背包求「组合数」
export function change(amount: number, coins: number[]): number {
  const dp = new Array<number>(amount + 1).fill(0);
  dp[0] = 1; // 凑金额 0 有 1 种方案（什么都不选）
  for (const coin of coins) {          // 外层遍历硬币（保证组合不重复）
    for (let j = coin; j <= amount; j++) {   // 👈 仍是正序！
      dp[j] += dp[j - coin];
    }
  }
  return dp[amount];
}
```

**为什么是正序？** 因为完全背包允许**同一枚硬币用多次**。内层金额 `j` **正序**遍历时，`dp[j - coin]` 已经是**本轮更新过**的值——意味着「这枚硬币可以被再次使用」，这正是「完全」的含义。

**对比 0-1 背包**：如果每种硬币只能用一次，内层必须**倒序** `for (let j = amount; j >= coin; j--)`——倒序时 `dp[j-coin]` 还是「上一轮、没用过当前硬币」的值，保证每枚硬币只用一次。

```
完全背包（可用无限次）：金额 j  →  正序遍历   →  dp[j-coin] 是「本轮」值 → 可重复用
0-1 背包（只能用一次）：金额 j  →  倒序遍历   →  dp[j-coin] 是「上轮」值 → 不重复用
```

**一行之差，语义天壤之别**——这就是背包问题最经典的面试陷阱。

**复杂度**：时间 O(amount × coins.length)、空间 O(amount)。

> 💬 **面试官**：0-1 背包和完全背包的区别是什么？为什么遍历顺序不同？
>
> ✅ 标准答案：区别在**每件物品能选几次**——0-1 背包每件**最多选一次**，完全背包每件**可选无限次**。状态定义和转移方程几乎一样，差异全在**内层循环金额的遍历方向**：完全背包内层金额**正序**遍历，此时 `dp[j-coin]` 已被当前物品更新过，相当于允许「同一物品再用一次」；0-1 背包内层金额**倒序**遍历，`dp[j-coin]` 还是未选当前物品的旧值，保证每件物品只用一次。
>
> 🎁 加分答案：能延伸到**「求最值」和「求方案数」的区别**——322（求最少硬币数）用 `min`，讲的是「最优解」；518（求组合数）用累加，讲的是「方案计数」。求方案数时**外层必须遍历物品、内层遍历容量**，否则会**重复计数**（把「先选 1 再选 2」和「先选 2 再选 1」当成两种不同方案）。能画出「完全背包 vs 0-1 背包」的遍历顺序对照表，说明你不是背结论，而是真的理解了「`dp[j-coin]` 取的是本轮值还是上轮值」这个本质。

## 八、前端工程落地

学 DP 最怕「刷完就忘」。这一节把 DP 思想和你每天用的前端工具对上号——你会发现 DP 离你根本不远。

### Myers diff：Git diff 就是编辑距离

前面第一节提过，这里说透。`git diff` 展示两个版本的差异，底层用的 **Myers 差分算法**把「旧文本 → 新文本」建模成**编辑图（edit graph）上求最短路径**：

- 编辑图的横轴是「新版本的字符」，纵轴是「旧版本的字符」
- 向右走 = 插入一个字符，向下走 = 删除一个字符，对角线走 = 匹配（保留）
- 找一条从左上到右下、**编辑步数最少**的路径，就是最优 diff

**这和编辑距离 DP 是同一个问题的两种表述**——都在求「把一个串变成另一个串的最小编辑代价」。区别只是 Myers 针对「文本 diff」做了内存和性能上的工程优化（比如利用对角线、二进制搜索降低空间）。理解了编辑距离，你就理解了 Git diff 的内核。

### 虚拟 DOM diff：DP 思想的工程近似

回忆第 1 篇讲过的 snabbdom / Vue 的**双端 diff**（`updateChildren`）：对比新旧两个子节点列表时，用「头头、尾尾、头尾、尾头」四个指针向中间收拢，找出可复用的节点。

严格来说，**「新旧列表的最优复用方案」本身是一个编辑距离问题**（把旧列表通过最少的增删移动变成新列表）。但真实前端场景里，节点移动是**高频**操作，O(n·m) 的编辑距离 DP 在大列表上太慢。于是框架做了一个**工程妥协**——用双端 diff 的**贪心策略**找「足够好」的 patch 序列，把复杂度压到接近 O(n)。

**这正是 DP 思想在前端最真实的落地**：不是照搬 DP 算法，而是「理解 DP 在解什么问题（最小编辑代价），然后根据场景约束选一个更快的近似」。这个取舍逻辑，和你第 1 篇学到的「虚拟 DOM diff 为什么只做同层对比」一脉相承。

### 代码分割：背包问题的现实版

回到开篇的代码分割。把模块分到不同 chunk，追求「总加载时间最短」——这本质上是一个**带容量约束的选择问题**，和 0-1 背包「每件物品选或不选，在容量约束下最大化价值」是同一套建模思路。

现实中的 webpack/Vite 不会真的跑一个精确的背包 DP（模块太多、代价函数太复杂），而是用启发式策略。但**「选择 + 代价最小化」的建模视角是相通的**——当你能把工程问题抽象成「状态 + 转移」，你就有能力判断「这里需不需要精确最优解，还是贪心近似就够」。

> 💬 **面试官**：前端有哪些地方用到动态规划的思想？
>
> ✅ 标准答案：最典型的是 **Git diff 背后的 Myers 算法**——它本质是在编辑图上求最短编辑路径，和编辑距离 DP 同源；此外**虚拟 DOM 的双端 diff** 是编辑距离问题的一个工程近似（因为精确 DP 太慢，改用贪心双端对比接近 O(n)）；再如**代码分割 / 分包策略**可以建模成背包问题式的选择优化。
>
> 🎁 加分答案：能讲出「**为什么前端用的是 DP 的近似而非精确 DP**」——因为前端对性能极其敏感（主线程 16.6ms 帧预算），精确 DP 的 O(n·m) 在大规模列表 / 模块图上不可接受，所以框架选择「识别问题本质 + 用启发式换取速度」。这个「理解问题本质、再按场景约束做工程妥协」的思维，比背下算法本身更有价值——它也正是 5-10 年经验开发者区别于「只会调 API」的地方。

## 九、面试高频问（完整答案）

把本篇四个核心问题集中收口，方便你复习速查。

**问 1：动态规划适用的两个必要条件是什么？**

✅ **最优子结构**——大问题的最优解能由子问题的最优解构造出来；**无后效性**——某个状态一旦确定，就不会被后续决策改变，未来只依赖当前状态、不依赖到达它的历史路径。两者同时满足才敢用 DP。判断时画出递归树：子问题重叠则是 DP，独立则是分治。

**问 2：如何从暴力递归推导出 DP 解法？四步是什么？**

✅ ① **暴力递归**，写朴素递归确认递推关系；② **记忆化**，加缓存消除重叠子问题的重复计算（自顶向下）；③ **DP 表**，把记忆化翻译成自底向上的循环，消除递归栈开销；④ **空间优化**，当转移只依赖相邻行/列时用滚动数组，把 O(n²) 压到 O(n) 甚至 O(1)。实战时先写 DP 表版验证逻辑正确，再做空间优化。

**问 3：0-1 背包和完全背包的区别是什么？为什么遍历顺序不同？**

✅ 区别在**每件物品能选几次**：0-1 背包每件最多一次，完全背包可选无限次。差异体现在内层**金额遍历方向**：完全背包**正序**（`dp[j-coin]` 是本轮已更新的值，允许重用当前物品），0-1 背包**倒序**（`dp[j-coin]` 是未选当前物品的旧值，保证只用一次）。

**问 4：编辑距离的状态转移方程是什么？增/删/改对应什么转移？**

✅ `dp[i][j]` 表示把 `word1` 前 i 个字符变成 `word2` 前 j 个字符的最少操作数。字符相同时 `dp[i][j] = dp[i-1][j-1]`；不同时 `dp[i][j] = min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1]) + 1`——分别是**替换**（两边各缩一个）、**删除**（`word1` 少一个）、**插入**（`word2` 少一个）。边界 `dp[i][0] = i`、`dp[0][j] = j`。
