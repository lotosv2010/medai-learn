# Vue 2 插槽原理：普通 / 具名 / 作用域插槽编译产物全对比（面试收藏级）

> 面试官推过来一道题：「父组件里写的插槽内容，能拿到子组件的数据吗？」你下意识回答「不能」，但马上又想起作用域插槽好像可以……那普通插槽为什么不行？两者的本质区别到底是什么？今天从编译产物层面把这个问题彻底答清楚。

---

在看细节之前，先把整条主线摆出来。**全文章节顺序就是这条插槽链路的展开**：

```text
【插槽完整链路】

① 父组件编译阶段
   普通/具名插槽 → genSlot    → _t(name) 占位
                               插槽内容的 VNode 在父作用域生成，存入 vm.$slots
   作用域插槽    → genScopedSlot → 生成插槽函数（function(slotData){ return VNode }）
                                   函数存入 scopedSlots 对象，VNode 尚未生成
                                        ↓
② 子组件渲染阶段
   普通/具名插槽 → renderSlot → 取 vm.$slots[name]      → 直接返回已生成的 VNode 数组
   作用域插槽    → renderSlot → 调用 $scopedSlots[name](slotData) → 此时才生成 VNode，可访问子数据
                                        ↓
③ Vue 2.6 统一（normalizeScopedSlots）
   $slots 中的普通插槽包装为函数，统一进 $scopedSlots
   → 可以用 $scopedSlots 统一访问所有插槽，不再需要区分两套 API
```

记住一句话：**普通插槽是 VNode，作用域插槽是函数——渲染时机的差异就藏在这里**。

## 🔌 一、基本使用：四种插槽语法一次摸清

> 链路位置：父组件模板书写阶段（编译前）

### 默认插槽与具名插槽

子组件用 `<slot>` 占位，父组件传入内容。具名插槽通过 `name` 属性区分多个占位：

```html
<!-- 子组件 DrugCard.vue -->
<template>
  <div class="drug-card">
    <slot name="header"></slot>   <!-- 具名插槽 -->
    <slot></slot>                 <!-- 默认插槽 -->
    <slot name="footer"></slot>   <!-- 具名插槽 -->
  </div>
</template>
```

父组件填充内容，新旧语法对比：

```html
<!-- 父组件（Vue 2.6+ 新语法，推荐） -->
<DrugCard>
  <template v-slot:header>
    <h3>布洛芬缓释胶囊</h3>
  </template>

  <p>用于缓解轻至中度疼痛</p>   <!-- 填入默认插槽 -->

  <template v-slot:footer>
    <span>OTC · 非处方药</span>
  </template>
</DrugCard>

<!-- 父组件（旧语法，已废弃，了解即可） -->
<DrugCard>
  <h3 slot="header">布洛芬缓释胶囊</h3>
  <p>用于缓解轻至中度疼痛</p>
  <span slot="footer">OTC · 非处方药</span>
</DrugCard>
```

新旧语法功能等价，但 `v-slot` 只能用在 `<template>` 或组件标签上，旧的 `slot` 属性可以直接写在任意元素上。**Vue 2.6 起推荐全面切换 `v-slot`**，旧语法在 Vue 3 中已移除。

### 作用域插槽：父组件拿子数据的标准姿势

子组件通过 `<slot>` 的属性向父组件暴露数据：

```html
<!-- 子组件 DrugList.vue -->
<template>
  <ul>
    <li v-for="drug in drugs" :key="drug.id">
      <!-- 把每条药品数据通过插槽暴露给父组件 -->
      <slot :drug="drug" :index="index"></slot>
    </li>
  </ul>
</template>

<script>
export default {
  data() {
    return {
      drugs: [
        { id: 1, name: '布洛芬缓释胶囊', stock: 120 },
        { id: 2, name: '阿莫西林胶囊', stock: 0 },
      ]
    }
  }
}
</script>
```

父组件通过 `v-slot` 接收数据，自定义每行渲染：

```html
<!-- 父组件 -->
<DrugList>
  <template v-slot:default="{ drug, index }">
    <span>{{ index + 1 }}. {{ drug.name }}</span>
    <span v-if="drug.stock === 0" style="color:red">缺货</span>
    <span v-else>库存：{{ drug.stock }}</span>
  </template>
</DrugList>
```

子组件提供数据逻辑，父组件决定 UI 样式——这正是作用域插槽最典型的使用模式。

### 插槽默认内容

`<slot>` 标签内部可以写默认内容，父组件未传入时显示：

```html
<slot name="empty-state">
  <p class="placeholder">暂无药品数据</p>
</slot>
```

### `$slots` vs `$scopedSlots` 速览

| 属性 | 存储内容 | 访问方式 | Vue 2.6 后变化 |
|------|---------|---------|---------------|
| `$slots` | 普通/具名插槽的 VNode 数组 | `this.$slots.default` | 仍可用，内容同步进 `$scopedSlots` |
| `$scopedSlots` | 所有插槽的**函数**（含普通插槽） | `this.$scopedSlots.default()` | 统一入口，推荐使用 |

> 💬 **面试官**：`$slots` 和 `$scopedSlots` 有什么区别？
>
> ✅ 标准答案：`$slots` 存的是已渲染好的 VNode 数组，只包含普通插槽；`$scopedSlots` 存的是插槽函数，调用时才生成 VNode，包含所有插槽。Vue 2.6 后普通插槽也被包装成函数统一进 `$scopedSlots`，可以用它访问全部插槽。
>
> 🎁 加分答案：能说出 `normalizeScopedSlots` 函数完成了这个统一，以及统一的意义：子组件可以不再区分两套 API，统一用 `$scopedSlots[name]()` 调用即可。

## 🌳 二、普通插槽原理：渲染时机在父组件

> 链路位置：① 父组件编译阶段 → 普通/具名插槽路径

### 父组件编译产物：插槽内容已是 VNode

写下这段父组件模板：

```html
<DrugCard>
  <p>布洛芬缓释胶囊说明</p>
</DrugCard>
```

经过 `generate` 阶段，父组件的 render 函数字符串大致是：

```javascript
// 父组件 render 函数（编译产物）
_c('DrugCard', [
  _c('p', [_v("布洛芬缓释胶囊说明")])  // 👈 插槽内容在父作用域已生成 VNode
])
```

这段 VNode 会通过 `componentOptions.children` 传给子组件，最终挂在 `vm.$slots.default` 上。**VNode 在父组件 render 时就已经创建完毕，`this` 指向父组件实例。**

### genSlot：子组件里的 `<slot>` 编译成什么

子组件模板里的 `<slot>` 标签，在 generate 阶段由 `genSlot` 处理，编译成 `_t()` 调用：

```javascript
// 子组件模板：<slot name="header"></slot>
// 编译产物：
_t("header")

// 带默认内容的编译产物：
// <slot name="header"><span>默认标题</span></slot>
_t("header", [_c('span', [_v("默认标题")])])
```

`_t` 是运行时辅助函数 `renderSlot` 的别名，在子组件执行 render 时被调用。

### renderSlot：取出父组件传入的 VNode

`_t("header")` 在子组件 render 时执行，本质是调用 `renderSlot`：

```javascript
// src/core/instance/render-helpers/render-slot.js（简化）
export function renderSlot(name, fallback) {
  const scopedSlotFn = this.$scopedSlots[name]

  if (scopedSlotFn) {
    // 作用域插槽路径（第三章展开）
    return scopedSlotFn({}) || fallback
  }

  // 普通插槽：直接取已生成的 VNode 数组
  return this.$slots[name] || fallback  // 👈 VNode 是父组件生成的，直接返回
}
```

**普通插槽完整流程**：父组件 render → 生成插槽 VNode（`this` = 父实例）→ 存入子组件 `$slots` → 子组件 render 时 `_t()` 直接取出返回。因为 VNode 创建时 `this` 是父实例，所以只能访问父组件数据。

🔧 **真实案例**：在医疗系统里，`<PatientLayout>` 组件用默认插槽接收各页面的主体内容。插槽里写的 `{{ currentUser.name }}` 取的是父组件（页面）的数据，而不是 `PatientLayout` 内部的状态——这正是普通插槽"只能访问父作用域"的体现。

> 💬 **面试官**：普通插槽为什么不能拿到子组件的数据？
>
> ✅ 标准答案：普通插槽的内容是在**父组件编译和渲染阶段**就生成了 VNode，`this` 指向父组件实例。子组件拿到的是已经渲染完的 VNode，而不是一个函数，所以无法在子组件作用域里再次执行来访问子数据。
>
> 🎁 加分答案：对比作用域插槽——作用域插槽传给子组件的是一个**函数**，子组件 render 时才调用这个函数，此时可以把子组件自己的数据作为参数传入。本质差异就是**渲染时机不同**。

## 🎁 三、作用域插槽原理：渲染时机在子组件

> 链路位置：① 父组件编译阶段 → 作用域插槽路径 → ② 子组件渲染阶段

### 父组件编译产物：是函数，不是 VNode

写下这段作用域插槽：

```html
<!-- 父组件 -->
<DrugList>
  <template v-slot:default="{ drug }">
    <span>{{ drug.name }}</span>
  </template>
</DrugList>
```

编译后，父组件 render 函数里不是 VNode，而是**一个函数**：

```javascript
// 父组件 render 函数（编译产物）
_c('DrugList', {
  scopedSlots: _u([
    {
      key: "default",
      fn: function({ drug }) {         // 👈 插槽函数，不是 VNode！
        return [_c('span', [_v(_s(drug.name))])]
      }
    }
  ])
})
```

`_u` 是 `resolveScopedSlots` 的别名，把数组格式转成 `{ key: fn }` 对象，最终挂到子组件的 `$scopedSlots` 上。**父组件编译阶段只生成了函数，VNode 还没有创建。**

### genScopedSlot：作用域插槽编译的核心

在 Vue 2 编译器的 `generate` 阶段，`genScopedSlot` 负责将作用域插槽的 AST 节点转成函数字符串：

```javascript
// src/compiler/codegen/index.js（核心逻辑）
function genScopedSlot(el, state) {
  const slotScope = el.slotScope  // "{ drug }" —— 父组件声明的接收参数
  return `{` +
    `key: ${el.slotTarget || '"default"'},` +
    `fn: function(${slotScope || ''}) {` +  // 👈 生成函数，参数是 slotScope
    `return ${genChildren(el, state) || 'undefined'}` +
    `}}`
}
```

关键在 `fn: function(${slotScope}){}` —— 这个函数在**子组件 render 时才被调用**，调用时子组件可以把自己的数据作为参数传入。

### 子组件 renderSlot：调用函数并传入数据

子组件 `<slot :drug="drug">` 编译成带参数的 `_t()`：

```javascript
// 子组件编译产物
// <slot :drug="drug" :index="index"></slot>
_t("default", null, { drug: drug, index: index })
//                    👆 子组件把自己的数据传进去
```

`renderSlot` 执行时取到插槽函数并调用：

```javascript
// src/core/instance/render-helpers/render-slot.js
export function renderSlot(name, fallback, props) {
  const scopedSlotFn = this.$scopedSlots[name]

  if (scopedSlotFn) {
    // 作用域插槽：把子组件数据 props 传给父组件的插槽函数
    return scopedSlotFn(props) || fallback  // 👈 此刻才执行父组件模板里的插槽内容
  }

  return this.$slots[name] || fallback
}
```

**作用域插槽完整流程**：父组件编译 → 生成插槽函数（VNode 未创建）→ 子组件 render → 调用插槽函数并传入子数据 → 函数执行生成 VNode。VNode 创建时虽然 `this` 是父组件实例（所以能访问父数据），但函数参数里携带了子组件数据，两者都能访问。

🔧 **真实案例**：医疗系统里的 `<DrugTable>` 组件封装了分页、排序、加载状态，但每行的渲染逻辑由业务方通过作用域插槽决定。`<DrugTable>` 暴露 `{ row, rowIndex, isLoading }`，业务方可以自由决定显示哪些字段、如何高亮缺货行——这就是"逻辑在子组件，UI 在父组件"的 renderless 组件雏形。

> 💬 **面试官**：作用域插槽为什么能拿到子组件的数据？父子作用域是怎么隔离的？
>
> ✅ 标准答案：作用域插槽编译后是一个函数，而不是 VNode。子组件 render 时调用这个函数，并把自己的数据作为参数传入，父组件模板里通过 `v-slot="{ drug }"` 解构接收，所以能访问子数据。父子作用域隔离的本质是：函数的参数（子数据）和函数执行时的 `this`（父实例）是两个来源，互不干扰。
>
> 🎁 加分答案：普通插槽是「父给子 VNode」，作用域插槽是「父给子函数，子调用时注入数据」。本质差异是**渲染时机**，前者在父组件 render 时完成，后者推迟到子组件 render 时完成。

## 🔗 四、Vue 2.6 统一：normalizeScopedSlots

> 链路位置：③ Vue 2.6 统一阶段

### 问题背景：两套 API 的心智负担

Vue 2.6 之前，普通插槽和作用域插槽是完全分开的两套 API：

- 普通插槽：父组件模板用 `slot="name"`，子组件用 `this.$slots.name` 访问
- 作用域插槽：父组件模板用 `slot-scope`，子组件用 `this.$scopedSlots.name` 访问

子组件内部需要判断：「这个插槽是普通插槽还是作用域插槽？」，用不同的路径取值，写起来繁琐。

### normalizeScopedSlots：统一的实现

Vue 2.6 在子组件初始化时调用 `normalizeScopedSlots`，把 `$slots` 中的普通插槽包装成函数，统一进 `$scopedSlots`：

```javascript
// src/core/vdom/helpers/normalize-scoped-slots.js（核心逻辑）
export function normalizeScopedSlots(slots, normalSlots) {
  let res = {}

  // 1. 先处理作用域插槽（已经是函数，直接放入）
  for (const key in slots) {
    res[key] = slots[key]
  }

  // 2. 再处理普通插槽（VNode 数组，包装成函数）
  for (const key in normalSlots) {
    if (!(key in res)) {
      res[key] = normalizeScopedSlot(normalSlots[key])  // 👈 包装为函数
    }
  }

  return res
}

function normalizeScopedSlot(fn) {
  // 把 VNode 数组包装为函数，调用时直接返回
  return function() {
    return fn
  }
}
```

统一后，子组件可以用 `$scopedSlots` 访问所有插槽，不再需要区分两套 API：

```javascript
// Vue 2.6 之前：需要判断类型
const header = this.$scopedSlots.header
  ? this.$scopedSlots.header({})
  : this.$slots.header

// Vue 2.6 之后：统一用 $scopedSlots
const header = this.$scopedSlots.header?.()
```

### 动态插槽名：`v-slot:[dynamicName]`

Vue 2.6 还引入了动态插槽名，编译为变量取值：

```html
<!-- 父组件模板 -->
<DrugCard>
  <template v-slot:[slotName]>
    <span>动态插槽内容</span>
  </template>
</DrugCard>
```

```javascript
// 编译产物：slotName 是运行时变量
_c('DrugCard', {
  scopedSlots: _u([
    {
      key: slotName,        // 👈 变量，而不是字符串字面量
      fn: function() { return [_c('span', [_v("动态插槽内容")])] }
    }
  ])
})
```

> 💬 **面试官**：Vue 2.6 对插槽做了什么统一？normalizeScopedSlots 的作用是什么？
>
> ✅ 标准答案：Vue 2.6 通过 `normalizeScopedSlots` 函数，把 `$slots` 中的普通插槽（VNode 数组）包装成函数，统一进 `$scopedSlots`。这样子组件内部可以用 `$scopedSlots` 统一访问所有插槽，不再区分两套 API。
>
> 🎁 加分答案：统一之后，`$slots` 和 `$scopedSlots` 的内容是同步的——访问 `$slots.default` 返回 VNode 数组，访问 `$scopedSlots.default()` 返回同样的 VNode 数组。Vue 2.6 同时新增了 `v-slot` 统一语法，废弃了旧的 `slot` / `slot-scope` 属性写法。

## 📖 五、源码解析（重点代码，来源 GitHub 仓库）

> 链路位置：① 编译阶段 + ② 运行时阶段完整串联

### ① genSlot：普通插槽编译

`src/compiler/codegen/index.js`

```javascript
// 子组件 <slot name="header"> 的编译
function genSlot(el, state) {
  const slotName = el.slotName || '"default"'
  const children = genChildren(el, state)  // 默认内容

  let res = `_t(${slotName}`

  if (children) {
    res += `,${children}`  // 有默认内容时作为第二个参数传入
  }

  // 绑定了属性说明是作用域插槽的子组件侧（<slot :drug="drug">）
  const attrs = el.attrs || el.dynamicAttrs
    ? genProps((el.attrs || []).concat(el.dynamicAttrs || []))
    : null
  const bind = el.attrsMap['v-bind']

  if ((attrs || bind) && !children) {
    res += `,null`
  }
  if (attrs) {
    res += `,${attrs}`   // 👈 子组件传给父组件的数据（作用域插槽的数据来源）
  }

  return res + ')'
}
```

**关键**：`attrs` 就是子组件 `<slot :drug="drug">` 里绑定的数据，作为第三个参数传给 `_t()`，最终被 `renderSlot` 转发给父组件的插槽函数。

### ② genScopedSlot：作用域插槽编译

`src/compiler/codegen/index.js`

```javascript
// 父组件 <template v-slot:default="{ drug }"> 的编译
function genScopedSlot(el, state) {
  const isLegacySyntax = el.attrsMap['slot-scope']  // 旧语法兼容
  const slotScope = el.slotScope  // 接收参数：如 "{ drug }"

  return `{key:${el.slotTarget || '"default"'},` +
    `fn:function(${String(slotScope)}){` +      // 👈 生成插槽函数
    `return ${el.tag === 'template'
      ? el.if && isLegacySyntax
        ? `(${el.if})?${genChildren(el, state) || 'undefined'}:undefined`
        : genChildren(el, state) || 'undefined'
      : genElement(el, state)
    }},proxy:${String(!!isLegacySyntax)}}`
}
```

### ③ renderSlot：运行时取插槽

`src/core/instance/render-helpers/render-slot.js`

```javascript
export function renderSlot(name, fallback, props, bindObject) {
  const scopedSlotFn = this.$scopedSlots[name]
  let nodes

  if (scopedSlotFn) {
    props = props || {}
    if (bindObject) {
      props = extend(extend({}, bindObject), props)
    }
    // 调用插槽函数，传入子组件数据
    nodes = scopedSlotFn(props) || fallback
  } else {
    // 普通插槽：直接取 VNode 数组
    nodes = this.$slots[name] || fallback
  }

  const target = props && props.slot
  if (target) {
    return this.$createElement('template', { slot: target }, nodes)
  } else {
    return nodes
  }
}
```

### ④ normalizeScopedSlots：Vue 2.6 统一入口

`src/core/vdom/helpers/normalize-scoped-slots.js`

```javascript
export function normalizeScopedSlots(slots, normalSlots, prevSlots) {
  let res

  const hasNormalSlots = normalSlots !== emptyObject
  const isStable = slots ? !!slots.$stable : !hasNormalSlots
  const key = slots && slots.$key

  if (!slots) {
    res = {}
  } else if (slots._normalized) {
    // 有缓存，直接返回（性能优化）
    if (slots._normalized === res) {
      return slots._normalized
    }
    res = slots._normalized
  } else {
    res = {}
    for (const key in slots) {
      if (slots[key] && key[0] !== '$') {
        res[key] = normalizeScopedSlot(normalSlots, key, slots[key])
      }
    }
  }

  // 把普通插槽也包装为函数，统一进 res
  for (const key in normalSlots) {
    if (!(key in res)) {
      res[key] = proxyNormalSlot(normalSlots, key)  // 👈 包装为函数
    }
  }

  // 打上缓存标记
  def(res, '$stable', isStable)
  def(res, '$key', key)
  def(res, '$hasNormal', hasNormalSlots)
  return res
}

// 把普通插槽的 VNode 数组包装为函数
function proxyNormalSlot(slots, key) {
  return () => slots[key]  // 调用时返回 VNode 数组
}
```

### ⑤ keep-alive 取插槽 VNode

`src/core/components/keep-alive.js`

`keep-alive` 没有自己的模板，它通过 `$slots.default` 取到第一个子组件的 VNode，再决定是否使用缓存：

```javascript
// src/core/components/keep-alive.js
export default {
  name: 'keep-alive',
  abstract: true,  // 抽象组件，不渲染真实 DOM

  render() {
    // 取默认插槽的所有 VNode
    const slot = this.$slots.default
    const vnode = getFirstComponentChild(slot)  // 👈 只取第一个组件类型的 VNode

    const componentOptions = vnode && vnode.componentOptions
    if (componentOptions) {
      // 取组件名，与 include/exclude 做匹配
      const name = getComponentName(componentOptions)
      const { include, exclude } = this
      if (
        (include && (!name || !matches(include, name))) ||
        (exclude && name && matches(exclude, name))
      ) {
        return vnode  // 不缓存，直接返回
      }

      // LRU 缓存逻辑
      const { cache, keys } = this
      const key = vnode.key == null
        ? componentOptions.Ctor.cid + (componentOptions.tag ? `::${componentOptions.tag}` : '')
        : vnode.key

      if (cache[key]) {
        vnode.componentInstance = cache[key].componentInstance  // 复用缓存实例
        remove(keys, key)
        keys.push(key)  // 刷新 LRU 顺序
      } else {
        cache[key] = vnode
        keys.push(key)
        if (this.max && keys.length > parseInt(this.max)) {
          pruneCacheEntry(cache, keys[0], keys, this._vnode)  // 淘汰最久未用
        }
      }
      vnode.data.keepAlive = true
    }
    return vnode || (slot && slot[0])
  }
}
```

**关键**：`keep-alive` 用 `this.$slots.default` 而不是 `$scopedSlots`，因为它需要的是子组件的 VNode 对象本身（要读取 `componentOptions.Ctor.cid` 等属性），而不是调用插槽函数。

> 💬 **面试官**：keep-alive 是如何通过插槽获取第一个子组件 VNode 的？
>
> ✅ 标准答案：`keep-alive` 是抽象组件，在 render 函数里直接访问 `this.$slots.default` 取到默认插槽的 VNode 数组，再调用 `getFirstComponentChild` 找到第一个组件类型的 VNode。然后根据 `include/exclude` 决定是否缓存，并用 LRU 策略管理缓存上限。
>
> 🎁 加分答案：它用 `$slots.default` 而不是 `$scopedSlots.default()`，因为需要拿到 VNode 对象本身（读取 `componentOptions`），而不是重新生成一个新的 VNode。

### 全面切换 v-slot 语法

Vue 2.6 起，`slot` 和 `slot-scope` 属性已被标记为废弃，Vue 3 中已移除。新项目和维护中的 Vue 2 项目应全面切换 `v-slot`：

```html
<!-- ❌ 旧语法，不要再写 -->
<DrugCard>
  <template slot="header" slot-scope="{ drug }">
    {{ drug.name }}
  </template>
</DrugCard>

<!-- ✅ 新语法 -->
<DrugCard>
  <template v-slot:header="{ drug }">
    {{ drug.name }}
  </template>
</DrugCard>

<!-- ✅ 默认插槽可以简写（只有默认插槽时） -->
<DrugCard v-slot="{ drug }">
  {{ drug.name }}
</DrugCard>
```

### renderless 组件：逻辑与 UI 彻底分离

作用域插槽最强大的应用场景是 **renderless 组件（无渲染组件）**：子组件只负责数据逻辑，不渲染任何 DOM，UI 完全交给父组件通过作用域插槽控制。

医疗场景：`<DrugDataProvider>` 封装药品列表的加载、分页、搜索逻辑，UI 由业务方完全定制：

```html
<!-- DrugDataProvider.vue：只有逻辑，无 DOM -->
<template>
  <div>
    <slot
      :drugs="drugs"
      :loading="loading"
      :error="error"
      :page="page"
      :totalPages="totalPages"
      :search="search"
      :nextPage="nextPage"
      :prevPage="prevPage"
    ></slot>
  </div>
</template>

<script>
export default {
  name: 'DrugDataProvider',
  props: {
    category: String,
    pageSize: { type: Number, default: 20 }
  },
  data() {
    return { drugs: [], loading: false, error: null, page: 1, total: 0 }
  },
  computed: {
    totalPages() { return Math.ceil(this.total / this.pageSize) }
  },
  methods: {
    async search(keyword) {
      this.loading = true
      try {
        const res = await fetchDrugs({ keyword, page: this.page, pageSize: this.pageSize })
        this.drugs = res.list
        this.total = res.total
      } catch (e) {
        this.error = e.message
      } finally {
        this.loading = false
      }
    },
    nextPage() { if (this.page < this.totalPages) this.page++ },
    prevPage() { if (this.page > 1) this.page-- }
  }
}
</script>
```

业务方可以完全自定义 UI：

```html
<!-- 业务页面 A：表格形式 -->
<DrugDataProvider category="OTC" v-slot="{ drugs, loading, search, nextPage }">
  <input @input="e => search(e.target.value)" placeholder="搜索药品" />
  <table v-if="!loading">
    <tr v-for="drug in drugs" :key="drug.id">
      <td>{{ drug.name }}</td>
      <td>{{ drug.price }}</td>
    </tr>
  </table>
  <button @click="nextPage">下一页</button>
</DrugDataProvider>

<!-- 业务页面 B：卡片形式 -->
<DrugDataProvider category="RX" v-slot="{ drugs, loading }">
  <div v-if="loading" class="skeleton"></div>
  <div v-else class="card-grid">
    <DrugCard v-for="drug in drugs" :key="drug.id" :drug="drug" />
  </div>
</DrugDataProvider>
```

**一套逻辑，多套 UI**，这是 renderless 组件的核心价值。在设计组件库时，可以把数据层（`DataProvider`）和展示层（`Card`/`Table`/`List`）彻底解耦。

### `$scopedSlots.default` 存在性检测

子组件在使用插槽前应检测父组件是否传入，否则调用未定义的函数会报错：

```javascript
// ❌ 危险写法
render() {
  return this.$scopedSlots.default({ drug: this.drug })
}

// ✅ 安全写法
render() {
  const defaultSlot = this.$scopedSlots.default
  if (!defaultSlot) {
    return this.$createElement('div', '暂无内容')
  }
  return defaultSlot({ drug: this.drug })
}
```

模板写法同理，用 `v-if` 保护：

```html
<template>
  <div>
    <slot v-if="$scopedSlots.default" :drug="drug"></slot>
    <p v-else>请传入插槽内容</p>
  </div>
</template>
```

### 插槽内容的响应式：两种时机的差异

| 插槽类型 | 响应时机 | 说明 |
|---------|---------|------|
| 普通/具名插槽 | 父组件重新 render | 插槽内容依赖父组件 data/computed 变化时更新 |
| 作用域插槽 | 子组件重新 render | 插槽函数在子组件 render 时执行，依赖子组件数据变化时更新 |

实际项目中的常见误区：用普通插槽传入内容，然后期望它能响应子组件内部的状态变化——这是不可能的，必须改用作用域插槽。

### 核心实现：三套编译产物手写

下面用纯 JS 手写三种插槽的编译产物，模拟 Vue 2 运行时行为（约 120 行）：

```javascript
// src/slots-demo.js

// ── 运行时辅助函数 ──────────────────────────────────────────

// 创建 VNode
function h(tag, data, children) {
  return { tag, data: data || {}, children: Array.isArray(children) ? children : [children].filter(Boolean) }
}

// 创建文本 VNode
function t(text) {
  return { tag: undefined, text: String(text) }
}

// renderSlot：_t() 的运行时实现
function renderSlot(vm, name, fallback, props) {
  // 优先走 $scopedSlots（含 Vue 2.6 统一后的普通插槽）
  const scopedSlotFn = vm.$scopedSlots && vm.$scopedSlots[name]
  if (scopedSlotFn) {
    return scopedSlotFn(props || {})
  }
  // 降级走 $slots（原始普通插槽）
  return (vm.$slots && vm.$slots[name]) || fallback || []
}

// 把普通插槽（VNode 数组）包装为函数，统一进 $scopedSlots（normalizeScopedSlots 简化版）
function normalizeSlots(slots, scopedSlots) {
  const res = Object.assign({}, scopedSlots || {})
  for (const key in slots) {
    if (!(key in res)) {
      const vnodes = slots[key]
      res[key] = () => vnodes  // 👈 包装为函数
    }
  }
  return res
}

// ── 子组件：DrugList ─────────────────────────────────────────
// 对应模板：
// <ul>
//   <li v-for="drug in drugs">
//     <slot :drug="drug" :index="index"></slot>   ← 作用域插槽
//   </li>
// </ul>

function createDrugList(options) {
  const vm = {
    drugs: [
      { id: 1, name: '布洛芬缓释胶囊', stock: 120, type: 'OTC' },
      { id: 2, name: '阿莫西林胶囊',   stock: 0,   type: 'RX'  },
      { id: 3, name: '复方甘草片',     stock: 56,  type: 'OTC' },
    ],
    $slots: {},
    $scopedSlots: {}
  }

  // 接收父组件传入的插槽（scopedSlots 是函数对象）
  if (options.scopedSlots) {
    vm.$scopedSlots = options.scopedSlots
  }
  if (options.slots) {
    // Vue 2.6 统一：把普通插槽也包装进 $scopedSlots
    vm.$slots = options.slots
    vm.$scopedSlots = normalizeSlots(options.slots, vm.$scopedSlots)
  }

  // render 函数（对应编译产物）
  vm.render = function() {
    const listItems = vm.drugs.map((drug, index) => {
      // _t("default", null, { drug, index }) 的手写版
      const slotContent = renderSlot(vm, 'default', [t('（无内容）')], { drug, index })
      return h('li', { style: 'padding: 8px; border-bottom: 1px solid #eee' }, slotContent)
    })
    return h('ul', { style: 'list-style:none; padding:0; margin:0' }, listItems)
  }

  return vm
}

// ── 演示一：普通插槽（父作用域渲染）────────────────────────────
// 父组件只传静态内容，无法访问 drug 数据
function demo1() {
  const parentData = { label: '药品列表' }  // 父组件自己的数据

  // 普通插槽编译产物：直接传 VNode 数组（父作用域已生成）
  const slots = {
    default: [
      h('span', { style: 'color: gray' }, [t(`来自父组件：${parentData.label}`)])
      // 👆 这里访问不到 drug.name，因为 VNode 在父作用域生成时 drug 还不存在
    ]
  }

  const vm = createDrugList({ slots })
  return renderToHTML(vm.render())
}

// ── 演示二：作用域插槽（子作用域渲染）────────────────────────────
// 父组件传函数，子组件调用时注入 drug 数据
function demo2() {
  // 作用域插槽编译产物：是函数，接收子组件传来的 { drug, index }
  const scopedSlots = {
    default: function({ drug, index }) {
      // 👆 此时才生成 VNode，drug 是子组件传来的数据
      const stockText = drug.stock === 0 ? '❌ 缺货' : `✅ 库存 ${drug.stock}`
      const typeColor = drug.type === 'OTC' ? '#52c41a' : '#1890ff'
      return [
        h('span', { style: 'font-weight:bold; margin-right:8px' }, [t(`${index + 1}. ${drug.name}`)]),
        h('span', { style: `color: ${typeColor}; margin-right:8px` }, [t(drug.type)]),
        h('span', {}, [t(stockText)])
      ]
    }
  }

  const vm = createDrugList({ scopedSlots })
  return renderToHTML(vm.render())
}

// ── 演示三：具名插槽 ──────────────────────────────────────────
// 子组件暴露多个插槽：header / default / footer
function createDrugCard(options) {
  const vm = {
    drug: { name: '布洛芬缓释胶囊', spec: '0.3g×24粒', price: 18.5, warning: '孕妇慎用' },
    $slots: {},
    $scopedSlots: {}
  }

  if (options.slots) {
    vm.$slots = options.slots
    vm.$scopedSlots = normalizeSlots(options.slots, {})
  }

  vm.render = function() {
    const header  = renderSlot(vm, 'header',  [h('h3', {}, [t(vm.drug.name)])])
    const content = renderSlot(vm, 'default', [h('p',  {}, [t(vm.drug.spec)])])
    const footer  = renderSlot(vm, 'footer',  [h('p',  { style: 'color:red; font-size:12px' }, [t(vm.drug.warning)])])

    return h('div', { style: 'border:1px solid #ddd; padding:16px; border-radius:4px; width:300px' }, [
      h('div', { style: 'border-bottom:1px solid #eee; padding-bottom:8px; margin-bottom:8px' }, header),
      h('div', {}, content),
      h('div', { style: 'border-top:1px solid #eee; padding-top:8px; margin-top:8px' }, footer)
    ])
  }

  return vm
}

function demo3() {
  const slots = {
    header:  [h('h3', { style: 'color:#1890ff; margin:0' }, [t('💊 布洛芬缓释胶囊')])],
    default: [h('p',  {}, [t('规格：0.3g×24粒 | 价格：¥18.5')])],
    footer:  [h('p',  { style: 'color:orange; font-size:12px; margin:0' }, [t('⚠️ 孕妇及哺乳期妇女慎用')])]
  }

  const vm = createDrugCard({ slots })
  return renderToHTML(vm.render())
}

// ── VNode → HTML 字符串（极简渲染器）──────────────────────────
function renderToHTML(vnode) {
  if (!vnode) return ''
  if (Array.isArray(vnode)) return vnode.map(renderToHTML).join('')
  if (vnode.text !== undefined) return escapeHTML(vnode.text)

  const attrs = Object.entries(vnode.data || {})
    .map(([k, v]) => `${k}="${v}"`)
    .join(' ')
  const children = (vnode.children || []).map(renderToHTML).join('')
  return `<${vnode.tag}${attrs ? ' ' + attrs : ''}>${children}</${vnode.tag}>`
}

function escapeHTML(str) {
  return str.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;')
}

// ── 挂载到页面 ────────────────────────────────────────────────
document.addEventListener('DOMContentLoaded', () => {
  document.getElementById('demo1').innerHTML = demo1()
  document.getElementById('demo2').innerHTML = demo2()
  document.getElementById('demo3').innerHTML = demo3()
})
```

## 💡 八、一张图总结（面试速记）

| 类型 | 编译产物（父组件） | 渲染时机 | 能否访问子数据 | `$slots` / `$scopedSlots` | 面试频率 |
|------|-----------------|---------|-------------|--------------------------|---------|
| 默认插槽 | VNode 数组（children） | 父组件 render | ❌ | `$slots.default` | ⭐⭐⭐⭐ |
| 具名插槽 | VNode 数组（children） | 父组件 render | ❌ | `$slots.header` | ⭐⭐⭐⭐ |
| 作用域插槽 | 插槽函数 `fn(slotData)` | 子组件 render | ✅ | `$scopedSlots.default()` | ⭐⭐⭐⭐⭐ |
| Vue 2.6 统一后 | 所有插槽均包装为函数 | — | — | `$scopedSlots` 统一访问 | ⭐⭐⭐ |

**记住这一句**：普通插槽是 VNode（父渲染），作用域插槽是函数（子调用）——渲染时机的差异决定了能否访问子数据。
