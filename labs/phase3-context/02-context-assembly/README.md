# 02 — 上下文组装：预算分配表 + 顺序对照的隐藏变量

对应文章：第 02 篇《上下文组装：一次调用里放了什么、各占多少》

## 要验证什么

1. **一次真实用药咨询调用里，六类内容各占多少 token**（实验 A，纯本地 gpt-tokenizer，零调用）——重点看「历史 + 工具结果」是不是悄悄吃掉一半以上窗口。
2. **顺序对照实验里，temperature 是隐藏变量**（实验 B，18 次真实调用）——重点看「掐住温度」和「不掐住温度」，同一个「相似候选」上下文会不会测出不一样的东西。

> 为什么实验 B 不直接复现「中间丢」？因为先用「唯一事实埋中间」验证过：DeepSeek 上无论上下文拉到 20k、60k，还是换信息密集历史、连贯长文档，「唯一事实」放中间都稳定命中——位置效应在「答案只有一份」时几乎不显形。「关键信息放头尾」的干净证据在阶段一 needle 实验（9 格矩阵）与 Lost in the Middle 论文里；本篇实验 B 补的是**方法这一课**：做任何顺序/编排对照实验，先掐住 temperature。

```
index.ts       主脚本：实验 A（预算表）+ 实验 B（温度对照 2×3×3 = 18 次调用）
fixtures.ts    样例上下文：六类内容（实验 A）+ 26 段相似档案（实验 B 的三组位置）
../_sdk/assemble.ts   组装器：measureBudget（预算）+ assemble（顺序 + 配额截断），供 03~06 篇复用
../_sdk/client.ts     共用调用入口 callModel（支持 opts.temperature，默认不传用默认采样）
```

## 怎么跑

```bash
nvm use 22
pnpm --filter @medai/labs p3-assemble
```

需要 `.env.local` 里配 `DEEPSEEK_API_KEY`，缺 key 时给中文提示并退出。实验 A 纯本地不花钱，实验 B 18 次调用约 ¥0.5。

## 看到什么算成功

### 实验 A：预算分配表

一张表六行：六类内容各自的 token 数与占比。要点——**历史 + 工具结果两类合计往往超过一半**，验证「预算失控通常不是检索片段，是历史与工具返回」。

### 实验 B：temperature 对照

一张表六行：temperature=0 / 默认采样 × 头/中/尾 三个位置的命中率（各 3 轮）。

- temperature=0 那一列应稳定全中——贪心解码永远选最高概率 token，把「位置信心不足」藏起来。
- 默认采样那一列可能偶发漂移（答成「2 级」）——但小样本下「哪个位置漂」是随机的，跑一轮一个样。
- 结论是方法论的：对照实验不掐温度，测到的不是「位置」，是「采样随机性」。

## 预算

实验 A 零调用；实验 B 2 组 × 3 位置 × 3 轮 = 18 次调用，约 ¥0.5。脚本启动会打印预估消耗。
