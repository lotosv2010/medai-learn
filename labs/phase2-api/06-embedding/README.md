# 06 — Embedding：把「意思相近」变成一道可以算的减法

对应文章：第 06 篇《Embedding：把「意思相近」变成一道可以算的减法》

## 要验证什么

用本地 Ollama 的 `qwen3-embedding:0.6b` 把 12 段说明书片段向量化，再算相似度、做检索、比度量。

```
index.ts    主脚本：实验 A（相似度矩阵）+ B（查询 Top-3）+ C（三度量对照）
samples.ts  12 段说明书片段 + 5 个查询 + 期望命中
```

代码只回答四个问题：

1. **同类片段会不会聚在一起**？两段「用法用量」相似度应该明显高；但「禁止饮酒」和「可少量饮酒」可能分不清——否定句是向量的盲区。
2. **「服药期间能否饮酒」会不会把「可少量饮酒」排到「禁止饮酒」前面**？逻辑相反的两句话，向量可能分不清谁是答案。
3. **「儿童剂量」会不会把「成人剂量」也排进前列**？数字对向量不敏感，0.5g 和 20mg/kg 的距离没有「剂量」这个词的距离近。
4. **余弦、欧氏、点积三种度量差在哪**？归一化之后，余弦与点积的排序完全一致。

## 怎么跑

```bash
# 仓库根目录，Node 22
nvm use 22
ollama pull qwen3-embedding:0.6b   # 首次，约 639MB
pnpm --filter @medai/labs p2-embed
```

需要本机已启动 Ollama（`ollama serve`）。无需 API key，全程零成本。可设 `OLLAMA_HOST` 指向远端（默认 `http://127.0.0.1:11434`）。

## 看到什么算成功

### 实验 A：12×12 相似度矩阵

成功的标志是：对角线上全是 1.00（自己和自己最像）；S7/S8（两段用法用量）相似度高达 0.80；S5「禁止饮酒」与 S6「可少量饮酒」的相似度 0.72——是 S5 那一行除对角线外最高的值。

### 实验 B：5 个查询的 Top-3

成功的标志是：「服药期间能否饮酒」的 Top-1 命中 **S6「可少量饮酒」**（0.82），而真正的答案 S5「禁止饮酒」只排第二——复现了「向量分不清否定与肯定」；「儿童剂量」正确命中 S8，但 S7「成人剂量」以 0.66 紧随其后排第二——复现了「数字不敏感」。

### 实验 C：三度量对照

成功的标志是：归一化后，余弦、点积、欧氏三行排序完全一样。

## 故意留下的两处「不完美」

| 没做的事 | 为什么 | 留在哪 |
|---|---|---|
| 不建向量库、不分块、不检索回填 Prompt | 那是 RAG 的活，本篇只解决「文本怎么变成能比大小的数组」 | 阶段四 |
| 不做混合检索与重排序 | 正是本篇两个失败（否定句 / 数字）的解法 | 阶段四 |
