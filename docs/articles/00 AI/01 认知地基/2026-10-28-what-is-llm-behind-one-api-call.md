# 大模型到底是什么：一次 API 调用背后发生了什么

> 它不是搜索引擎，不是数据库，也不是推理引擎——它是一台「算下一个词」的概率机器。

---

## 🎯 这篇文章解决什么问题

「为什么大模型会一本正经地胡说八道？」

这个问题我面过很多人。答「训练数据不够全」的，基本就停在这儿了。答「因为它的目标函数不是求真，而是求像」的，才算摸到了门。

不夸张地说，**大模型的所有怪毛病——幻觉、没有记忆、不会算数、答得很像真的但全是编的——都能从一个定义里推出来。** 这个定义就是：它是一个逐词续写的概率机器，不是检索系统。

这篇文章要解决四件事：

- 三个几乎所有人都踩过的误判，为什么它们看起来都对、实际都错
- 自回归生成到底在做什么，一次调用从输入到输出完整走一遍
- 预训练 / SFT / RLHF 三阶段各给了模型什么，少一个会怎样
- 亲手跑一次 API，看清你付的钱到底买的是什么

每一段都配「面试官会怎么问」，以及标准答案和加分答案。读完你不只是懂了，是能答了。

## 🔍 三个几乎所有人都踩过的误判

先说三个真实会发生的事。

**第一个：把它当搜索引擎。** 你问「这款药最新的说明书里写了什么禁忌」，它答得条理清晰、格式规范、用词专业。但你回头核原始说明书，发现有一整段根本不存在。

**第二个：把它当数据库。** 你告诉它「我们这边的用药规范是首剂加倍」，它记住了，这一轮答得很好。下一轮新开一个对话，它完全不记得你谁。

**第三个：把它当推理引擎。** 你让它按体重折算儿童剂量，简单题它算对了，你觉得可以托付。换成「按体重折算后再判断是否超过成人上限，超了按上限给」——它给你一个数字，格式漂亮，逻辑不通。

三个场景，三种失败，但根子是同一个。

| 你以为它是 | 它的实际行为 |
|---|---|
| 搜索引擎：有则返回，无则空 | 参数里没有，也照样续写，续出最像的文本 |
| 数据库：存了就有，没存就没有 | 每次调用都是全新实例，不留上一轮任何痕迹 |
| 推理引擎：按规则演算 | 续写「最可能的算式结果」，不是真的在算 |

三种误判殊途同归到同一个动作：**给定前文，续写下一个 token。**

- 没有对应信息时：它不返回空、不报错，而是续出最像的文本
- 后果：💥 幻觉 / 无记忆 / 算错复杂题

> **你以为是它在「取回」信息，其实它在「续写」文本。**

搜索引擎的模型是「有则返回、无则空」。数据库的模型是「存了就有、没存就没有」。推理引擎的模型是「按规则演算」。

而大模型的模型是：**给定前面这些字，下一个字最可能是什么。**

这一个差别，决定了它在医疗、法律、金融这类「事实准确性优先」的场景里，天生带着风险。

🔧 **真实场景**：在用药咨询助手里，用户问「这个药能不能和布洛芬一起吃」。直接问模型，它会给你「一般可以，建议间隔两小时」。听起来很专业，但这**不是查询了药物相互作用数据库的结果**，而是在它读过的海量文本里，「这两类药一起出现」后面最常见接的是什么话。幸运的话它答对了，不幸的话你拿到一个格式完美的错误建议。

## ⚙️ 概率续写机器：一次生成到底发生了什么

### 逐词续写的机械过程

大模型一次生成，本质上是一个循环：

- 把已有的全部文本切成一串 token，送进模型
- 模型输出「词表里每个 token 作为下一个词的概率分布」
- 从这个分布里**采样**一个 token，接到序列末尾
- 把新序列再送进去，重复，直到采到结束标记

这个过程叫自回归生成。它没有「想好了再说」，只有「边说边想下一个字」。

示意图长这样（概率是编的，只为了让你看见形状）：

```text
已有文本：阿莫西林的常见不良反应
模型输出：包括 0.62 | 主要有 0.18 | 一般有 0.09 | 常见 0.05 | ……（万亿级词表）
采样结果：「包括」

已有文本：阿莫西林的常见不良反应包括
模型输出：恶心 0.31 | 胃肠道 0.22 | 皮疹 0.15 | 腹泻 0.11 | ……
采样结果：「恶心」

……（如此循环，直到采到结束标记）
```

这个循环就是个没有出口的闭环——**每吐一个字，都要把「前文 + 新字」整段重新送进去算一遍**（工程上用 KV 缓存避免重复计算，但逻辑上就是这样滚雪球）：

![自回归生成：每算出一个 token，就把它拼回序列末尾，再把整段送回模型重算](https://jalammar.github.io/images/xlnet/gpt-2-autoregression-2.gif)

拆开看是这样一个闭环：**已有文本 → 切 token → 前向计算 → 下一 token 概率分布 → 采样一个 → 拼回末尾 → 判断是否采到结束标记 → 没采到就再走一圈，采到就返回完整文本。**

你打「今天天气」时输入法给你「不错 / 很好 / 真热」，是同一个机制。**区别只在于这个大模型读过的东西多到足以让它续出来的文字看起来像知识。**

![手机输入法的联想候选词：和模型采样下一个 token 是同一件事，只是规模差了几个数量级](https://jalammar.github.io/images/word2vec/swiftkey-keyboard.png)

### 为什么幻觉不是 bug，是这套机制的必然产物

这是全文最重要的一段，请慢读。

模型的训练目标是：**让「真实的下一句」在它预测的分布里概率尽量高。** 换句话说，它被优化的方向是「生成像人写的文本」，不是「生成真的陈述」。

这两件事在绝大多数场景下重合——所以它看起来很有用。但当真实信息不在模型参数里时，两者就分叉了：

用户提问：「这个药最新的禁忌是什么」→ 先看真实信息在不在模型参数里：

| 真实信息在参数里吗 | 只剩哪些候选动作 | 这个动作在语料里的概率 | 结果 |
|---|---|---|---|
| ✅ 在 | 续写出正确内容 | 高 | 答对了 |
| ❌ 不在 | 编一段像说明书的话（这类文本语料里到处都是） | **高** | 💥 幻觉：格式完美，内容虚构 |
| ❌ 不在 | 回答「我不知道」（诚实弃权在语料里极稀有） | **低，几乎采不到** | 本应如此，但采不到 |

注意那两行的概率差：**「我不知道」不是模型不愿意说，是在概率上它压根轮不到被采样。**

于是模型必然选择前者。**它不是不知道自己在编，是这个机制里压根没有「知道 / 不知道」这个维度。**

再加一层：在后来的对齐训练里，人类标注员普遍更喜欢「给了答案」的回答而不是「我拒绝回答」。这进一步把「编一个」的概率推高。

> 💬 **面试官**：为什么大模型会一本正经地胡说八道？
>
> ✅ **标准答案**：因为它的目标函数是下一 token 的似然而不是事实正确性。它在做概率续写，不是检索。当参数里没有真实信息时，「最像真的续写」就是编造。
>
> 🎁 **加分答案**：而且「我不知道」在训练语料里的频率极低，所以在概率上天然劣于编造；后续的人类偏好对齐又进一步奖励了「给出答案」的行为。所以幻觉不是数据不够导致的，是**目标函数决定的结构性产物**——数据再多也只是降低频率，不可能消除。

### 为什么它「没有记忆」

每一次 API 调用都是**完全无状态**的。你把 messages 发过去，它生成回复，这次交互在服务端不留下任何东西。下一次请求它是全新的。

那你为什么感觉它有记忆？

因为多轮对话时，**你的客户端把前面所有的历史消息又重新拼进了这次请求里**。它「记得」的每一句话，都是你每一次亲手重新递给它的。

| 轮次 | 客户端实际发出的 `messages` | 服务端 |
|---|---|---|
| 第 1 轮 | `[第1轮问题]` | 全新推理，这轮之后什么都不留 |
| 第 2 轮 | `[第1轮问题, 第1轮回答, 第2轮问题]` | 依旧是全新推理 |
| 第 3 轮 | `[1问, 1答, 2问, 2答, 3问]` | 依旧是全新推理 |

**注意中间那一列：每一轮都比上一轮多塞了一截历史，而右边那一列从头到尾都没变过——它不认识你，只是每次都把递过去的东西读一遍。**

```typescript
// 你以为的第 3 轮请求
// 实际发出去的第 3 轮请求
messages: [
  { role: 'user', content: '第 1 轮的问题' },      // 👈 历史被重放
  { role: 'assistant', content: '第 1 轮的回答' }, // 👈 历史被重放
  { role: 'user', content: '第 2 轮的问题' },      // 👈 历史被重放
  { role: 'assistant', content: '第 2 轮的回答' }, // 👈 历史被重放
  { role: 'user', content: '第 3 轮的问题' },
]
```

这解释了两件很多人没连起来的事：

- **为什么对话越长越贵**——每一轮都在为全部历史重复付费
- **为什么聊久了它会「忘」**——不是忘了，是历史塞不进窗口被裁掉了

> 💬 **面试官**：大模型有记忆吗？多轮对话的「记忆」是怎么来的？
>
> ✅ **标准答案**：模型本身无状态，API 也不维护会话。所谓记忆是应用层把历史消息重新拼进上下文实现的。
>
> 🎁 **加分答案**：这意味着「记忆」是一个工程问题，不是模型能力。它直接引出上下文窗口的预算管理、历史压缩和 Prompt 缓存——这也是为什么上下文工程会成为 AI 应用的核心议题。

## 🗺️ 三阶段训练全景：知识、格式与脾气

我们作为应用开发者，只做推理侧的调用者，不做训练。但不懂这三段，就没法解释模型为什么有这些脾气。

**第一段：预训练（Pre-training）。** 给它几万亿 token 的文本，任务只有一个——预测下一个词。做完之后得到一个基座模型。**它的全部「知识」都是在这一步进到参数里的，所以知识截止日就锁在这批数据的截止时间。**

**第二段：SFT（监督微调）。** 用大量「指令 → 理想回答」的成对数据继续训练。这一步教的不是知识，是**格式和服从**：让它明白「用户抛来一个问题，我该组织成一段回答」，而不是接着往下续写更多问题。

**第三段：RLHF / DPO（对齐）。** 让人类（或另一个模型）对多个候选回答排序打分，用这些偏好数据继续调。这一步塑造的是**脾气**：更有用、更少有害、更愿意拒绝。

一句话记忆钩子：**预训练给知识，SFT 给格式，RLHF 给脾气。**

把三段串起来看，每一段在「同一条流水线」上拧的是不同的螺丝：

![三阶段训练：① 预训练给知识 → ② SFT 给格式 → ③ RLHF 给脾气，最后才是你调用的对话模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/rlhf/rlhf.png)

对照着图记一句话：**第一格进的是「知识」，第二格进的是「格式」，第三格进的是「脾气」。**

少一个会怎样？

- 只有预训练：你有了一台读过全世界的文本补全机，但它不一定会「回答问题」。你问它「阿莫西林的禁忌是什么」，它可能续写出更多类似的问题——因为在它的经验里，这类文本后面经常跟着一连串问题
- 有预训练 + SFT，没对齐：会答了，但可能啰嗦、说教、被引导着说不该说的话
- 没有预训练只有后两步：无从谈起，因为它压根没知识

### 知识截止是怎么产生的

预训练数据有一刀切的时间点。这之后发生的事，模型不可能知道——**而且它不知道自己不知道。**

这是最容易被忽略的一点：模型不会因为「这个信息在我的训练数据之后」而降低置信度。它会拿最接近的旧知识，用同样自信的语气答出来。

```text
预训练语料覆盖的时间段          🔪 知识截止日            截止日之后
────────────────────────────────┼──────────────────────────────▶
 参数里有这段知识               │   新药上市 / 指南修订 / 价格调整
 ✅ 能答得准确、说得具体        │   ❌ 模型不知道
                                │   而且不知道自己不知道
                                │   ➜ 拿最接近的旧知识，
                                │     用同样自信的语气答
                                │   💥 看起来专业，实际过期
```

所以「提示它注意时效」没有用。你在 prompt 里写「请注意信息可能已过时」，只是给它增加了一段文本，改变不了它参数里根本没有新知识这个事实。

绕过的唯一正路是：**需要时效性的问题，必须走检索或工具，不能靠模型记忆。**

> 💬 **面试官**：预训练 / SFT / RLHF 各自解决什么问题？少一个会怎样？
>
> ✅ **标准答案**：预训练给知识和语言能力，SFT 给指令服从和输出格式，RLHF 给人类偏好的对齐。少了预训练没有知识底座，少了 SFT 不会按指令组织回答，少了 RLHF 可用性和安全性都不达标。
>
> 🎁 **加分答案**：这三段里，**只有预训练在注入事实性知识**。所以「模型知识过期了怎么办」这个问题的答案只有一个方向——外部注入（RAG / 工具），而不是「再训练一下让它记住」。这也正是阶段四要建 RAG 的根本动机。

### 边界：你在哪一侧

顺手划清三条线，避免后面学串：

- **推理 vs 训练**：我们做的是推理——把已有的模型调起来用。不改权重，不碰数据工程
- **开源 vs 闭源**：闭源只能通过 API 用；开源可以下载权重自己跑，代价是自己扛显存和运维
- **应用层 vs 算法层**：应用层的核心能力是「怎么把一个概率机器用稳」，不是「怎么让概率机器更准」

## 🧪 动手实验：看见 token 用量

> **说明**：下面这段是脚本的**运行形态示意**，其中的 token 数字与回答措辞为示意值，真实数值以你本机运行为准。脚本已就绪：`labs/phase1-cognition/00-hello-llm/`，一条命令即可跑通。

实验设计很简单：同一个医疗问题，分别问 DeepSeek、通义千问、Claude 三家的模型，**把完整原始响应打印出来**。

```bash
# 在仓库根目录
pnpm install
cp .env.local.example .env.local    # 填入至少两家的 key
pnpm --filter @medai/labs hello
```

问题选的是：**「阿莫西林胶囊的常见不良反应有哪些？请用三句话概括。」**

脚本刻意不用任何官方 SDK，直接 `fetch` 裸 HTTP 请求。原因很直白：**SDK 会把「请求长什么样」「响应长什么样」藏起来，而你这一篇要看的恰恰就是这个。**

```typescript
const res = await fetch(`${baseURL}/chat/completions`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${apiKey}`,
  },
  body: JSON.stringify({
    model: 'deepseek-chat',
    messages: [{ role: 'user', content: QUESTION }],
    temperature: 0.7,
  }),
})
```

### 要看见的第一件事：返回结构

响应 JSON 里字段很多，但按「该不该花时间盯」只分三层：

| 层 | 字段 | 用途 | 该花多少时间 |
|---|---|---|---|
| 你要的 | `choices[0].message.content` | 人读的文本，**只有这一个** | 全部 |
| 账单 | `usage.prompt_tokens` / `completion_tokens` / `total_tokens` | 计费依据 | 跑之前先预估 |
| 元数据 | `id` / `object` / `created` / `model` / `finish_reason` | 排查与观测 | 只盯 `finish_reason`（它告诉你为什么停） |

```typescript
interface ChatResponse {
  choices: Array<{ message: { content: string } }>  // 👈 人读的文本，就这一个
  usage: {
    prompt_tokens: number      // 你发过去的
    completion_tokens: number  // 它生成的
    total_tokens: number       // 账单按这个算
  }
  // 其余字段：id / object / created / model / finish_reason…… 全是元数据
}
```

只看这一个 `content`，你会发现返回给你的**是文本，不是事实**。

### 要看见的第二件事：token 就是账单单位

示意值如下（真实值请自己跑一遍）：

| 模型 | 输入 token | 输出 token |
|------|-----------|-----------|
| DeepSeek | 28 | 96 |
| 通义千问 | 31 | 88 |
| Claude | 27 | 102 |

三家的量级接近，但都**明显大于你数出来的字数**。你只发了 20 来个汉字，它算你 28 个 token——为什么？这个问题直接引出下一篇。

### 要看见的第三件事：三家结构高度相似

同一个问题，三家措辞不同、断句不同、专业程度略有差异，但**结构惊人地一致**：都是「主要不良反应有 A、B、C，偶见 D，如出现 E 应就医」这个套路。

不是它们串通好了，是因为它们在学同一件事——**这类文本在语料里最可能的写法**。

> 💬 **面试官**：你调用过一次大模型 API，能说说返回了什么吗？
>
> ✅ **标准答案**：文本在 `choices[0].message.content`，计费看 `usage` 的三个 token 字段。
>
> 🎁 **加分答案**：要点出「你拿到的是文本，不是事实；你付费买的是 token，不是答案」——这两句话能立刻把你和只会调 SDK 的人区分开。

🔧 **真实场景**：脚本启动第一件事是打印预估消耗。这不是仪式感——LLM 按 token 计费，一个忘关的循环能在几分钟内烧掉几十块。**把「跑之前先看见要花多少」做成肌肉记忆，比任何成本优化技巧都值钱。**

## 🚧 结论与边界

本篇的结论可以压缩成一句话：

> **大模型 = 概率续写机器 × 三阶段训练的产物。它的一切局限，都能从这个定义推出来。**

幻觉，因为目标是「像」不是「真」。没记忆，因为每调用一次都是全新的。算错复杂题，因为它在续写最可能的算式结果而不是在演算。

有意识地留到后面四件事：

- **token 具体怎么切、为什么中文更贵** → 第 01 篇
- **幻觉怎么降低、知识截止怎么绕** → 第 02 篇
- **temperature 这些参数在调什么** → 第 03 篇
- **上下文怎么编排、怎么缓存** → 阶段三（上下文工程）

## 🎤 面试追问链

单个问题答对只能拿及格分。真正的区分度在追问——面试官会顺着你的答案往下挖，看你有没有真正的体系。

**追问一：「你说幻觉是续写导致的，那上 RAG 能根治吗？」**

不能根治，只能压缩。RAG 解决的是「知识不在参数里」这一类幻觉——它把真实资料塞进上下文，让模型续写的原料变成真材料。但「资料在眼前，它答偏了」这种忠实性幻觉依然存在。**没有任何手段能根除幻觉，只能把概率压到可接受。**

**追问二：「那微调呢？把说明书训进去不就记住了？」**

方向错了。微调擅长的是固化格式、风格、任务特化，不是可靠的知识注入。而且知识一更新就要重训，成本高、周期长、还同样不保证事实准确。这正是「知识频繁更新的场景优选 RAG」的原因。

**追问三：「现在窗口都到 200K 了，是不是直接把整本说明书塞进去就行？」**

窗口是预算，不是保险柜。塞得进去和读得出来是两件事，中间隔着注意力稀释。而且每一轮都为这段长文本付费。这个问题的完整答案在第 01 篇。

**追问四：「那你把 temperature 设成 0，是不是就完全确定了？」**

不保证。浮点运算顺序、并发实现的差异都会带来微小抖动。工程上要「可复现」，靠的是日志、固定版本和评估集兜底，不是靠一个参数。这个留给第 03 篇。
