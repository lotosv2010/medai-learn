# <font style="color:rgb(51, 51, 51);">V8内存管理</font>
+ <font style="color:rgb(51, 51, 51);">程序运行需要分配内存</font>
+ <font style="color:rgb(51, 51, 51);">V8也会申请内存，申请的内存又会分为堆内存和栈内存</font>

## <font style="color:rgb(51, 51, 51);">栈</font>
+ <font style="color:rgb(51, 51, 51);">栈用于存放JS中的基本类型和引用类型指针</font>
+ <font style="color:rgb(51, 51, 51);">栈的空间是连续的，增加删除只需要移动指针，操作速度非常快</font>
+ <font style="color:rgb(51, 51, 51);">栈的空间是有限的，当栈满了，就会抛出一个错误</font>
+ <font style="color:rgb(51, 51, 51);">栈一般是在执行函数时创建的，在函数执行完毕后，栈就会被销毁</font>

```javascript
              `${format(space.space_used_size)}`,

              `${format(space.physical_space_size)}`);
}
```

### <font style="color:rgb(51, 51, 51);">堆空间分类</font>
#### <font style="color:rgb(51, 51, 51);">新生代(new space)</font>
+ <font style="color:rgb(51, 51, 51);">新生代内存用于存放一些生命周期比较短的对象数据</font>

#### <font style="color:rgb(51, 51, 51);">老生代(old space)</font>
+ [<font style="color:rgb(51, 122, 183);">老生代</font>](https://gitee.com/zhufengpeixun/v8/blob/master/src/heap/paged-spaces.cc)<font style="color:rgb(51, 51, 51);">内存用于存放一些生命周期比较长的对象数据</font>
+ <font style="color:rgb(51, 51, 51);">当</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">new space</font>`<font style="color:rgb(51, 51, 51);">的对象进行两个周期的垃圾回收后，如果数据还存在</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">new space</font>`<font style="color:rgb(51, 51, 51);">中，则将他们存放到</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">old space</font>`<font style="color:rgb(51, 51, 51);">中</font>
+ <font style="color:rgb(51, 51, 51);">old space又可以分为两部分，分别是Old pointer space和Old data space</font>
    - <font style="color:rgb(51, 51, 51);">Old pointer space 存放GC后surviving的指针对象</font>
    - <font style="color:rgb(51, 51, 51);">Old data space 存放GC后surviving的数据对象</font>
+ <font style="color:rgb(51, 51, 51);">Old Space使用标记清除和标记整理的方式进行垃圾回收</font>

#### <font style="color:rgb(51, 51, 51);">Code space</font>
+ <font style="color:rgb(51, 51, 51);">用于存放JIT已编译的代码</font>
+ <font style="color:rgb(51, 51, 51);">唯一拥有执行权限的内存</font>

#### <font style="color:rgb(51, 51, 51);">Large object space</font>
+ <font style="color:rgb(51, 51, 51);">为了避免大对象的拷贝，使用该空间专门存储大对象</font>
+ <font style="color:rgb(51, 51, 51);">GC 不会回收这部分内存</font>

#### <font style="color:rgb(51, 51, 51);">Map space</font>
+ <font style="color:rgb(51, 51, 51);">存放对象的Map信息，即隐藏类</font>
+ <font style="color:rgb(51, 51, 51);">隐藏类是为了提升对象属性的访问速度的</font>
+ <font style="color:rgb(51, 51, 51);">V8 会为每个对象创建一个隐藏类，记录了对象的属性布局，包括所有的属性和偏移量</font>

### <font style="color:rgb(51, 51, 51);">什么是垃圾</font>
+ <font style="color:rgb(51, 51, 51);">在程序运行过程中肯定会用到一些数据，这些数据会放在堆栈中，但是在程序运行结束后，这些数据就不会再被使用了，那些不再使用的数据就是垃圾</font>

```javascript
global.a = { name: 'a' };
global.a.b = { name: 'b1' };
global.a.b = { name: 'b2' };
```

> #### 引用计数法（已被淘汰）
> 早先的一种垃圾回收算法，它把 `对象是否不再需要` 简化定义为 `对象有没有其他对象引用到它`，如果没有引用指向该对象（零引用），对象将被垃圾回收机制回收，目前很少使用这种算法了，因为它的问题很多
>
> **优点**
>
> + 引用计数算法的优点我们对比标记清除来看就会清晰很多，首先引用计数在引用值为 0 时，也就是在变成垃圾的那一刻就会被回收，所以它可以立即回收垃圾，而标记清除算法需要每隔一段时间进行一次，那在应用程序（JS脚本）运行过程中线程就必须要暂停去执行一段时间的 `GC`
> + 标记清除算法需要遍历堆里的活动以及非活动对象来清除，而引用计数则只需要在引用时计数就可以了 **缺点**
> + 首先它需要一个计数器，而此计数器需要占很大的位置，因为我们也不知道被引用数量的上限，还有就是无法解决循环引用无法回收的问题，这也是最严重的
>

### <font style="color:rgb(51, 51, 51);">新生代的垃圾回收</font>
+ <font style="color:rgb(51, 51, 51);">新生代内存有两个区域，分别是对象区域(from) 和 空闲区域(to)</font>
+ <font style="color:rgb(51, 51, 51);">新生代内存使用</font>`<font style="color:rgb(111, 89, 144);background-color:rgb(237, 237, 247);">Scavenger</font>`<font style="color:rgb(51, 51, 51);">算法来管理内存,</font>[<font style="color:rgb(51, 122, 183);">垃圾回收的入口</font>](https://gitee.com/zhufengpeixun/v8/blob/master/src/heap/heap-inl.h)
    - <font style="color:rgb(51, 51, 51);">广度优先遍历 From-Space 中的对象，从根对象出发，广度优先遍历所有能到达的对象,把存活的对象复制到 To-Space</font>
    - <font style="color:rgb(51, 51, 51);">遍历完成后，清空 From-Space</font>
    - <font style="color:rgb(51, 51, 51);">From-Space 和 To-Space 角色互换</font>
+ <font style="color:rgb(51, 51, 51);">复制后的对象在 To-Space 中占用的内存空间是连续的，不会出现碎片问题</font>
+ <font style="color:rgb(51, 51, 51);">这种垃圾回收方式快速而又高效，但是会造成空间浪费</font>
+ <font style="color:rgb(51, 51, 51);">新生代的 GC 比较频繁</font>
+ <font style="color:rgb(51, 51, 51);">新生代的对象转移到老生代称为晋升</font>[<font style="color:rgb(51, 122, 183);">Promote</font>](https://gitee.com/zhufengpeixun/v8/blob/master/src/heap/heap.h#L760)<font style="color:rgb(51, 51, 51);">,</font>[<font style="color:rgb(51, 122, 183);">判断晋升</font>](https://gitee.com/zhufengpeixun/v8/blob/master/src/heap/heap-inl.h#L522)<font style="color:rgb(51, 51, 51);">的情况有两种</font>
    - <font style="color:rgb(51, 51, 51);">经过一次 GC 还存活的对象</font>
    - <font style="color:rgb(51, 51, 51);">对象复制到 To-Space 时，To-Space 的空间达到一定的限制</font>

```javascript
global.a={};
global.b = {e：{}}
global.c = {f: {},g:{h:{}}} 
global.d = {};
global.d=null;
```

```javascript
bool Heap::ShouldBePromoted(Address old_address) {
  Page* page = Page::FromAddress(old_address);
  Address age_mark = new_space_->age_mark();
  return page->IsFlagSet(MemoryChunk::NEW_SPACE_BELOW_AGE_MARK) &&
    (!page->ContainsLimit(age_mark) || old_address < age_mark);
}
```

### <font style="color:rgb(51, 51, 51);">老生代的垃圾回收</font>
+ <font style="color:rgb(51, 51, 51);">老生代里的对象有些是从新生代晋升过来的，有些是比较大的对象直接分配到老生代里的，所以老生代的对象空间大，活的长</font>
+ <font style="color:rgb(51, 51, 51);">如果使用Scavenge算法，浪费一半空间不说，复制如此大块的内存消耗时间将会相当长。所以Scavenge算法显然不适合</font>
+ <font style="color:rgb(51, 51, 51);">V8在老生代中的垃圾回收策略采用Mark-Sweep(标记清除)和Mark-Compact(标记整理)相结合</font>

#### <font style="color:rgb(51, 51, 51);">Mark-Sweep(标记清除)</font>
+ <font style="color:rgb(51, 51, 51);">标记清除分为标记和清除两个阶段</font>
+ <font style="color:rgb(51, 51, 51);">在标记阶段需要遍历堆中的所有对象，并标记那些活着的对象，然后进入清除阶段。在清除阶段总，只清除没有被标记的对象</font>
+ <font style="color:rgb(51, 51, 51);">V8采取的是黑色和白色来标记数据，垃圾收集之前，会把所有的数据设置为白色，用来标记所有的尚未标记的对象，然后会从GC根出发，以深度优先的方式把所有的能访问到的数据都标记为黑色，遍历结束后黑色的就是活的数据，白色的就是可以清理的垃圾数据</font>
+ <font style="color:rgb(51, 51, 51);">由于标记清除只清除死亡对象，而死亡对象在老生代中占用的比例很小，所以效率较高</font>
+ <font style="color:rgb(51, 51, 51);">标记清除有一个问题就是进行一次标记清楚后，内存空间往往是不连续的，会出现很多的内存碎片。如果后续需要分配一个需要内存空间较多的对象时，如果所有的内存碎片都不够用，就会出现内存溢出的问题</font>

#### <font style="color:rgb(51, 51, 51);">Mark-Compact（标记整理）</font>
+ <font style="color:rgb(51, 51, 51);">标记整理正是为了解决标记清除所带来的内存碎片的问题</font>
+ <font style="color:rgb(51, 51, 51);">标记整理在标记清除的基础进行修改，将其的清除阶段变为紧缩极端</font>
+ <font style="color:rgb(51, 51, 51);">在整理的过程中，将活着的对象向内存区的一段移动，移动完成后直接清理掉边界外的内存</font>
+ <font style="color:rgb(51, 51, 51);">紧缩过程涉及对象的移动，所以效率并不是太好，但是能保证不会生成内存碎片，一般10次标记清理会伴随一次标记整理</font>

#### <font style="color:rgb(51, 51, 51);">Parallel(并行执行)</font>
+ <font style="color:rgb(51, 51, 51);">新生代的垃圾回收采取并行策略提升垃圾回收速度，它会开启多个辅助线程来执行新生代的垃圾回收工作</font>
+ <font style="color:rgb(51, 51, 51);">并行执行需要的时间等于所有的辅助线程时间的总和加上管理的时间</font>
+ <font style="color:rgb(51, 51, 51);">并行执行的时候也是全停顿的状态，主线程不能进行任何操作，只能等待辅助线程的完成</font>
+ <font style="color:rgb(51, 51, 51);">这个主要应用于新生代的垃圾回收</font>

```plain
         -------辅助线程----->
         -------辅助线程----->
         -------辅助线程----->
---------                    --------------------------->
```

#### <font style="color:rgb(51, 51, 51);">增量标记</font>
+ <font style="color:rgb(51, 51, 51);">老生代因为对象又大又多，所以垃圾回收的时间更长，采用增量标记的方式进行优化</font>
+ <font style="color:rgb(51, 51, 51);">增量标记就是把标记工作分成多个阶段，每个阶段都只标记一部分对象，和主线程的执行穿插进行</font>

## <font style="color:rgb(51, 51, 51);">什么是内存泄露</font>
+ <font style="color:rgb(51, 51, 51);">那当不再用到的对象内存没有及时被回收时，我们叫它内存泄漏</font>

## <font style="color:rgb(51, 51, 51);">不合理的闭包</font>
+ [<font style="color:rgb(51, 122, 183);">闭包</font>](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Closures)
+ <font style="color:rgb(51, 51, 51);">一个函数和对其周围状态(lexical environment,词法环境)的引用捆绑在一起这样的组合就是闭包（closure）</font>
+ <font style="color:rgb(51, 51, 51);">也就是说，闭包让你可以在一个内层函数中访问到其外层函数的作用域。在 JavaScript 中，每当创建一个函数，闭包就会在函数创建的同时被创建出来</font>
+ <font style="color:rgb(51, 51, 51);">词法(lexical)一词指的是，词法作用域根据源代码中声明变量的位置来确定该变量在何处可用。嵌套函数可访问声明于它们外部作用域的变量</font>

```javascript
function Person(){}
function fn(){
  let name = 'zhufeng';
  let age = 13;
  let arr = new Array();
  for(let i=0;i<10000;i++){
    arr.push(new Person());
  }
  return function(){
    console.log('hello',arr,name);
  }
}
let hello = fn();
debugger
hello();
```

## <font style="color:rgb(51, 51, 51);">Map、Set对象</font>
