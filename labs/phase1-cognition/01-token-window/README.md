# 01 — Token 与上下文窗口

对应文章：第 01 篇《从 Token 到上下文窗口：模型眼里的文字长什么样》

## 要验证什么

### 实验 A：token 计量对照

同一段医疗内容的中文版 / 英文版 / 对应代码片段，统计各自 token 数。

预期看到：中文 token 数 > 英文（同语义）；代码 token 密度最高。

### 实验 B：needle-in-a-haystack（大海捞针）

构造 5k / 20k / 80k 三段填充文本，在其中埋一条唯一事实（如「本批号药品的召回截止日是 X 月 X 日」），把这条事实分别放在**开头 / 中间 / 结尾**。

3 个长度 × 3 个位置 = 9 次调用，记录模型是否答对，做成一张 3×3 命中矩阵。

预期看到：**中间位置失败率显著高于两头；总长度越长，整体失败率越高。**

## 怎么跑

```bash
pnpm --filter @medai/labs token
```

## 看到什么算成功

- 一张 token 对照表（中文 / 英文 / 代码）
- 一张 9 格命中矩阵，中间列明显更差
- 你能用一句话解释「为什么 128K 窗口不等于 128K 有效注意力」

## 预算

9 次长文本调用（其中 80k 长上下文 3 次最贵），预计 ¥2-4。
