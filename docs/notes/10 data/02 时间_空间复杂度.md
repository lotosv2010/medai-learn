# <font style="color:rgb(51, 51, 51);">一、什么是复杂度分析 </font>
+ 数据结构和算法解决是 “如何让计算机更快时间、更省空间的解决问题”
+ 因此需从执行时间和占用空间两个维度来评估数据结构和算法的性能
+ 分别用时间复杂度和空间复杂度两个概念来描述性能问题，二者统称为复杂度
+ 复杂度描述的是算法执行时间（或占用空间）与数据规模的增长关系

# <font style="color:rgb(51, 51, 51);">二、为什么要进行复杂度分析 </font>
+ 和性能测试相比，复杂度分析有不依赖执行环境、成本低、效率高、易操作、指导性强的特点。
+ 掌握复杂度分析，将能编写出性能更优的代码，有利于降低系统开发和维护成本。

# <font style="color:rgb(51, 51, 51);">三、</font><font style="color:rgb(33, 37, 41);">复杂度的表示方式</font>
```javascript
T(n) = O(f(n)) 
S(n) = O(f(n)) 
```

+ <font style="color:rgb(33, 37, 41);">这个叫做</font>**<font style="color:#E8323C;">大O表示法</font>**<font style="color:rgb(33, 37, 41);">，其中</font>
    - <font style="color:rgb(33, 37, 41);">T 代表的是算法需要执行的总时间</font>
    - <font style="color:rgb(33, 37, 41);">S 表示的算法需要的总空间</font>
    - <font style="color:rgb(33, 37, 41);">f(n) 表示的是代码执行的总次数</font>
+ 举个例子

```javascript
function go(n) { 
  var item = 0;      // 这里执行了一次
  for (var i = 0; i < n; i++) {   //这里执行了N次
    for (var j = 0; j < n; j++) {     //这里执行了n*n次
      item = item + i + j;     //这里执行了n*n次
    }
  }
  return item;  //这里执行了一次
}
```

+ <font style="color:rgb(33, 37, 41);">所以说上边这段代码是 </font><font style="color:#E8323C;">1+n+n*n*2+1=2+n+2n²</font>
+ <font style="color:rgb(33, 37, 41);">也就是说 T(n) = O(f(2+n+2n²))</font>
+ <font style="color:rgb(33, 37, 41);">然后之前说了时间复杂度看的是一个代码执行的时间的趋势， 所以说在N，也就是规模比较大的时候，那些常量是起不到决定性的作用的，所以这个时候我们忽略这些常量，这里的例子是一个单段的代码，这里只看最大量级的循环就可以了</font>
+ <font style="color:rgb(33, 37, 41);">所以最后的这个代码的时间复杂度是T(n) = O(n²)，</font>这就是<font style="color:#E8323C;">大 O 时间复杂度表示法</font>，它不代表代码真正的执行时间，而是<font style="color:#E8323C;">表示代码随数据规模增长的变化趋势</font>，简称<font style="color:#E8323C;">时间复杂度</font>。

# <font style="color:rgb(51, 51, 51);">四、时间复杂度</font>
## 概述
+ <font style="color:rgb(51, 51, 51);">算法的时间复杂度，也就是算法的时间量度</font>
+ **<font style="color:rgb(51, 51, 51);">大 O 时间复杂度表示法</font>**<font style="color:rgb(51, 51, 51);"> 实际上并不具体表示代码真正的执行时间，而是表示 </font>**<font style="color:rgb(51, 51, 51);">代码执行时间随数据规模增长的变化趋势</font>**<font style="color:rgb(51, 51, 51);">，所以也叫 </font>**<font style="color:rgb(51, 51, 51);">渐进时间复杂度</font>**<font style="color:rgb(51, 51, 51);">，简称 </font>**<font style="color:rgb(51, 51, 51);">时间复杂度</font>**<font style="color:rgb(51, 51, 51);">（asymptotic time complexity）</font>
+ 这种时间复杂度表示法并不能真正反应一个算法的执行时间，反应的只是一个趋势，所以我们在分析复杂度的时候要关注“变”，忽略“不变”
+ 变指的是变量，也就是一段代码的执行时间是随着变量的变化而变化的，而不变指的是常量，也就是不论我的变量如何改变，执行时间都不会改变



+ **<font style="color:rgb(51, 51, 51);">例子1</font>**

```javascript
function aFun() {
  console.log("Hello, World!");      //  需要执行 1 次
  return 0;       // 需要执行 1 次
}
```

+ 那么这个方法需要执行 2 次运算



+ **例子 2**

```javascript
function bFun(n) {
  for(let i = 0; i < n; i++) {         // 需要执行 (n + 1) 次
    console.log("Hello, World!");      // 需要执行 n 次
  }
  return 0;       // 需要执行 1 次
}
```

+ 那么这个方法需要执行 ( n + 1 + n + 1 ) = 2n +2 次运算



+ **例子 3**

```javascript
function cal(n) {
  let sum = 0; // 1 次
  let i = 1; // 1 次
  let j = 1; // 1 次
  for (; i <= n; ++i) {  // n 次
    j = 1;  // n 次
    for (; j <= n; ++j) {  // n * n ，也即是  n平方次
      sum = sum +  i * j;  // n * n ，也即是  n平方次
    }
  }
 }
```

+ 注意，这里是二层 for 循环，所以第二层执行的是 n * n = n<font style="color:rgb(33, 37, 41);">²</font> 次，而且这里的循环是 ++i，和例子 2 的是 i++，是不同的，是先加与后加的区别
+ 那么这个方法需要执行 ( n<font style="color:rgb(33, 37, 41);">²</font> + n<font style="color:rgb(33, 37, 41);">²</font> + n + n + 1 + 1 +1 ) = 2n<font style="color:rgb(33, 37, 41);">²</font> +2n + 3 



+ **总结**
    - 以时间复杂度为例，由于 **时间复杂度** 描述的是算法执行时间与数据规模的 **增长变化趋势**，所以 **常量、低阶、系数** 实际上对这种增长趋势不产生决定性影响，所以在做时间复杂度分析时 **忽略** 这些项。
    - 所以，上面例子1 的时间复杂度为 T(n) = O(1)，例子2 的时间复杂度为 T(n) = O(n)，例子3 的时间复杂度为 T(n) = O(n<font style="color:rgb(33, 37, 41);">²</font>)。

## <font style="color:rgb(51, 51, 51);">时间复杂度分析</font>
### <font style="color:rgb(51, 51, 51);">只关注循环执行次数最多的一段代码</font>
+ 单段代码看高频：比如循环

```javascript
function cal(n) { 
   let sum = 0;
   let i = 1;
   for (; i <= n; ++i) {
     sum = sum + i;
   }
   return sum;
 }
```

+ 执行次数最多的是 for 循环及里面的代码，执行了 n 次，所以时间复杂度为 O(n)

### <font style="color:rgb(51, 51, 51);">加法法则</font>
+ **<font style="color:rgb(51, 51, 51);">总复杂度等于量级最大的那段代码的复杂度</font>**
+ 多段代码取最大：比如一段代码中有单循环和多重循环，那么取多重循环的复杂度

```javascript
function cal(n) {
   let sum_1 = 0;
   let p = 1;
   for (; p < 100; ++p) {
     sum_1 = sum_1 + p;
   }

   let sum_2 = 0;
   let q = 1;
   for (; q < n; ++q) {
     sum_2 = sum_2 + q;
   }
 
   let sum_3 = 0;
   let i = 1;
   let j = 1;
   for (; i <= n; ++i) {
     j = 1; 
     for (; j <= n; ++j) {
       sum_3 = sum_3 +  i * j;
     }
   }
 
   return sum_1 + sum_2 + sum_3;
 }
```

+ 上面代码分为三部分，分别求 sum_1、sum_2、sum_3 ，主要看循环部分
    - 第一部分，求 sum_1 ，明确知道执行了 100 次，而和 n 的规模无关，是个常量的执行时间，不能反映**增长变化趋势**，所以时间复杂度为 O(1)
    - 第二和第三部分，求 sum_2 和 sum_3 ，时间复杂度是和 n 的规模有关的，为别为 O(n) 和 O(n<font style="color:rgb(33, 37, 41);">²</font>)
+ 所以，取三段代码的最大量级，上面例子的最终的时间复杂度为 O(n<font style="color:rgb(33, 37, 41);">²</font>)
+ 同理类推，如果有 3 层 for 循环，那么时间复杂度为 O(n<sup><font style="color:rgb(33, 37, 41);">3</font></sup>)，4 层就是 O(n<sup>4</sup>)
+ 所以，**总的时间复杂度就等于量级最大的那段代码的时间复杂度**

### <font style="color:rgb(51, 51, 51);">乘法法则</font>
+ **<font style="color:rgb(51, 51, 51);">嵌套代码的复杂度等于嵌套内外代码复杂度的乘积</font>**
+ <font style="color:rgb(51, 51, 51);">嵌套代码求乘积：比如递归、多重循环等</font>

```javascript
function cal(n) {
   let ret = 0; 
   let i = 1;
   for (; i < n; ++i) {
     ret = ret + f(i); // 重点为  f(i)
   } 
 } 
 
function f(n) {
  let sum = 0;
  let i = 1;
  for (; i < n; ++i) {
    sum = sum + i;
  } 
  return sum;
 }
```

+ 方法 cal 循环里面调用 f 方法，而 f 方法里面也有循环
+ 所以，整个 cal() 函数的时间复杂度就是，T(n) = T1(n) * T2(n) = O(n*n) = O(n<font style="color:rgb(33, 37, 41);">²</font>) 

### <font style="color:rgb(51, 51, 51);">多个规模求加法</font>
+ **比如方法有两个参数控制两个循环的次数，那么这时就取二者复杂度相加**

```javascript
function cal(m, n) {
  let sum_1 = 0;
  let i = 1;
  for (; i < m; ++i) {
    sum_1 = sum_1 + i;
  }

  let sum_2 = 0;
  let j = 1;
  for (; j < n; ++j) {
    sum_2 = sum_2 + j;
  }

  return sum_1 + sum_2;
}
```

+ 以上代码也是求和 ，求 sum_1 的数据规模为 m、求 sum_2 的数据规模为 n，所以时间复杂度为 O(m+n)
+ 公式：T1(m) + T2(n) = O(f(m) + g(n)) 

### <font style="color:rgb(51, 51, 51);">多个规模求乘法</font>
+ **比如方法有两个参数控制两个循环的次数，那么这时就取二者复杂度相乘**

```javascript
function cal(m, n) {
  let sum_3 = 0;
   let i = 1;
   let j = 1;
   for (; i <= m; ++i) {
     j = 1; 
     for (; j <= n; ++j) {
       sum_3 = sum_3 +  i * j;
     }
   }
}
```

+ 以上代码也是求和，两层 for 循环 ，求 sum_3 的数据规模为 m 和 n，所以时间复杂度为 O(m*n)
+ 公式：T1(m) * T2(n) = O(f(m) * g(n)) 

## <font style="color:rgb(51, 51, 51);">常见的时间复杂度分析</font>
### <font style="color:rgb(51, 51, 51);">多项式阶</font>
+ 随着数据规模的增长，算法的执行时间和空间占用，按照多项式的比例增长。
+ 包括 O(1)（常数阶）、O(logn)（对数阶）、O(n)（线性阶）、O(nlogn)（线性对数阶）、O(n2) （平方阶）、O(n3)（立方阶）

#### O(1)（常数阶）
+ <font style="color:rgb(51, 51, 51);">O(1) 复杂度算法也称之为常数阶算法。这里的 </font><font style="color:rgb(255, 80, 44);background-color:rgb(255, 245, 245);">1</font><font style="color:rgb(51, 51, 51);"> 是用来代指常量，也就是说这个算法的效率是固定的，无论你的数据量如何变化，效率都一样，这种复杂度也是最优的一种算法。</font>

```javascript
function total() {
  var sum = 0;
  for(var i=0;i<100;i++) {
    sum += i;
  }
}
```

+ 虽然有这么多行，即使 for 循环执行了 100 次，但是代码的执行时间不随 n 的增大而增长，所以这样的代码复杂度就为 O(1)

#### O(logn)（对数阶）
+ <font style="color:rgb(255, 80, 44);background-color:rgb(255, 245, 245);">O(logn)</font><font style="color:rgb(51, 51, 51);"> 也称之为对数阶，对数阶也很常见，像二分查找，二叉树之类的问题中会见到比较多的对数阶复杂度，但是对数阶也是比较难理解的一种算法复杂度</font>

```javascript
function print(n){
  let i=1;
  while (i <= n) {
    i = i * 2;
  }
}
```

+ 代码是从 1 开始，每次循环就乘以 2，当大于 n 时，循环结束。
+ 其实就是高中学过的等比数列，i 的取值就是一个等比数列。在数学里面是这样子的：20 21 22 ... 2k ... 2x = n
+ 所以，我们只要知道 x 值是多少，就知道这行代码执行的次数了，通过 2x = n 求解 x，数学中求解得 x = log2n 。所以上面代码的时间复杂度为 O(log2n)。
+ 实际上，不管是以 2 为底、以 3 为底，还是以 10 为底，我们可以把所有对数阶的时间复杂度都记为 O(logn)。为什么呢？
+ 因为对数之间是可以互相转换的，log3n = log32 * log2n，所以 O(log3n) = O(C * log2n)，其中 C=log32 是一个常量。
+ 由于 **时间复杂度** 描述的是算法执行时间与数据规模的 **增长变化趋势**，所以 **常量、低阶、系数** 实际上对这种增长趋势不产生决定性影响，所以在做时间复杂度分析时 **忽略** 这些项。
+ 因此，**在对数阶时间复杂度的表示方法里，我们忽略对数的 “底”，统一表示为 O(logn)**。

#### O(nlogn)（线性对数阶）
+ 只需要在对数阶的算法中再嵌一层循环就是线性对数阶

```javascript
function aFun(n){
  let i = 1;
  while (i <= n)  {
     i = i * 2;
  }
  return i
}

function cal(n) { 
   let sum = 0;
   for (let i = 1; i <= n; ++i) {
     sum = sum + aFun(n);
   }
   return sum;
 }
```

+ aFun 的时间复杂度为 O(logn)，而 cal 的时间复杂度为 O(n)，所以上面代码的时间复杂度为 T(n) = T1(logn) * T2(n) = O(logn*n) = O(nlogn) 

#### O(n)（线性阶）
+ <font style="color:rgb(255, 80, 44);background-color:rgb(255, 245, 245);">O(n)</font><font style="color:rgb(51, 51, 51);"> 复杂度算法也称之为线性阶</font>

```javascript
function print(n){
  let a = 0;
  for (let i=0;i<n;i++){
    console.log(i);
  }
}
```

+ 前面常量阶没分析是因为常量阶比较容易理解，接下来我们就以线性阶这个为例子来分析下具体是怎么得到的
+ 我们假设每一行代码的执行时间是 T，那么上面这段代码的执行复杂度是多少呢？
+ 答案很明显，那就是 T+n*T，也就是 (n+1)T，而在算法中有一个原则，那就是常量可以被忽略，所以就得到了 nT，换成大 O 表示法就是 O(n)
+ 这只是一个简略的计算过程，大家也不用较真说每行代码执行时间可能不一样之类的，也不要较真说 for 循环占用了一行，下面的大括号也占用了一行，如果要较真这个，那我建议可以去想一下 1=1 为什么等于 2
+ 算法中的复杂度反应的只是一个趋势，这里 O(n) 反应的就是一个趋势，也就是随着 n 的变化，算法的执行时间是会降低的

#### O(n2) （平方阶）
+ <font style="color:rgb(51, 51, 51);">知道了上面的线性阶，那么平方阶就很好理解了，</font><font style="color:#E8323C;">双层循环</font><font style="color:rgb(51, 51, 51);">就是平方阶</font>

```javascript
function go(i) {
  var sum = 0;
  for (var j = 0; j < i; j++) {
    sum += i;
  }
  return sum;
}
function main(n) {
  var res = 0;
  for (var i = 0; i < n; i++) {
    res = res + go(i); // 这里是重点
  }
}
```

#### O(n3)（立方阶）
+ <font style="color:rgb(51, 51, 51);">同理，</font><font style="color:#E8323C;">三次循环</font><font style="color:rgb(51, 51, 51);">就是立方阶，</font><font style="color:#E8323C;background-color:rgb(255, 245, 245);">k</font><font style="color:#E8323C;"> 次循环</font><font style="color:rgb(51, 51, 51);">就是 </font><font style="color:rgb(255, 80, 44);background-color:rgb(255, 245, 245);">k</font><font style="color:rgb(51, 51, 51);"> 次方阶</font>

### <font style="color:rgb(51, 51, 51);">非多项式阶</font>
+ 随着数据规模的增长，算法的执行时间和空间占用暴增，这类算法性能极差。
+ 包括 O(2<sup>n</sup>)（指数阶）、O(n!)（阶乘阶）

#### O(2n)（指数阶）
```javascript
function fibonacci( n ) {
  if (n <= 1) {
    return 1;
  } else {
    return aFunc(n - 1) + aFunc(n - 2);
  }
}
```

+ 显然运行次数，T(0) = T(1) = 1，同时 T(n) = T(n - 1) + T(n - 2) + 1，这里的 1 是其中的加法算一次执行。 显然 T(n) = T(n - 1) + T(n - 2) 是一个斐波那契数列(<font style="color:rgb(51, 51, 51);">Fibonacci sequence</font>)，通过归纳证明法可以证明，当 n >= 1 时 T(n) < (5/3)<sup>n</sup>，同时当 n > 4 时 T(n) >= (3/2)<sup>n</sup>。 所以该方法的时间复杂度可以表示为 O((5/3)<sup>n</sup>)，简化后为 O(2<sup>n</sup>)。 可见这个方法所需的运行时间是以指数的速度增长的。 如果大家感兴趣，可以试下分别用 1，10，100 的输入大小来测试下算法的运行时间，相信大家会感受到时间复杂度的无穷魅力



#### O(n!)（阶乘阶）
```javascript
function factorial(){
  if(num <= 1){
    return 1;
  }else{
    return num * factorial(num - 1);
  }
}
```

+ 阶乘型O(n!)的时间复杂度按照(n!+(n-1)!+(n-2)!+ ··· + 1) +((n-1)!+(n-2)!+ ··· + 1)+ ··· 的方式去计算
+ 注意，这里是多个阶乘的和，不仅仅是n * (n-1) * (n-2) * (n-3)···1
+ 假设n从0到10，它的算法复杂度O(n!)依次为1，4，15，64，325，1956，13699，109600，986409，9864100··· 
+ 为了和上文中的其它算法复杂度做比较，n为100时是多少呢？ 
+ **O(2**<sup>**n**</sup>**)为10才是1024，n为100时O(2**<sup>**n**</sup>**)直接浏览器卡死了。 O(n!)才为10就接近1000万了，真要是n设置成100，计算到机器烧了也计算不出吧**
+ 所以n为100时的O(n!)就不要想了，庞大到恐怖的一个数字

### 总结
+ **<font style="color:#E8323C;">O(1) < O(logn) < O(n) < O(nlogn) < O(n2) < O(n3) < O(2n) < O(n!) < O(nn)</font>**

| **操作数量实例** | **大O表示法** | **术语** |
| --- | --- | --- |
| 15 | **O(1)** | 常数阶 |
| 3logn | **O(logn)** | 对数阶 |
| 3n+5 | **O(n)** | 线性阶 |
| 4nlogn | **O(nlogn)** | 线性对数阶 |
| 5n<sup>2</sup>+3N+1 | **O(**n<sup>2</sup>**)** | 平方阶 |
| 6n<sup>3</sup>+4N+2 | **O(**n<sup>3</sup>**)** | 立方阶 |
| 2<sup>n</sup>+1<sup> </sup> | **O(**2<sup>n</sup>**)** | 指数阶 |
| n!+1 | **O(**n!**)** | 阶乘阶 |


+ 当数据规模 n 增长时，**非多项式量级**的执行时间就会急剧增加，所以，**非多项式量级**的代码算法是非常低效的算法

## <font style="color:rgb(51, 51, 51);">时间复杂度类型</font>
```javascript
// n 表示数组 array 的长度
function find(array, n, x) {
  let i = 0;
  let pos = -1;
  for (; i < n; ++i) {
    if (array[i] == x) {
      pos = i; 
      break;
    }
  }
  return pos;
}
```

### 最好情况时间复杂度（best case time complexity）
+ 在最理想的情况下，执行这段代码的时间复杂度
+ 上面例子中，如果数组中第一个值就等于 x，那么时间复杂度为 O(1)，如果数组中不存在变量 x，那我们就需要把整个数组都遍历一遍，时间复杂度就成了 O(n)。所以，不同的情况下，这段代码的时间复杂度是不一样的。
+ 所以上面代码的 <font style="color:#E8323C;">最好情况时间复杂度为 O(1)</font>

### 最坏情况时间复杂度（worst case time complexity）
+ 在最糟糕的情况下，执行这段代码的时间复杂度
+ 上面例子中，<font style="color:rgb(51, 51, 51);">理解了最好时间复杂度，那么最坏时间复杂度也很好理解了，那就是数组中不存在我要找到元素，或者说最后一个值才是我要找的元素，那么这样我就必须循环完整个数组，那么时间复杂度就是 </font><font style="color:rgb(255, 80, 44);background-color:rgb(255, 245, 245);">O(n)</font><font style="color:rgb(51, 51, 51);">，这也就是</font><font style="color:#E8323C;">最坏时间复杂度为 O(n)</font>

### 均摊时间复杂度（amortized time complexity）
+ 在代码执行的所有复杂度情况中绝大部分是低级别的复杂度，个别情况是高级别复杂度且发生具有时序关系时，可以将个别高级别复杂度均摊到低级别复杂度上
+ 基本上均摊结果就等于低级别复杂度
+ <font style="color:rgb(51, 51, 51);">均摊时间复杂度就是一种特殊的平均时间复杂度 (应用场景非常特殊，非常有限，这里不说)</font>

# <font style="color:rgb(51, 51, 51);">五、空间复杂度</font>
## 概述
+ <font style="color:rgb(51, 51, 51);">空间复杂度全称就是 </font>**<font style="color:rgb(51, 51, 51);">渐进空间复杂度</font>**<font style="color:rgb(51, 51, 51);">（asymptotic space complexity），表示 </font>**<font style="color:rgb(51, 51, 51);">算法的存储空间与数据规模之间的增长关系</font>**<font style="color:rgb(51, 51, 51);"> 。</font>
+ <font style="color:rgb(51, 51, 51);">定义：算法的空间复杂度通过计算算法所需的存储空间实现，算法的空间复杂度的计算公式记作：</font>**<font style="color:rgb(51, 51, 51);">S(n) = O(f(n))</font>**<font style="color:rgb(51, 51, 51);">，其中，n 为问题的规模，f(n) 为语句关于 n 所占存储空间的函数。</font>

```javascript
function print(n) {
 const newArr = []; // 第 2 行
 newArr.length = n; // 第 3 行
  for (let i = 0; i <n; ++i) {
    newArr[i] = i * i;
  }

  for (let j = n-1; j >= 0; --j) {
    console.log(newArr[i])
  }
}
```

+ 跟时间复杂度分析一样，我们可以看到，第 2 行代码中，我们申请了一个空间存储变量 newArr ，是个空数组。第 3 行把 newArr 的长度修改为 n 的长度的数组，每项的值为 undefined ，除此之外，剩下的代码都没有占用更多的空间，所以整段代码的空间复杂度就是 O(n)

# 七、总结
+ **<font style="color:#E8323C;">复杂度</font>**也叫**<font style="color:#E8323C;">渐进复杂度</font>**，包括**<font style="color:#E8323C;">时间复杂度和空间复杂度</font>**，一个表示执行的快慢，一个表示内存的消耗，用来分析算法执行效率与数据规模之间的增长关系，可以粗略的表示，越高阶复杂度的算法，执行效率越低。
