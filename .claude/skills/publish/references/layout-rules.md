# 排版铁律 & 公众号兼容性

## 标题层级（最容易出错的地方）

公众号是内容消费场景，**绝对不要用数字编号标题**（1. / 1.1 / 1.1.1 / 一、/ （一）），那是技术文档和教材的风格，读者体验差。

严格遵守以下三层视觉层级，**不得出现第四层**：

```
# 文章标题         ← 全文唯一，只用一次
## 主章节标题      ← emoji 前缀 + 标题，是文章骨架
### 子话题标题     ← 无 emoji，章节内细分
**加粗小标题**     ← 替代 ####，段落内的微标题，不占独立行级
```

决策规则：
- 需要独立成章、有实质内容的 → 用 `##`
- 章节内有 2 个以上并列子话题 → 用 `###`
- 只是一段话的引导词、或列表的前置说明 → 用 `**加粗**`，不升级为标题
- 永远不用 `####` 及更深层级

**错误示例**（目录混乱的根源）：
```markdown
## Promise
### Promise 的状态
#### Pending 状态    ← ❌ 第四层，改用加粗
#### Fulfilled 状态  ← ❌ 第四层，改用加粗
### Promise 的方法
#### then            ← ❌ 第四层，改用加粗
```

**正确示例**：
```markdown
## ⚡ Promise：状态机 + 链式调用

Promise 是一个有限状态机，三个状态：

**Pending**：初始态，等待决议
**Fulfilled**：成功态，有不可变的 value
**Rejected**：失败态，有不可变的 reason

### then 的链式调用原理

{内容...}
```

## 结构节奏

- 每段 **不超过 4 行**（移动端一屏）
- 每 200-300 字有一个**视觉锚点**（`##`/`###` 标题 / 表格 / 代码 / 引用块）
- 章节间用 `---` 分隔（公众号识别为分割线）

---

## 文字风格

- 用「你」不用「我们」——对话感
- 开头 3 句话内制造冲突或悬念，最好带面试场景
- 「是什么 → 怎么工作 → 为什么」的递进藏在叙事里，别写成教科书
- **关键结论加粗**，一段最多加粗 1 处

---

## 代码块规范

- 必须带语言标记（` ```typescript ` / ` ```javascript `）
- 单块 **不超过 15 行**（超了就拆分成多块 + 文字衔接，**不能删代码**）
- 代码前后各一句话说明「这段要展示什么」
- 关键行用 `// 👈 注意这里` 标注
- 笔记里的超长代码（如完整手写 Promise）要**完整保留**，拆成多个代码块分段展示，每段加说明句衔接

---

## 视觉与面试元素

- emoji **只用在 `##` 主章节标题前**，`###` 子标题不加 emoji，每篇不超过 6 种
- `> 引用块` 专门用来做「💬 面试官视角」和「划重点」
- 对比类知识用**表格**
- 列表用 `-` 而非 `1.`（公众号有序列表渲染不稳定）

---

## 公众号 Markdown 兼容性速查

公众号本身不支持 Markdown，需经第三方工具（mdnice.com、Markdown Nice、墨滴）渲染后粘贴。以下元素确保兼容：

| 元素 | 支持 | 注意 |
|------|------|------|
| `#`~`###` 标题 | ✅ | 最多用到 h3 |
| `**加粗**` / `` `行内代码` `` | ✅ | |
| 代码块 | ✅ | 带语言标记 |
| `> 引用` / `---` 分割线 | ✅ | |
| 表格 | ✅ | 列数 ≤ 4 |
| 无序列表 | ✅ | 最多 2 层 |
| 有序列表 | ⚠️ | 序号可能丢失 |
| 图片 `![]()` | ⚠️ | 需上传素材库 |
| 超链接 `[]()` / `<details>` / 脚注 | ❌ | 一律不用 |

> 不用 `[文字](url)` 外链 → 改为「搜索关键词：XXX」；不用 HTML 标签；嵌套列表不超过 2 层。
