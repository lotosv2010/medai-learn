## 各篇详细大纲

### 第 00 篇：大模型到底是什么：一次 API 调用背后发生了什么

**副标题**：它不是搜索引擎，不是数据库，也不是推理引擎——它是一台「算下一个词」的概率机器

**学习目标**：能向同事解释清楚大模型为什么会产生幻觉、为什么它不"查"知识；能画出预训练 → SFT → RLHF 的三阶段地图

**前置准备**：任选一家 API key（推荐 DeepSeek / 通义千问，成本最低）；`pnpm install`；预计花费 < ¥1

> 本篇是导读，承担全阶段最关键的认知纠偏，采用「认知驱动」骨架，实验段保留。

#### 一、认知切入：三个几乎所有人都踩过的误判

- 把大模型当搜索引擎用："问它一个药的最新说明书内容"，它答得很像真的，但可能整段是编的
- 把大模型当数据库用："让它记住我们医院的用药规范"，下一轮对话它就忘了
- 把大模型当推理引擎用："帮我算这个患者按体重折算的儿童剂量"，它能算对简单题，但复杂多步会一本正经地错

三个误判的根是同一个：**误以为模型在"取回"信息，其实它在"续写"文本。**

#### 二、原理讲透：概率续写机器

- 自回归生成：给定前文，输出**下一个 token 的概率分布**，采样一个，接上，再算下一个——重复到结束标记
- 为什么这必然产生幻觉：模型的目标函数是"像人写的文本"，不是"说真话"；当真实信息不在参数里时，"最像真的"续写就是编造，而编造在概率上优于说"我不知道"
- 为什么它"没有记忆"：每次调用都是无状态的；你感觉它有记忆，是因为**你把历史消息又重新拼进了上下文**（这一点到阶段三才展开）
- **训练全景地图**（只到能画出来为止，不碰损失函数与数据工程）：
  - 预训练（Pre-training）：海量文本上学"下一个词"，得到基座模型，知识截止日就定在这批数据的截止时间
  - SFT（监督微调）：用「指令-回答」对教它听话、按格式回答
  - RLHF / DPO（对齐）：用人类偏好打分让它更有用、更少有害
  - 一句话记忆钩子：**预训练给知识，SFT 给格式，RLHF 给脾气**
- 推理 vs 训练、开源 vs 闭源的边界认知：我们只做「推理」侧的调用者，不做训练侧的研究者

#### 三、动手实验：看见 token 用量

- 项目：`labs/phase1-cognition/00-hello-llm/`
- 要做的事：同一个医疗问题（如「阿莫西林胶囊的常见不良反应有哪些」）分别问 DeepSeek / 通义千问 / 一家备选，**打印完整原始响应 JSON**
- 要看见的三件事：
  1. 返回结构长什么样：`choices[0].message.content` 是人读的文本，其余都是元数据
  2. `usage.prompt_tokens` / `completion_tokens` / `total_tokens`——这就是账单的计量单位（下一篇展开）
  3. 三家对同一问题的回答措辞不同，但**结构高度相似**——因为它们在学同一件事：最可能的续写
- 关键结论：**你付费买的是 token 数，不是"答案"；你拿到的是文本，不是"事实"**
- 脚本要求：启动先打印「本脚本约消耗 X token / ¥Y」，缺 key 时给出明确提示而不是抛栈

#### 四、结论与边界

- 本篇结论：大模型 = 概率续写机器 + 三阶段训练的产物；它的一切局限都能从这个定义推出来
- 明确留到后面：
  - Token 具体怎么切、为什么中文更贵 → 第 01 篇
  - 幻觉为什么不可避免、怎么降低 → 第 02 篇
  - 温度这些参数怎么影响"最可能" → 第 03 篇
  - 上下文怎么编排、怎么缓存 → 阶段三（Prompt/Context 四层框架见已发布《从 Prompt Engineering 到 Loop Engineering》）

#### 五、面试核心问

- 为什么大模型会一本正经地胡说八道？（从目标函数答，而不是"训练数据不够"）
- 预训练 / SFT / RLHF 各自解决什么问题？少一个会怎样？
- 大模型有记忆吗？多轮对话的"记忆"是怎么来的？
- 知识截止（Knowledge Cutoff）是怎么产生的？怎么绕过？

**产出物**：一个能跑通三家模型调用、并打印 token 用量的实验目录

### 第 01 篇：从 Token 到上下文窗口：模型眼里的文字长什么样

**副标题**：128K 的窗口，真正好用的可能只有一半——而且中文比英文贵

**学习目标**：会估算 token 与成本；能解释为什么长上下文不是免费的，能说清 Lost in the Middle 的成因

**前置准备**：同 00 篇；需要能读 5k / 20k / 80k 的长文本（可脚本生成）；预计花费 ¥2-4

#### 一、认知切入：一份药品说明书为什么"塞得进去却读不出来"

- 现象：把 80 页说明书整份丢给模型问"禁忌人群有哪些"，回答漏了明确写着的一条
- 直觉解释："窗口有 200K，塞进去不就行了？"——这一篇要拆掉这个直觉

#### 二、原理讲透：Token、窗口与注意力

- **Tokenizer 的本质**：文本 → 子词（subword）→ 整数 ID。BPE 的直觉是"常见组合合并成一个 token"
- **中文为什么更贵**：主流 tokenizer 以英文语料为主训练，一个汉字常占 1-2 个 token，而一个英文单词常只占 1 个；同样的语义，中文 prompt 的 token 数常是英文的 1.5-2 倍
- **计费公式**：成本 = 输入 token × 输入单价 + 输出 token × 输出单价（输出单价通常贵 3-5 倍，这一点决定了"让它少说废话"就是省钱）
- **上下文窗口**：一次调用能容纳的最大 token 数（输入 + 输出共享）
- **注意力稀释（Lost in the Middle）的物理成因**：
  - Transformer 的注意力要在一段长序列里分配"关注预算"，位置靠中间的内容获得的关注显著低于开头与结尾
  - 这是现象层面的解释，**不做数学推导**（路线图原则：原理够用即止）
  - 推论：长上下文 ≠ 有效上下文；关键信息应放头尾
- 边界声明：**"所以该怎么排布、怎么分配预算、前缀缓存怎么配"属于上下文工程，留到阶段三**。本篇只讲清"为什么会这样"

#### 三、动手实验：两次量化

- 项目：`labs/phase1-cognition/01-token-window/`
- 实验 A：token 计量对照
  - 同一段医疗内容的中文版 / 英文版 / 对应代码片段，用 tokenizer 统计 token 数，做成一张对照表
  - 要看见：中文 token 数 > 英文；代码的 token 密度最高
- 实验 B：needle-in-a-haystack（大海捞针）
  - 构造一段 5k / 20k / 80k 的填充文本，在其中埋一条唯一事实（如"本批号药品的召回截止日是 X 月 X 日"），把这条分别放在**开头 / 中间 / 结尾**
  - 三个长度 × 三个位置 = 9 次调用，记录模型是否答对
  - 要看见：中间位置的失败率显著高于两头；长度越长，整体失败率越高
- 关键结论：**"塞进去"和"读到"是两件事；上下文窗口是预算，不是保险柜**

#### 四、结论与边界

- 本篇结论：Token 是计量与计费单位；窗口是硬上限；有效注意力远小于标称窗口
- 明确留到后面：
  - 怎么在这点预算里编排内容（配额、顺序、压缩）→ 阶段三
  - 检索替代长上下文（RAG 为什么存在）→ 阶段四

#### 五、面试核心问

- Token 是什么？中文和英文同样的语义，token 数一样吗？
- 为什么上下文窗口有限？扩大窗口的代价是什么？
- 什么是 Lost in the Middle？工程上怎么规避？
- 输入 token 和输出 token 哪个贵？这对产品设计有什么影响？

**产出物**：token 对照表 + 9 格 needle 命中矩阵

### 第 02 篇：能力边界：幻觉、知识截止与「它不知道自己不知道」

**副标题**：幻觉不是 bug 是特性——医疗场景最大的风险就在这里

**学习目标**：知道幻觉与知识截止的触发条件与规避手段；能判断一个需求"能不能靠模型本身解决"

**前置准备**：同前；预计花费 ¥1-2

#### 一、认知切入：一个真实会出事的问题

- "某药品的儿童剂量怎么调整？"——模型给的数字看起来专业、格式规范，但可能整段编造
- 医疗场景的特殊性：**幻觉在这里不是体验问题，是安全问题**

#### 二、原理讲透：三类边界

- **幻觉（Hallucination）**
  - 成因：从 00 篇的目标函数推出——它优化"像真的"，不优化"是真的"
  - 两种形态：事实性幻觉（编了个不存在的文献）与忠实性幻觉（给了参考资料，但回答偏离了资料）
  - 降低手段的分层：Prompt 约束（"不知道就说不知道"）→ 提供参考资料 → 工具调用核验 → RAG（阶段四）→ 人工复核
  - **重要认知：没有任何手段能根除幻觉，只能把概率压低到可接受**
- **知识截止（Knowledge Cutoff）**
  - 成因：预训练数据有截止日；SFT/RLHF 不会补新知识
  - 表现：它不知道自己的知识过时了，仍会用旧知识自信作答
  - 规避：需要时效性的问题必须走检索/工具，不能靠模型记忆
- **它不知道自己不知道**
  - 模型的置信度不是校准过的概率；"语气自信"和"答案正确"没有相关性
  - 这就是为什么医疗场景必须有人机协作与兜底（阶段五展开）

#### 三、动手实验：三种问法的对照

- 项目：`labs/phase1-cognition/02-boundary/`
- 选 3 个"模型大概率不知道"的问题（编造的药品批号、未来的政策、极冷门的剂量细节）
- 每个问题用三种问法各问一次：
  1. 裸问（直接问）
  2. 加约束（"如果不确定，请直接说不知道，不要编造"）
  3. 给资料（附一段真实说明书段落，让模型只依据资料回答）
- 记录：三次回答里，哪次编了、哪次说了不知道、哪次答对了
- 要看见：裸问最容易编；加约束能明显减少编造但不彻底；给资料后准确率最高，但会出现"忠实性幻觉"（资料里有，它答偏了）
- 关键结论：**Prompt 只能缓解，资料注入才是根本；而资料注入就是 RAG 的动机**

#### 四、结论与边界

- 本篇结论：幻觉/截止/过度自信是同一件事的三个侧面；医疗场景必须"不靠模型记忆"
- 明确留到后面：
  - 怎么把外部知识注入 → 阶段四 RAG
  - 怎么用工具核验 → 阶段五 Agent
  - 怎么度量"幻觉率有没有下降"→ 阶段九评估

#### 五、面试核心问

- 幻觉的成因是什么？能彻底解决吗？
- 知识截止怎么处理？为什么"提示它注意时效"没用？
- Prompt 约束"不知道就说不知道"为什么只能缓解？

### 第 03 篇：采样参数与推理模型：temperature 到底在调什么

**副标题**：它调的不是"创造力"，是"从概率分布里怎么抽签"

**学习目标**：会按任务调 temperature / Top-p；知道什么时候该用推理模型、什么时候是浪费钱

**前置准备**：需要一家支持参数调节的 API + 一个推理模型（DeepSeek-R1 或同类）；预计花费 ¥2-3

#### 一、认知切入：同一个问题，两次答案不一样

- 现象：查药品剂量，问两次得到两个略有差异的答案——这在医疗场景是致命的
- 直觉解释："模型不稳定"，其实是采样参数在起作用

#### 二、原理讲透：从概率分布到具体那个词

- **temperature**：把概率分布"压平"或"削尖"。低温度 → 高概率词几乎必选（稳定、可复现）；高温度 → 低概率词也有机会（多样、易跑偏）
- **Top-p（核采样）**：只从累计概率达到 p 的最小词集合里抽
- **Top-k**：只从概率最高的 k 个词里抽
- 三者的关系（易混淆点）：temperature 改**分布的形状**，Top-p / Top-k 改**候选集的范围**，可以叠加使用
- **任务与参数的对应**（这是本篇最实用的一张表）：
  - 事实问答 / 结构化输出 / 抽取 → temperature 0~0.2
  - 客服对话 / 文案 → 0.5~0.7
  - 创意发散 / 起标题 → 0.8~1.0
  - 医疗场景默认压到最低档，**用确定性换可复现**
- **注意**：temperature=0 也不保证完全确定（浮点与并发实现差异），"完全可复现"要靠日志与评估兜底（阶段九）
- **推理模型（o1 / R1 类）**
  - 它不是"更聪明的普通模型"，是"回答前先写草稿"的模型：先产生大量隐藏的推理 token，再给答案
  - 代价：慢、贵（推理 token 也计费）、不适合简单任务
  - 判断标准：多步逻辑 / 数学 / 复杂权衡用它；简单问答/抽取用它就是浪费

#### 三、动手实验：两次对照

- 项目：`labs/phase1-cognition/03-params/`
- 实验 A：temperature 扫描
  - 固定一个 prompt（如"给这款药写一条 30 字以内的用药提醒"），temperature 取 0 / 0.3 / 0.7 / 1.0，每档跑 5 次
  - 记录 20 条输出，看重复率与偏离程度；做成一张"档位 × 输出差异"的表
  - 要看见：0 档几乎完全一致；1.0 档偶尔出现事实偏移
- 实验 B：普通模型 vs 推理模型
  - 一道多步医学计算题（如"按体重折算儿童剂量，并判断是否超过成人上限"），两个模型各跑一次
  - 记录：正确率、耗时、思考 token 数、总成本
  - 要看见：推理模型答对但贵好几倍；简单题上两者无差别
- 关键结论：**参数是成本与稳定性的旋钮，不是"智能程度"的旋钮**

#### 四、结论与边界

- 本篇结论：理解采样 = 理解了"为什么同一个模型会有不同表现"
- 明确留到后面：
  - 怎么让输出稳定成可解析的数据结构 → 阶段二结构化输出
  - 怎么量化"改参数后效果变好还是变坏"→ 阶段九评估

#### 五、面试核心问

- temperature / Top-p / Top-k 分别调什么？有什么区别？
- temperature=0 就完全确定吗？为什么？
- 推理模型和普通模型的本质区别是什么？什么时候不该用它？
- 医疗问答你会怎么设参数？为什么？

**产出物**：参数-输出差异表 + 普通/推理模型对比表

### 第 04 篇：模型图谱与选型：把成本算清楚（阶段一收官）

**副标题**：不是选"最强的模型"，是选"刚好够用且算得起的那一个"

**学习目标**：能按任务选型并给出成本依据；产出阶段一的核心成果物「模型选型 + 成本估算备忘录」

**前置准备**：无需新 key；预计花费 ¥0（纯计算）

#### 一、认知切入：一个上线前才被发现的问题

- 原型阶段用最强模型很爽，上线后日均 1000 次问诊，月账单远超预算
- 选型不是技术偏好题，是**成本 × 能力 × 合规**的三维权衡

#### 二、原理讲透：模型图谱与选型框架

- **四类模型的分野**：
  - 闭源旗舰（Claude / GPT 系列）：能力上限最高、最贵、数据出境需评估
  - 国产商用（通义 / DeepSeek / 文心等）：价格低、境内合规友好、长文本与中文表现好
  - 开源可自部署（Qwen / Llama 等）：数据不出内网、需自己扛推理成本与运维（阶段八）
  - 推理专用（o1 / R1 类）：只用于复杂推理
- **选型的四个判断维度**（本篇给一张决策表）：
  1. 任务复杂度：简单抽取 / 复杂推理 → 决定要不要推理模型
  2. 上下文长度：长文档理解 vs 短问答 → 决定窗口需求
  3. 合规与数据出境：医疗数据 → 优先境内模型或私有化
  4. 成本：按"日均调用量 × 平均 token"算月成本，而不是看单价高低
- **模型路由的动机**（了解即可，实现留到阶段二）：简单任务走小模型，复杂任务走大模型，同一套接口下按任务分流
- **成本估算的方法**：把单价换算成"每次问诊成本"，再乘日均量 × 30，得到可比较的月账单

#### 三、动手实验：写一个成本估算器

- 项目：`labs/phase1-cognition/04-cost/`
- 输入参数：日均调用量 1000 次 / 平均输入 800 token / 平均输出 300 token
- 输出：一张表，列出 5 个候选模型（含 1 个推理模型作对照）的「每次成本 / 日成本 / 月成本」
- 再算第二组：加入模型路由（70% 简单任务走小模型 + 30% 复杂任务走大模型），对比省了多少钱
- 要看见：**单价差 10 倍的模型，月成本可能差一个数量级；而路由能再省一半以上**
- 关键结论：**成本是设计出来的，不是省出来的**

#### 四、结论与边界

- 本篇结论：选型的答案永远是"具体任务的具体权衡"，没有普适最优模型
- 阶段一总结：到这里你已经能回答路线图阶段一的两条里程碑——"为什么胡说八道"与"该选哪个模型"
- 明确留到后面：选型落地成可切换的代码 → 阶段二（多模型抽象）；本地部署开源模型 → 阶段八
- **成果物交付**：把本篇的实验结果整理成「模型选型 + 成本估算备忘录」，作为用药咨询助手的第一份技术决策文档，落到 `docs/articles/00 AI/01 认知地基/`

#### 五、面试核心问

- 给你一个医疗问答需求，你怎么选模型？考虑哪几个维度？
- 日均 1 万次调用，你怎么把成本压下来？（路由 / 缓存 / 上下文精简 / 分级）
- 为什么医疗场景常优先国产模型或私有化部署？
- 什么时候该用推理模型？什么时候用它是浪费？
