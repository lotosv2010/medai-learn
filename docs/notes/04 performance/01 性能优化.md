## 构建效率优化

### 慢在哪里？

- speed-measure-webpack-plugin：用来分析构建时间
- webpack-bundle-analyzer：分析构建后文件的大小、文件的依赖关系

### 问题

#### 本地启动慢

- 了解完整的构建过程：如webpack（start -> 入口文件 -> 解析配置 -> 依赖解析 -> loader转换 -> 构建模块图 -> 生成chunk -> 优化处理 -> 生成产物 -> 写入 dist）

- 解决思路：启动缓存、减少启动时的全局工作、较少的loader和plugin处理、替换更快的编译器如SWC替换babel

#### 热更新慢

- barrel file 问题

## 资源加载优化

### 浏览器加载页面的过程

URL输入
  ↓
① DNS 解析          medai.com → 123.45.67.89
  ↓
② TCP + TLS 握手     建立安全信道（HTTPS 多一次 RTT）
  ↓
③ HTTP 请求/响应     服务器返回 HTML 字节流
  ↓
④ HTML 解析          字节 → Token → DOM Tree
   └─ 遇到 `<link CSS>`  → 暂停渲染，下载并解析 CSS → CSSOM Tree
   └─ 遇到 `<script>`    → 暂停 HTML 解析，执行 JS（除非 defer/async）
  ↓
⑤ Render Tree        DOM + CSSOM 合并（display:none 节点被剔除）
  ↓
⑥ Layout（Reflow）   计算每个节点的几何信息（位置+尺寸）
  ↓
⑦ Paint + Composite  像素绘制 → 图层合成 → GPU 上屏

关键节点时序：

|---DNS---|--TCP--|--请求--|--HTML解析--|--CSS--|--JS--|--Layout--|--Paint--|
          ^                ^                                      ^         ^
          TTFB        FCP可能触发                               LCP        TTI

## 完整线路图

性能优化
├── 0. 开发阶段
│   ├── 构建工具优化 & Bundle 分析
│   ├── 依赖管理（替换重型库）
│   ├── 架构决策（渲染策略 / Islands / RSC）
│   └── React Compiler / 自动 memo
│
├── 1. 度量
│   ├── Core Web Vitals（LCP / CLS / INP）
│   ├── 性能预算（Performance Budget）
│  ├── RUM 真实用户监控
│   └── 日志 & 错误追踪
│
├── 2. 网络层
│   ├── DNS 预解析 / 预连接
│   ├── HTTP/2/ HTTP/3 + QUIC
│   ├── CDN / Edge 计算
│   └── 缓存策略（HTTP Cache / Service Worker）
│
├── 3. 加载性能
│   ├── Bundle 优化（Code Split / 懒加载 / Tree Shaking）
│   ├── 资源优化（WebP/AVIF / 字体裁剪）
│   └── 预加载（preload / prefetch / modulepreload）
│
├── 4. 渲染性能
│   ├── 关键渲染路径（消除 CSS/JS 阻塞）
│   ├── React 渲染优化（memo / 虚拟列表）
│   ├──减少重排重绘
│   └── SSR / Streaming / PPR
│
├── 5.运行时性能
│   ├── JS 任务拆分（scheduler / Web Worker）
│   ├── 内存管理
│   └── 运行时缓存（SWR / React Query）
│
└── 6. 感知性能
    ├── Skeleton / Optimistic UI
    ├── 流式渲染（Streaming SSR）
    └── 动画流畅度（FLIP / 60fps）

核心逻辑：架构决策 →构建期消灭 → 网络层提速 →加载期减量 →渲染期提效 → 运行时稳定 →感知层兜底。
