# 01 — Prompt 工程进阶：三版 Prompt 对照 + 最小版本管理器

对应文章：第 01 篇《Prompt 工程进阶：提示词从文案到资产》

## 要验证什么

同一批 5 个用药咨询问题，用三版 Prompt 各跑一遍，对照三指标；再演示「改一处 Prompt，怎么看出哪题被改坏」。

```
index.ts      主案例：实验 A（3 版 × 5 题对照）+ 实验 B（v1→v2 加边界的回归对照）
eval.ts       最小版本管理器 runEval(promptVersion, testCases) + 启发式判定
testcases.ts  5 个固定测试题（normal 3 道 + boundary 2 道）
../_sdk/prompts.ts   三版 Prompt 资产（v1 裸指令 / v2 角色+边界+格式 / v3 v2+2 Few-shot）
```

代码只回答三个问题：

1. **三版 Prompt 的效果和成本分别怎么挪动**？v1 格式乱、拒绝方式不可控（长篇大论、token 翻倍）；v2 格式稳、边界生效，且因为「短句」约束，token 反而比 v1 更省；v3 格式已无提升空间，但 few-shot 本身占 token，总 token 涨约 45%——每一版都在「效果」和「成本」之间挪，没有免费午餐。
2. **为什么测试集要固定**？同一批题，跑两版的差异才可归因于 Prompt 本身——这是回归测试能成立的根基。
3. **改一处怎么看出改坏了哪题**？把边界过度收紧成「只答能不能吃 / 一次吃多少」后，「不良反应有哪些」这类正常用药题被误拒——回归测试把「误拒上线」这件事量化出来了。

## 怎么跑

```bash
nvm use 22
pnpm --filter @medai/labs p3-prompt
```

需要 `.env.local` 里配 `DEEPSEEK_API_KEY`，缺 key 时给中文提示并退出。

## 看到什么算成功

### 实验 A：三版对照

一张表三行：v1 / v2 / v3 的格式符合率、边界触达率、每次平均 token。

- v1 格式符合率 0%（没要求，模型不主动分段）、token 反而最贵（回答长篇大论）
- v2 格式与边界都 100%，token 因「短句」约束下降
- v3 格式已无提升空间，few-shot 让 token 涨约 45%

### 实验 B：回归对照

v2 → v4 的「过度收紧边界」改动：boundary 题仍能拒，但正常题被误拒——
T1「不良反应有哪些」被判「不在两类问题内」，边界触达率从 100% 掉到 80%。
这就是「改好了 A、改坏了 B」的量化证据。

## 预算

实验 A 共 15 次调用（3 版 × 5 题），实验 B 再跑 5 次（v4 回归），共 20 次调用。
合计约 ¥0.5，远低于本篇 ¥3 上限。脚本启动会打印预估消耗。
