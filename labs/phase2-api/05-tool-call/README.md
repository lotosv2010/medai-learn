# 05 — Function Calling：模型只写调用单，不执行

对应文章：第 05 篇《Function Calling：模型只写调用单，不执行》

## 要验证什么

给模型一个「查药物相互作用」的工具，看它到底在干什么：它不执行任何代码，只输出一张结构化「调用单」，真正执行的是你的函数。

```
index.ts    主脚本：实验 A（完整往返）+ B（参数幻觉拦截）+ C（描述宽窄对照）
drug-db.ts  mock 药品库：10 条相互作用规则 + 已知药名列表（刻意与工具定义分离）
tools.ts    工具定义（发给模型的 JSON Schema）+ 执行器 + Zod 参数校验
```

代码只回答四个问题：

1. **Function Calling 是模型在调用函数吗**？不是。它只返回一段 JSON（`tool_calls`），说明「我想调 `check_drug_interaction`，参数是……」。执行权在代码手里。
2. **一次 tool call 的完整流程有哪几步**？发工具定义 → 模型写调用单 → 代码校验并执行 → 结果回传 → 模型作答。中间那步是唯一能插入安全检查的地方。
3. **`arguments` 是什么类型**？字符串。必须 `JSON.parse`，而且模型不一定生成合法 JSON，解析前要兜底。
4. **模型编了不存在的参数怎么办**？不校验就会把「暂无数据」曲解成结论；校验（Zod 拦住 + 回传纠错消息）它就会自己换个参数重试。

## 怎么跑

```bash

pnpm --filter @medai/labs p2-tools
```

> ⚠️ **关键前提**：脚本默认带 `thinking: { type: 'disabled' }`。思考模式会改变行为并拖慢，污染实验 A/B 对照。

## 看到什么算成功

### 实验 A：完整往返

成功的标志是五步都能看清，尤其第 ② 步——此时 `finish_reason='tool_calls'`，模型停下来等你的代码，**没有函数被调用、没有副作用**。`arguments` 的类型打印出来是 `string`。

### 实验 B：参数幻觉拦截

问一个 mock 库没有的药（「头孢克肟」不在 `DRUG_NAMES` 里）：

- **不校验版**：模型编一个药名，查库返回「暂无数据」，模型据此给出自信的错误结论。
- **校验版**：Zod 拦住 → 回传「已知药名有：阿莫西林、布洛芬……请换用其中药名」，模型自己换参数重试。

同一次对话，加了校验就从「自信地错」变成「自己纠正」。

### 实验 C：描述宽窄对照

问「阿莫西林是什么药」（不是问相互作用）：

- **宽描述**（「查询药品信息」）→ 模型误触发工具。
- **窄描述**（「仅当明确问两药能否一起吃时才调用」）→ 直接回答。

工具描述的每个字都是发给模型的 Prompt，写太宽就会误触发。

## 故意留下的不完美

| 不完美 | 为什么不修 | 对应观察点 |
|---|---|---|
| 只做单次往返，不做循环 | 循环、终止条件、ReAct 是阶段五「Agent」的主题 | 本篇明确「Function Calling 是 Agent 的器官，不是 Agent 本身」 |
| 工具执行器是同步查内存库 | 真实场景要查数据库 / 调外部服务 | 07 篇会把执行器搬进 SDK 并做并发调度 |
| mock 库只有 10 条规则 | 演示够用即可，数据量不影响本篇结论 | 07 篇复用这份数据 |
| 写操作（下单、改处方）未演示 | 只读工具可自动执行，写操作需人机确认（HITL） | 阶段五展开 |
