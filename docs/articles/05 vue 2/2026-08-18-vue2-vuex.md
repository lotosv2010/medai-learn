## 🧩 一、什么是状态管理模式

### 单组件的 state 流

先看一个最简单的计数器组件：

```javascript
new Vue({
  data() {
    return { count: 0 }    // state：驱动应用的数据源
  },
  template: `<button @click="increment">{{ count }}</button>`,
  methods: {
    increment() {
      this.count++         // action：响应用户输入，改变 state
    }
  }
})
// view：以声明方式将 state 映射到视图
```

这是一个完美的「单向数据流」：**State → View → Actions → State**。

单组件内部这套流转非常干净。但当多个组件需要共享同一份状态时，问题就来了：

- 多层嵌套组件之间传递状态，`props` 层层下传变成「prop drilling」
- 兄弟组件之间要通信，需要把状态提升到共同祖先，再通过 `$emit` 逐层上传
- 频繁使用 `EventBus`，事件散落各处，调试困难

![单组件状态管理：State → View → Actions 单向数据流](https://v3.vuex.vuejs.org/flow.png)
>
> 图片来源：[Vuex 官方文档 - 简单状态管理起步](https://v3.vuex.vuejs.org/zh/#最简单的-store)

### Vuex 的解法：全局单例 Store

Vuex 把组件的**共享状态抽取出来**，以一个全局单例模式管理。在这种模式下，组件树构成了一个视图，任何组件都能获取状态或触发行为：

```
┌──────────────────────────────────────────┐
│              Vuex Store                  │
│  State ←── Mutations ←── Actions         │
│    ↓                          ↑          │
│  Getters               (async API 请求)  │
└──────┬───────────────────────┬───────────┘
       ↓                       ↑
   Vue Components          Dispatch
   (读取 state/getters)    (触发 action)
   (Commit mutations)
```

![Vuex 状态管理架构图：Vue Components / Actions / Mutations / State / Backend API 的单向流转](https://v3.vuex.vuejs.org/vuex.png)
>
> 图片来源：[Vuex 官方文档 - Vuex 是什么？](https://v3.vuex.vuejs.org/zh/#vuex-是什么)

规则只有一条：**组件永远不直接修改 state，只能通过 commit mutation（同步）或 dispatch action（异步 → commit mutation）来改变状态**。

> 💬 **面试官**：什么是状态管理模式？为什么需要 Vuex？
>
> ✅ 标准答案：状态管理模式是把组件共享的状态抽取到一个全局单例 Store 中，通过规定的方式（mutation/action）来变更状态，使状态变化可预测、可追踪。需要 Vuex 的场景是：多个组件共享状态，且这些状态的变化需要在整个应用中同步。
>
> 🎁 加分答案：提到「Vuex 是一种约定，不是强制」——小项目用 `Vue.observable` 或 `provide/inject` 也能达到效果；Vuex 的核心价值是配合 devtools 实现**时间旅行调试**，这也是为什么 mutation 必须同步。

### 什么情况下才应该用 Vuex

Vuex 不是银弹，引入它有学习成本和样板代码。

**适合用 Vuex**：
- 多个视图依赖同一状态（用户登录态、购物车、全局通知）
- 来自不同视图的行为需要变更同一状态（医疗场景：多个页面都要刷新药品库存）
- 需要 devtools 时间旅行调试和状态快照

**不适合用 Vuex**：
- 组件内部的局部状态（如折叠面板的 `isOpen`）
- 父子组件间简单的单向数据流（用 props/$emit 即可）
- 简单的跨组件共享（用 `Vue.observable` 或 `provide/inject`）

## 🚀 二、五个核心概念：从零搭建药品库存系统

用一个**药品库存管理系统**贯穿五个核心概念，把 Vuex 的使用场景落到实处。

### State：单一状态树

Vuex 用一个对象包含了全部的应用层级状态——**单一状态树**（single source of truth）。

```javascript
// store/index.js
import Vue from 'vue'
import Vuex from 'vuex'

Vue.use(Vuex)

const store = new Vuex.Store({
  state: {
    drugList: [],          // 药品列表
    totalStock: 0,         // 总库存
    currentUser: null      // 当前登录用户
  }
})
```

在组件中读取 state 有两种方式：

```javascript
// 方式一：直接访问
export default {
  computed: {
    drugList() {
      return this.$store.state.drugList
    }
  }
}

// 方式二：mapState 辅助函数（推荐）
import { mapState } from 'vuex'

export default {
  computed: {
    ...mapState(['drugList', 'totalStock']),
    // 或对象写法，可重命名
    ...mapState({
      drugs: state => state.drugList,
      stock: 'totalStock'
    })
  }
}
```

**`mapState` 的本质**：遍历传入的 key 列表，为每个 key 生成一个 computed 函数，函数内部访问 `this.$store.state[key]`。

### Getters：Store 的计算属性

Getters 相当于 store 的 `computed`，对 state 进行派生计算，并且**有缓存**（依赖不变不重新计算）。

```javascript
const store = new Vuex.Store({
  state: {
    drugList: [
      { id: 1, name: '阿司匹林', stock: 100, price: 12.5, isExpired: false },
      { id: 2, name: '布洛芬',  stock: 0,   price: 8.0,  isExpired: false },
      { id: 3, name: '青霉素',  stock: 50,  price: 35.0, isExpired: true  }
    ]
  },
  getters: {
    // 有效库存（未过期且有库存）
    validDrugs: state => state.drugList.filter(d => !d.isExpired && d.stock > 0),
    // 总库存价值
    totalValue: state => state.drugList.reduce((sum, d) => sum + d.stock * d.price, 0),
    // getter 可以接受其他 getter 作为第二个参数
    validDrugCount: (state, getters) => getters.validDrugs.length
  }
})
```

组件中使用：

```javascript
import { mapGetters } from 'vuex'

export default {
  computed: {
    ...mapGetters(['validDrugs', 'totalValue', 'validDrugCount']),
    // 或重命名
    ...mapGetters({
      drugs: 'validDrugs'
    })
  }
}
```

如果需要向 getter 传参（如按 ID 查药品），可以**返回一个函数**：

```javascript
getters: {
  getDrugById: state => id => state.drugList.find(d => d.id === id)
}

// 组件中：this.$store.getters.getDrugById(1)
// 注意：这种方式不会缓存，每次调用都重新计算
```

> 💬 **面试官**：Vuex getters 的缓存机制是什么？
>
> ✅ 标准答案：getters 被实现为 Vue 实例的 `computed` 属性，利用 Vue 响应式系统的 `dirty flag` 机制实现缓存——依赖的 state 没有变化时，直接返回缓存值，不重新执行计算函数。
>
> 🎁 加分答案：能说出 getter 返回函数时缓存失效的原因（返回的是函数，computed 的依赖是函数本身而非函数的返回值），以及这对性能的影响。

### Mutations：同步提交 + 为什么必须同步

**Mutation 是唯一可以直接修改 state 的方式。**

```javascript
const store = new Vuex.Store({
  state: {
    drugList: []
  },
  mutations: {
    // type: 'ADD_DRUG', payload: 药品对象
    ADD_DRUG(state, drug) {
      state.drugList.push(drug)
    },
    UPDATE_STOCK(state, { id, stock }) {
      const drug = state.drugList.find(d => d.id === id)
      if (drug) drug.stock = stock
    },
    REMOVE_DRUG(state, id) {
      state.drugList = state.drugList.filter(d => d.id !== id)
    }
  }
})
```

提交 mutation：

```javascript
// 直接 commit
this.$store.commit('ADD_DRUG', { id: 4, name: '头孢', stock: 200, price: 28.0 })

// 对象写法（type + payload）
this.$store.commit({
  type: 'UPDATE_STOCK',
  id: 1,
  stock: 80
})
```

辅助函数 `mapMutations`：

```javascript
import { mapMutations } from 'vuex'

export default {
  methods: {
    ...mapMutations(['ADD_DRUG', 'UPDATE_STOCK', 'REMOVE_DRUG']),
    addNewDrug() {
      this.ADD_DRUG({ id: 5, name: '维生素C', stock: 500 })
    }
  }
}
```

**为什么 mutation 必须是同步函数？**

这是 Vuex 设计中最重要的约束，背后是 **devtools 时间旅行**的需求。

Vuex devtools 会记录每次 mutation 的**前后状态快照**，让开发者可以在历史中「穿越」——回退到任意一次 mutation 前的状态。这个机制的前提是：当一个 mutation 被记录时，它对应的**状态变更必须是确定且已完成的**。

如果 mutation 是异步的：

```javascript
// ❌ 错误示例：在 mutation 中写异步
mutations: {
  FETCH_DRUG(state) {
    axios.get('/api/drugs').then(res => {
      state.drugList = res.data  // 异步赋值，devtools 无法知道是哪个 mutation 导致的
    })
  }
}
```

当 devtools 记录这个 mutation 时，`state.drugList` 还没被赋值（异步 pending 中）。当异步回调执行时，devtools 已经完成了这次 mutation 的记录——状态变更和 mutation 记录时间点脱钩，时间旅行就坏掉了。

**严格模式通过同步 watcher 在运行时强制执行这个约束**——下文「进阶」章节会详细讲原理。

> 💬 **面试官**：mutation 为什么必须是同步函数？异步会有什么问题？
>
> ✅ 标准答案：Vuex devtools 的时间旅行功能依赖在每次 mutation 提交时记录状态快照。如果 mutation 是异步的，状态变更发生在未来某个时刻，devtools 无法在 commit 时刻确定「这次 mutation 结束后的状态是什么」，导致快照不准，时间旅行失效。
>
> 🎁 加分答案：能提到严格模式的实现——Vuex 用 `store._vm.$watch(() => store._vm._data.$$state, cb, { deep: true, sync: true })` 监听状态变化，如果在 mutation 之外修改了 state，`_committing` 标志位为 false，watch 回调立即抛出错误；`sync: true` 确保状态一变化就同步执行回调（不进队列），这样才能精确捕获非法修改。

### Actions：封装异步操作

Action 类似 mutation，但有两点关键区别：

- **Action 提交的是 mutation**，不是直接变更状态
- **Action 可以包含异步操作**

```javascript
const store = new Vuex.Store({
  state: { drugList: [], loading: false },
  mutations: {
    SET_LOADING(state, loading) { state.loading = loading },
    SET_DRUG_LIST(state, list) { state.drugList = list }
  },
  actions: {
    // context 对象包含 { commit, dispatch, state, getters, rootState, rootGetters }
    async fetchDrugList({ commit }, params) {
      commit('SET_LOADING', true)
      try {
        const { data } = await axios.get('/api/drugs', { params })
        commit('SET_DRUG_LIST', data)
      } finally {
        commit('SET_LOADING', false)
      }
    },
    // action 可以组合其他 action
    async initPage({ dispatch }) {
      await dispatch('fetchDrugList')
      await dispatch('fetchPatientList')
    }
  }
})
```

组件中触发 action，`dispatch` 返回 `Promise`，可以用 `await` 等待：

```javascript
import { mapActions } from 'vuex'

export default {
  methods: {
    ...mapActions(['fetchDrugList']),
    async loadData() {
      try {
        await this.fetchDrugList({ category: 'antibiotic' })
        this.$message.success('加载成功')
      } catch(e) {
        this.$message.error('加载失败')
      }
    }
  }
}
```

> 💬 **面试官**：action 和 mutation 的本质区别？什么情况下必须用 action？
>
> ✅ 标准答案：mutation 必须同步、直接修改 state；action 可以异步、但不能直接修改 state，只能通过 commit mutation 来改变状态。只要涉及异步操作（API 请求、定时器）就必须放到 action 中。
>
> 🎁 加分答案：action 本质上是通过 `new Promise(fn)` 包装用户函数并返回的——即使用户函数不返回 Promise，`dispatch` 也始终返回 Promise，这保证了 `await dispatch(...)` 始终可用；action 还可以 `dispatch` 其他 action 来组合异步流程。

### Modules：拆分大型 Store

当应用变得复杂，所有状态放在单一 store 会非常臃肿。Vuex 允许将 store 拆分成**模块**（module），每个模块拥有自己的 state/getters/mutations/actions，甚至可以嵌套子模块。

```javascript
// store/modules/drug.js
const drugModule = {
  namespaced: true,    // 开启命名空间（推荐）
  state: () => ({
    list: [],
    loading: false
  }),
  getters: {
    validDrugs: state => state.list.filter(d => d.stock > 0)
  },
  mutations: {
    SET_LIST(state, list) { state.list = list }
  },
  actions: {
    async fetch({ commit }) {
      const { data } = await axios.get('/api/drugs')
      commit('SET_LIST', data)
    }
  }
}

// store/modules/prescription.js
const prescriptionModule = {
  namespaced: true,
  state: () => ({
    list: [],
    currentPrescription: null
  }),
  mutations: {
    SET_CURRENT(state, prescription) {
      state.currentPrescription = prescription
    }
  },
  actions: {
    // 跨模块调用：通过 rootState 访问其他模块状态
    async createPrescription({ commit, rootState }, prescriptionData) {
      const doctorId = rootState.user.currentUser.id  // 访问 user 模块的 state
      await axios.post('/api/prescriptions', { ...prescriptionData, doctorId })
    }
  }
}

// store/index.js
const store = new Vuex.Store({
  modules: {
    drug: drugModule,
    prescription: prescriptionModule,
    user: userModule
  }
})
```

**命名空间下的访问方式**：

```javascript
// 访问模块 state
this.$store.state.drug.list
this.$store.state.prescription.currentPrescription

// 访问模块 getter
this.$store.getters['drug/validDrugs']

// 提交模块 mutation
this.$store.commit('drug/SET_LIST', drugList)

// 触发模块 action
this.$store.dispatch('drug/fetch')
```

**在模块内部访问根状态 rootState / rootGetters**：

```javascript
// actions 的 context 对象提供 rootState 和 rootGetters
actions: {
  someAction({ state, commit, rootState, rootGetters }) {
    // state: 当前模块的 state
    // rootState: 根模块的 state（可访问所有模块）
    // rootGetters: 全局 getters 命名空间
  }
}
```

**跨模块 dispatch/commit（带 `{ root: true }`）**：

```javascript
actions: {
  // 在 drug 模块中调用 prescription 模块的 action
  async fetchWithPrescription({ dispatch }) {
    await dispatch('drug/fetch', null, { root: true })          // 调用其他模块 action
    await dispatch('prescription/loadList', null, { root: true })
  }
}
```

**辅助函数在模块中的使用**，推荐在组件中用 `createNamespacedHelpers`：

```javascript
import { createNamespacedHelpers } from 'vuex'
const { mapState, mapActions } = createNamespacedHelpers('drug')

export default {
  computed: {
    ...mapState(['list', 'loading']),            // 等价于 drug/list
  },
  methods: {
    ...mapActions(['fetch']),                    // 等价于 drug/fetch
  }
}
```

> 💬 **面试官**：modules 命名空间的路径是怎么拼接的？怎么跨模块调用 action？
>
> ✅ 标准答案：命名空间路径是 `moduleName + '/'` 的拼接，支持嵌套（如 `home/title/CHANGE_NAME`）。跨模块调用 action 有两种方式：在 action 的 context 中 `dispatch('otherModule/actionName', payload, { root: true })`，或直接在组件中 `this.$store.dispatch('otherModule/actionName', payload)`。
>
> 🎁 加分答案：能说出 `{ root: true }` 的作用——在命名空间模块内部，`dispatch` 和 `commit` 默认是局部的（只在当前模块命名空间内查找），加上 `{ root: true }` 才会去根命名空间查找。

## 🔍 三、原理拆解：Vuex 为什么这样设计

这一节手写 Vuex 核心机制，理解每个设计决策背后的原因。

### install：Vue.mixin beforeCreate 注入 $store

`Vue.use(Vuex)` 会调用 `Vuex.install(Vue)`，install 的唯一任务是给所有组件注入 `$store` 属性：

```javascript
// src/plugins/vuex/store.js
import applyMixin from "./mixin"

// 暴露 Vue 构造函数（供内部使用，如 Vue.set）
export let Vue

export const install = (_Vue) => {
  Vue = _Vue
  // 需要将根组件注入的 store 分派给每一个组件(子组件)
  applyMixin(Vue)
}
```

```javascript
// src/plugins/vuex/mixin.js
export default function applyMixin(Vue) {
  // vue内部会把生命周期函数，拍平成一个数组
  Vue.mixin({
    beforeCreate: vuexInit  // 初始化
  })
}

function vuexInit() {
  // 1.给所有的组件增加 $store 属性，指向我们创建的 store 实例
  const options = this.$options  // 获取用户所有的选项
  if(options.store) {            // 根实例（new Vue({ store }) 时）
    this.$store = options.store
  } else if(options.parent && options.parent.$store) {  // 子孙组件
    this.$store = options.parent.$store  // 从父组件继承
  }
}
```

**设计亮点**：利用全局 mixin 在所有组件的 `beforeCreate` 中注入 `$store`——根组件直接从 `options.store` 取，子组件从 `options.parent.$store` 继承。这样不需要手动传递，所有组件都能访问 `this.$store`。

```javascript
// src/plugins/vuex/index.js
import { Store, install } from './store'

export default {
  Store,
  install
}
```

### state 响应式化：借用 Vue 实例的妙处

Vuex 没有自己实现响应式系统，而是**直接借用 Vue 实例**：

```javascript
// src/plugins/vuex/store.js
export class Store {
  constructor(options) {
    const state = options.state

    // 1. 添加状态逻辑
    // 属性如果是通过 $ 开头的，默认不会将这个属性挂载到实例上
    this._vm = new Vue({
      data: {
        $$state: state  // 会将 $$state 对应的对象，都通过 defineProperty 来进行属性劫持
      }
    })
  }

  get state() {
    return this._vm._data.$$state
  }
}
```

**为什么用 `$$state` 而不是 `state`？**

Vue 实例初始化时，会把 `data` 中的所有属性代理到实例上（`this.xxx`）。以 `$` 开头的属性会跳过这个代理（Vue 内部约定 `$` 开头是框架属性），所以 `$$state` 不会被代理到 `_vm` 实例上，只存在于 `_vm._data.$$state`。

这样设计有一个优点：`store.state` 只通过 getter 暴露，避免直接修改。

**验证 state 响应式**：

```javascript
// store/index.js
const store = new Vuex.Store({
  state: {
    name: 'robin'
  }
})
```

```vue
<!-- HelloWorld.vue -->
<template>
  <div class="hello">
    <h3>{{ msg }}</h3>
    <h4>{{ this.$store.state.name}}</h4>
  </div>
</template>

<script>
export default {
  name: 'HelloWorld',
  props: {
    msg: String
  },
  mounted() {
    setTimeout(() => {
      this.$store.state.name = 'jack'  // 直接赋值也会响应式更新（但不推荐）
    }, 2000);
  }
}
</script>
```

### getters 缓存：挂载为 computed 属性

getters 的缓存机制完全依赖 Vue 的 `computed`：

```javascript
// src/plugins/vuex/store.js
import { forEachValue } from "./utils"

export class Store {
  constructor(options) {
    const state = options.state
    const computed = {}  // getters 缓存使用

    // 2. 添加 getters 逻辑
    // getters 属性具有缓存的
    this.getters = {}
    forEachValue(options.getters, (fn, key) => {
      // 将用户的 getters 定义在实例上
      computed[key] = () => fn(this.state)
      Object.defineProperty(this.getters, key, {
        // 当执行取值时，执行计算属性逻辑
        get: () => this._vm[key]  // 从 Vue 实例的 computed 取值（有缓存）
      })
    })

    // 1. 添加状态逻辑
    this._vm = new Vue({
      data: {
        $$state: state
      },
      computed   // 👈 把 getter 函数作为 computed 属性传入
    })
  }

  get state() {
    return this._vm._data.$$state
  }
}
```

### mutations 和 actions 的实现

```javascript
// src/plugins/vuex/store.js
export class Store {
  constructor(options) {
    const state = options.state
    const computed = {}

    this.getters = {}
    forEachValue(options.getters, (fn, key) => {
      computed[key] = () => fn(this.state)
      Object.defineProperty(this.getters, key, {
        get: () => this._vm[key]
      })
    })

    this._vm = new Vue({
      data: {
        $$state: state
      },
      computed
    })

    // 3. 添加 mutations 逻辑
    this.mutations = {}
    forEachValue(options.mutations, (fn, key) => {  // 绑定 mutations
      this.mutations[key] = (payload) => fn(this.state, payload)
    })

    // 4. 添加 actions 逻辑
    this.actions = {}
    forEachValue(options.actions, (fn, key) => {
      this.actions[key] = (payload) => fn(this, payload)  // 传入 store 作为 context
    })
  }

  get state() {
    return this._vm._data.$$state
  }

  // 在严格模式下，commit 和 dispatch 是有区别的
  commit = (type, payload) => {  // 保证当前 this，永远指向当前 store 实例
    // 调用 commit 其实就是去找绑定在 mutations 上的用户方法
    this.mutations[type](payload)
  }

  dispatch = (type, payload) => {
    this.actions[type](payload)
  }
}
```

**为什么 `commit` 和 `dispatch` 用箭头函数？**

当 action 中使用解构 `{ commit }` 时，`commit` 被单独提取出来，`this` 丢失。箭头函数使 `commit` 始终指向 store 实例：

```javascript
actions: {
  changeName({ commit }, payload) {  // 解构出来的 commit 不会丢失 this
    setTimeout(() => {
      commit('CHANGE_NAME', payload)  // 正常工作，因为 commit 是箭头函数
    }, 1000)
  }
}
```

```javascript
class ModuleCollection {
  constructor(options) {
    this.register([], options)  // stack 栈结构 ['根对象', 'home', 'title']
  }

  register(path, rootModule) {
    let newModule = {  // 格式化后的结果
      _raw: rootModule,     // 原来的模块(用户定义的)
      _children: {},        // 子模块
      state: rootModule.state  // 当前模块的状态
    }

    if(path.length == 0) {
      // 根模块
      this.root = newModule
    } else {
      const parent = path.slice(0, -1).reduce((memo, current) => {
        return memo._children[current]
      }, this.root)
      parent._children[path[path.length - 1]] = newModule
    }

    if(rootModule.modules) {  // 有子模块的情况
      // 循环模块
      forEachValue(rootModule.modules, (module, moduleName) => {
        this.register(path.concat(moduleName), module)
      })
    }
  }
}
```

```javascript
import { forEachValue } from "./utils"

class Module {
  constructor(rawModule) {
    this._raw = rawModule   // 原来的模块(用户定义的)
    this._children = {}     // 子模块
    this.state = rawModule.state  // 当前模块的状态
  }

  getChild(key) {
    return this._children[key]
  }

  addChild(key, module) {
    this._children[key] = module
  }

  forEachMutation(fn) {
    if(this._raw.mutations) {
      forEachValue(this._raw.mutations, fn)
    }
  }

  forEachAction(fn) {
    if(this._raw.actions) {
      forEachValue(this._raw.actions, fn)
    }
  }

  forEachGetter(fn) {
    if(this._raw.getters) {
      forEachValue(this._raw.getters, fn)
    }
  }

  forEachChild(fn) {
    forEachValue(this._children, fn)
  }

  get namespaced() {
    return !!this._raw.namespaced
  }
}

export default Module
```

```javascript
// src/plugins/vuex/module-collection.js（使用 Module 类）
import Module from "./module"
import { forEachValue } from "./utils"

class ModuleCollection {
  constructor(options) {
    this.register([], options)
  }

  register(path, rootModule) {
    // 格式化后的结果
    let newModule = new Module(rootModule)

    if(path.length == 0) {
      this.root = newModule
    } else {
      const parent = path.slice(0, -1).reduce((memo, current) => {
        return memo.getChild(current)
      }, this.root)
      parent.addChild(path[path.length - 1], newModule)
    }

    if(rootModule.modules) {
      forEachValue(rootModule.modules, (module, moduleName) => {
        this.register(path.concat(moduleName), module)
      })
    }
  }

  getNamespaced(path) {
    let root = this.root  // 从根模块开始找
    return path.reduce((str, key) => {
      root = root.getChild(key)  // 不停的去找当前模块
      return str + (root.namespaced ? `${key}/` : ``)
    }, '')
  }
}
```

### 安装模块：installModule 递归

对模块进行安装操作，对 `dispatch` 和 `action` 方法进行重写。

```javascript
// src/plugins/vuex/store.js（完整版）
import applyMixin from "./mixin"
import ModuleCollection from "./module-collection"
import { forEachValue } from "./utils"

export let Vue

/**
 * 获取最新的状态
 * @param {*} store
 * @param {*} path
 */
function getState(store, path) {
  let local = path.reduce((newState, current) => {
    return newState[current];
  }, store.state);
  return local
}

/**
 * 初始化模块
 * @param {容器} store
 * @param {根模块} rootState
 * @param {路径} path
 * @param {格式化后的数据} module
 */
const installModule = (store, rootState, path, module) => {
  // 给当前订阅的事件，增加一个命名空间
  // 例如:home/changeAge user/changeAge home/title/changeAge
  let namespaced = store._modules.getNamespaced(path)  // 返回前缀

  // 状态：将所有的子模块的状态安装到父模块的状态上
  if(path.length > 0) {  // vuex 可以动态的添加模块
    let parent = path.slice(0, -1).reduce((memo, current) => {
      return memo[current]
    }, rootState)

    // 如果这个对象本身不是响应式的，那么 Vue.set 就相当于 obj[属性] = 值
    store._withCommitting(() => {
      Vue.set(parent, path[path.length - 1], module.state)
    })
  }

  module.forEachMutation((mutation, key) => {
    key = namespaced + key  // 拼接命名空间前缀
    store._mutations[key] = store._mutations[key] || []
    store._mutations[key].push((payload) => {
      store._withCommitting(() => {
        mutation.call(store, getState(store, path), payload)  // 这里更改状态
      })
      store._subscribes.forEach(fn => {
        fn(mutation, store.state)  // 用最新的状态触发插件订阅
      })
    })
  })

  module.forEachAction((action, key) => {
    key = namespaced + key
    store._actions[key] = store._actions[key] || []
    store._actions[key].push((payload) => {
      action.call(store, store, payload)
    })
  })

  module.forEachGetter((getter, key) => {
    key = namespaced + key
    // 模块中getters的名字重复会覆盖
    store._wrappedGetters[key] = function() {
      return getter(getState(store, path))
    }
  })

  module.forEachChild((child, key) => {
    // 递归加载模块
    installModule(store, rootState, path.concat(key), child)
  })
}

function resetStoreVM(store, state) {
  const computed = {}  // 定义计算属性
  store.getters = {}   // 定义 store 中的 getters

  forEachValue(store._wrappedGetters, (fn, key) => {
    computed[key] = () => {
      return fn(store.state)
    }
    Object.defineProperty(store.getters, key, {
      get: () => store._vm[key]  // 去计算属性取值
    })
  })

  store._vm = new Vue({
    data: {
      $$state: state
    },
    computed  // 计算属性有缓存特性
  })

  // 严格模式：只要状态一变化会立即执行，在状态变化后同步执行
  if (store.strict) {
    store._vm.$watch(() => store._vm._data.$$state, () => {
      console.assert(store._committing, '在 mutation 之外更改了状态')
    }, { deep: true, sync: true });
  }
}

export class Store {
  constructor(options) {
    const state = options.state

    this._committing = false  // 严格模式标志位
    this.strict = options.strict || false  // 是否开启严格模式

    // 1. 数据格式化，格式化的结果是树结构
    this._modules = new ModuleCollection(options)

    // 2. 安装模块
    this._actions = {}
    this._mutations = {}
    this._wrappedGetters = {}
    this._subscribes = []

    // 根模块的状态中，要将子模块通过模块名定义在根模块上
    installModule(this, state, [], this._modules.root)

    // 3. 将状态和 getters 都定义在当前 vm 上
    resetStoreVM(this, state)

    // 4. 插件
    if (options.plugins) {
      options.plugins.forEach(plugin => plugin(this))
    }
  }

  get state() {
    return this._vm._data.$$state
  }

  // 在严格模式下，commit 和 dispatch 是有区别的
  commit = (type, payload) => {  // 保证当前 this，永远指向当前 store 实例
    this._mutations[type].forEach(fn => fn.call(this, payload))
  }

  dispatch = (type, payload) => {
    this._actions[type].forEach(fn => fn.call(this, payload))
  }

  replaceState(newState) {  // 用最新的状态替换掉
    this._withCommitting(() => {
      this._vm._data.$$state = newState;
    })
  }

  subscribe(fn) {
    this._subscribes.push(fn)
  }

  _withCommitting(fn) {
    let committing = this._committing;
    this._committing = true;  // 在函数调用前表示 _committing 为 true
    fn();
    this._committing = committing;
  }
}

export const install = (_Vue) => {
  Vue = _Vue
  applyMixin(Vue)
}
```

## 🔌 五、插件机制：持久化原理

### 插件开发与 subscribe / replaceState

Vuex 插件是一个函数，接收 store 作为唯一参数，通过 `subscribe` 订阅 mutation 来监听状态变化：

```javascript
// store/index.js（插件配置）
import Vue from 'vue'
import Vuex from '../plugins/vuex/index'
import user from './user.store'
import home from './home.store'

Vue.use(Vuex)

function persists(store) {  // 每次去服务器上拉取最新的 session、local
  let local = localStorage.getItem('VUEX:state');
  if (local) {
    store.replaceState(JSON.parse(local));  // 会用 local 替换掉所有的状态
  }
  store.subscribe((mutation, state) => {
    // 这里需要做一个节流 throttle lodash
    localStorage.setItem('VUEX:state', JSON.stringify(state));
  });
}

const store = new Vuex.Store({
  plugins: [
    persists
  ],
  state: {
    name: 'robin',
    age: 8
  },
  // ...其他配置
})

export default store
```

### 手写 subscribe 和 replaceState

这里我们要实现 `subscribe`、`replaceState` 方法。

```javascript
// src/plugins/vuex/store.js（插件机制核心实现）
// 容器初始化
export class Store {
  constructor(options) {
    const state = options.state
    this._modules = new ModuleCollection(options)

    this._actions = {}
    this._mutations = {}
    this._wrappedGetters = {}
    this._subscribes = []  // 👈 插件订阅列表

    installModule(this, state, [], this._modules.root)
    resetStoreVM(this, state)

    // 4. 插件：按顺序调用每个插件函数
    options.plugins.forEach(plugin => plugin(this))
  }

  get state() {
    return this._vm._data.$$state
  }

  commit = (type, payload) => {
    this._mutations[type].forEach(fn => fn.call(this, payload))
  }

  dispatch = (type, payload) => {
    this._actions[type].forEach(fn => fn.call(this, payload))
  }

  replaceState(state) {
    this._vm._data.$$state = state;  // 直接替换 $$state
  }

  subscribe(fn) {
    this._subscribes.push(fn)  // 将订阅函数推入列表
  }
}
```

**插件的订阅触发时机**：在 `installModule` 中，每次 mutation 执行后立即通知所有插件：

```javascript
module.forEachMutation((mutation, key) => {
  key = namespaced + key
  store._mutations[key] = store._mutations[key] || []
  store._mutations[key].push((payload) => {
    mutation.call(store, getState(store, path), payload, namespaced)
    store._subscribes.forEach(fn => {
      fn(mutation, store.state)  // 用最新的状态触发插件订阅
    })
  })
})
```

### vuex-persistedstate 原理

市面上的 `vuex-persistedstate` 库核心逻辑与上面的 `persists` 函数相同，增加了：

- 支持多种 storage（localStorage / sessionStorage / cookie）
- 支持按 key 过滤，只持久化部分状态
- 支持节流（throttle），避免频繁写入
- 支持加密

**医疗场景：处方草稿持久化**

```javascript
// 实际项目中的持久化插件配置
import createPersistedState from 'vuex-persistedstate'

const store = new Vuex.Store({
  plugins: [
    createPersistedState({
      key: 'medai-store',           // localStorage key
      paths: ['prescription.draft'], // 只持久化处方草稿，不持久化完整药品列表
      storage: window.sessionStorage // 会话级持久化（关闭标签页清除）
    })
  ],
  modules: {
    prescription: {
      namespaced: true,
      state: () => ({
        draft: null,    // 处方草稿（需要持久化）
        list: []        // 处方列表（不需要持久化，每次从服务端拉取）
      }),
      mutations: {
        SAVE_DRAFT(state, draft) {
          state.draft = draft  // 保存草稿时，插件自动写入 sessionStorage
        },
        CLEAR_DRAFT(state) {
          state.draft = null
        }
      }
    }
  }
})
```

> 💬 **面试官**：vuex-persistedstate 的持久化原理是什么？
>
> ✅ 标准答案：通过 Vuex 插件机制，在 `subscribe` 中监听每次 mutation 执行后将整个（或部分）state 序列化写入 storage；Store 初始化时调用 `replaceState` 用 storage 中的数据覆盖初始 state。
>
> 🎁 加分答案：能提到性能优化——每次 mutation 都写 storage 代价高，实际应用中会加 throttle（节流）；大数据不适合用 localStorage（最大 5MB），应该只持久化关键状态（如 `paths` 配置）。

### 严格模式：_withCommitting + sync watcher

严格模式下，如果 state 在 mutation 之外被修改，Vuex 会立刻抛出错误：

```javascript
const store = new Vuex.Store({
  strict: process.env.NODE_ENV !== 'production',  // 生产环境关闭，避免性能损耗
  state: { count: 0 },
  mutations: {
    increment(state) { state.count++ }
  }
})

// 这样会抛出错误：[vuex] do not mutate vuex store state outside mutation handlers.
store.state.count = 1
```

**手写严格模式实现**：

```javascript
// 严格模式核心：_withCommitting 标志位
this._committing = false;

_withCommitting(fn) {
  let committing = this._committing;
  this._committing = true;  // 在函数调用前表示 _committing 为 true
  fn();
  this._committing = committing;
}
```

```javascript
// resetStoreVM 中启用严格模式监听
if (store.strict) {
  // 只要状态一变化会立即执行，在状态变化后同步执行
  store._vm.$watch(() => store._vm._data.$$state, () => {
    console.assert(store._committing, '在 mutation 之外更改了状态')
  }, { deep: true, sync: true });
}
```

```javascript
// mutation 内部更改状态：通过 _withCommitting 包裹
store._mutations[key].push((payload) => {
  store._withCommitting(() => {
    mutation.call(store, getState(store, path), payload);  // 这里更改状态
  })
})
```

```javascript
// replaceState 也要包裹，属于合法的状态替换
replaceState(newState) {
  this._withCommitting(() => {
    this._vm._data.$$state = newState;
  })
}
```

```javascript
// installModule 中的 Vue.set 也要包裹，内部更改状态属于正常更新
store._withCommitting(() => {
  Vue.set(parent, path[path.length - 1], module.state);
})
```

**`{ sync: true }` 的关键性**：Vue 的 `$watch` 默认是异步的（批量更新队列），但严格模式需要在状态变化的**同一个调用栈**内判断 `_committing`。`sync: true` 让 watcher 同步执行——状态一变化立刻触发回调，此时 `_withCommitting` 的上下文还在，`_committing` 仍为 `true`；如果是非法修改，`_committing` 为 `false`，断言失败。

> 💬 **面试官**：Vuex 严格模式的实现原理是什么？
>
> ✅ 标准答案：严格模式用 `$watch` 监听 `$$state`，`{ deep: true, sync: true }`。`sync: true` 让 watcher 在状态变化时同步执行回调；`_withCommitting` 方法在执行 mutation 前将 `_committing` 置 true，执行完置回 false。如果 watcher 触发时 `_committing` 为 false，说明是在 mutation 外部修改了 state，通过 `console.assert` 报错。
>
> 🎁 加分答案：严格模式只应在开发环境开启（`strict: process.env.NODE_ENV !== 'production'`），因为 `sync: true` 的深度 watcher 对每次状态变化都同步执行，在频繁更新的场景下有性能损耗。

### 表单处理：v-model 与 Vuex 的冲突

`v-model` 本质是 `:value` + `@input`，直接与 Vuex state 绑定时会绕过 mutation：

```html
<!-- ❌ 这样会在严格模式下报错 -->
<input v-model="$store.state.prescription.patientName">
```

**解决方案一：使用 computed 的 setter**（推荐）

```javascript
export default {
  computed: {
    patientName: {
      get() {
        return this.$store.state.prescription.patientName
      },
      set(value) {
        this.$store.commit('prescription/SET_PATIENT_NAME', value)
      }
    }
  }
}
```

```html
<!-- 绑定 computed，v-model 正常工作 -->
<input v-model="patientName">
```

**解决方案二：`:value` + `@input` 分开写**

```html
<input
  :value="$store.state.prescription.patientName"
  @input="$store.commit('prescription/SET_PATIENT_NAME', $event.target.value)"
>
```

两种方案本质相同，computed setter 写法更简洁，推荐用于多个字段的表单场景。

### resetStoreVM：state 响应式化 + getters computed 化

```javascript
// src/store.js
function resetStoreVM (store, state, hot) {
  const oldVm = store._vm

  store.getters = {}
  store._makeLocalGettersCache = Object.create(null)

  const wrappedGetters = store._wrappedGetters
  const computed = {}

  forEachValue(wrappedGetters, (fn, key) => {
    computed[key] = partial(fn, store)  // 把 getter 绑定为 Vue computed
    Object.defineProperty(store.getters, key, {
      get: () => store._vm[key],  // 从 computed 取值（有缓存）
      enumerable: true
    })
  })

  const silent = Vue.config.silent
  Vue.config.silent = true
  store._vm = new Vue({
    data: {
      $$state: state  // state 挂载为 Vue 实例的响应式 data
    },
    computed  // getters 挂载为 computed
  })
  Vue.config.silent = silent

  if (store.strict) {
    enableStrictMode(store)  // 开启严格模式
  }

  if (oldVm) {
    if (hot) {
      store._withCommit(() => {
        oldVm._data.$$state = null
      })
    }
    Vue.nextTick(() => oldVm.$destroy())  // 销毁旧的 vm 实例
  }
}
```

### commit / dispatch：mutation 同步 + action Promise

```javascript
// src/store.js
commit (_type, _payload, _options) {
  const { type, payload, options } = unifyObjectStyle(_type, _payload, _options)

  const mutation = { type, payload }
  const entry = this._mutations[type]

  this._withCommit(() => {
    entry.forEach(function commitIterator (handler) {
      handler(payload)
    })
  })

  // 通知所有插件
  this._subscribers
    .slice()
    .forEach(sub => sub(mutation, this.state))
}

dispatch (_type, _payload) {
  const { type, payload } = unifyObjectStyle(_type, _payload)

  const action = { type, payload }
  const entry = this._actions[type]

  // 通知 subscribeAction（before 钩子）
  try {
    this._actionSubscribers
      .slice()
      .filter(sub => sub.before)
      .forEach(sub => sub.before(action, this.state))
  } catch (e) { ... }

  const result = entry.length > 1
    ? Promise.all(entry.map(handler => handler(payload)))
    : entry[0](payload)

  return new Promise((resolve, reject) => {
    result.then(res => {
      // 通知 subscribeAction（after 钩子）
      resolve(res)
    }, error => {
      reject(error)
    })
  })
}
```

**关键点**：`dispatch` 始终返回 `Promise`，即使 action 是同步的。多个同名 action（跨模块无 namespaced 时会重叠）用 `Promise.all` 并发执行。

### ModuleCollection + installModule：命名空间路径拼接

```javascript
// src/module/module-collection.js（官方实现）
export default class ModuleCollection {
  constructor (rawRootModule) {
    this.register([], rawRootModule, false)
  }

  get (path) {
    return path.reduce((module, key) => {
      return module.getChild(key)
    }, this.root)
  }

  getNamespace (path) {
    let module = this.root
    return path.reduce((namespace, key) => {
      module = module.getChild(key)
      return namespace + (module.namespaced ? key + '/' : '')
    }, '')
  }

  register (path, rawModule, runtime = true) {
    if (__DEV__) {
      assertRawModule(path, rawModule)
    }

    const newModule = new Module(rawModule, runtime)
    if (path.length === 0) {
      this.root = newModule
    } else {
      const parent = this.get(path.slice(0, -1))
      parent.addChild(path[path.length - 1], newModule)
    }

    if (rawModule.modules) {
      forEachValue(rawModule.modules, (rawChildModule, key) => {
        this.register(path.concat(key), rawChildModule, runtime)
      })
    }
  }
}
```

## 🎯 八、生产级最佳实践

### 何时不用 Vuex

**用 Vuex 的边界**：

```
                是否跨组件共享？
                     │
          ┌──── 否 ────┤──── 是 ────┐
          ↓           │             ↓
   组件内部 state   变化是否频繁    是否需要 devtools 时间旅行？
   (data/ref)       且复杂？          │
                       │        ┌── 否 ──┐── 是 ──┐
                  ┌─ 否 ─┐      ↓        ↓        ↓
                  ↓      ↓  provide/  Vue.         Vuex
             props/   事件   inject  observable
             emit    总线
```

判断标准：
- **用 Vuex**：多个无关联视图共享同一状态，且状态变化要追踪
- **用 provide/inject**：祖孙组件传值，不需要追踪
- **用 `Vue.observable`**：轻量全局状态，不需要 modules 和 devtools
- **用组件 data**：UI 状态（折叠/展开、hover 效果）

### 模块化拆分规范

按**业务域**拆分，不按技术层面拆：

```javascript
// ✅ 按业务域（推荐）
modules: {
  user,         // 用户：登录态、权限、个人信息
  drug,         // 药品：列表、搜索、库存
  prescription, // 处方：创建、审核、历史
  notification  // 通知：消息列表、未读数
}

// ❌ 按技术层面（不推荐）
modules: {
  api,     // 所有 API 请求结果？太混乱
  ui,      // 所有 UI 状态？太宽泛
  cache    // 缓存层？不是状态管理的职责
}
```

每个模块的 state 用**工厂函数**（`state: () => ({...})`），而不是对象，避免多个 store 实例之间共享引用。

### 与 Pinia 的对比

Pinia 是 Vue 3 推荐的状态管理库，理解它和 Vuex 的区别有助于面试加分：

| 维度 | Vuex 3.x | Pinia |
|------|---------|-------|
| 核心概念 | State/Getter/Mutation/Action | State/Getter/Action（无 Mutation）|
| 异步支持 | Action 中异步，不能直接修改 state | Action 中可以直接修改 state |
| TypeScript | 需要大量类型标注 | 开箱即用，类型推断友好 |
| DevTools | 支持时间旅行（依赖 Mutation 同步） | 支持，但无 Mutation 概念的时间旅行 |
| 模块 | 需要 namespaced 配置 | 每个 store 是独立的，天然隔离 |
| 包体积 | ~20KB | ~2KB |
| SSR | 支持 | 支持，且更简单 |

**Vue 2 存量项目中选择的建议**：
- Vue 2 项目继续用 Vuex 3.x（成熟稳定）
- 新开 Vue 3 项目直接用 Pinia
- Vue 2 → Vue 3 迁移时，同步把 Vuex → Pinia（迁移成本不高）

> 💬 **面试官**：Vuex 和 Pinia 的主要区别？为什么 Vue 3 更推荐 Pinia？
>
> ✅ 标准答案：Pinia 去掉了 Mutation，state 可以直接在 Action 中修改，减少了样板代码；TypeScript 类型推断开箱即用；多个 store 天然隔离不需要 namespace；包体积更小（约 2KB vs 20KB）。
>
> 🎁 加分答案：Pinia 去掉 Mutation 不代表放弃可追踪性——Pinia 的 devtools 支持查看每次 state 变化的来源，只是不强制所有修改都必须走 mutation。Vue 团队认为「mutation 必须同步」这个约束对开发者是额外心智负担，Pinia 的设计更贴近 Composition API 的思维方式。

```javascript
class ModuleCollection {
  constructor(options) {
    this.register([], options)
  }

  register(path, rawModule) {
    const newModule = new Module(rawModule)
    if (path.length === 0) {
      this.root = newModule
    } else {
      const parent = path.slice(0, -1).reduce(
        (memo, key) => memo.getChild(key),
        this.root
      )
      parent.addChild(path[path.length - 1], newModule)
    }
    if (rawModule.modules) {
      forEachValue(rawModule.modules, (module, moduleName) => {
        this.register(path.concat(moduleName), module)
      })
    }
  }

  getNamespaced(path) {
    let root = this.root
    return path.reduce((str, key) => {
      root = root.getChild(key)
      return str + (root.namespaced ? `${key}/` : '')
    }, '')
  }
}
```

```javascript
import Vue from 'vue'
import applyMixin from './mixin'
import ModuleCollection from './module-collection'
import { forEachValue } from './utils'

export let _Vue

// 从 path 路径获取当前模块的最新 state
function getState(store, path) {
  return path.reduce((state, key) => state[key], store.state)
}

// 递归安装模块
const installModule = (store, rootState, path, module) => {
  const namespace = store._modules.getNamespaced(path)

  // 子模块 state 挂载到父 state 上（响应式）
  if (path.length > 0) {
    const parent = path.slice(0, -1).reduce((s, key) => s[key], rootState)
    store._withCommitting(() => {
      _Vue.set(parent, path[path.length - 1], module.state)
    })
  }

  // 注册 mutations
  module.forEachMutation((mutation, key) => {
    const type = namespace + key
    store._mutations[type] = store._mutations[type] || []
    store._mutations[type].push(payload => {
      store._withCommitting(() => {
        mutation.call(store, getState(store, path), payload)
      })
      // mutation 执行完后通知所有插件
      store._subscribers.forEach(fn => fn({ type, payload }, store.state))
    })
  })

  // 注册 actions（始终返回 Promise）
  module.forEachAction((action, key) => {
    const type = namespace + key
    store._actions[type] = store._actions[type] || []
    store._actions[type].push(payload => {
      return Promise.resolve(
        action.call(store, {
          commit: store.commit,
          dispatch: store.dispatch,
          state: getState(store, path),
          rootState: store.state,
          getters: store.getters,
          rootGetters: store.getters
        }, payload)
      )
    })
  })

  // 注册 getters
  module.forEachGetter((getter, key) => {
    const type = namespace + key
    store._wrappedGetters[type] = () =>
      getter(getState(store, path), store.getters, store.state, store.getters)
  })

  // 递归安装子模块
  module.forEachChild((child, key) => {
    installModule(store, rootState, path.concat(key), child)
  })
}

// 将 state 和 getters 绑定到 Vue 实例
function resetStoreVM(store, state) {
  const computed = {}
  store.getters = {}

  forEachValue(store._wrappedGetters, (fn, key) => {
    computed[key] = fn
    Object.defineProperty(store.getters, key, {
      get: () => store._vm[key],
      enumerable: true
    })
  })

  store._vm = new Vue({
    data: { $$state: state },
    computed
  })

  // 严格模式：state 变化时同步检查 _committing 标志
  if (store.strict) {
    store._vm.$watch(
      () => store._vm._data.$$state,
      () => {
        console.assert(store._committing,
          '[vuex-mini] 不能在 mutation 之外修改 state！')
      },
      { deep: true, sync: true }
    )
  }
}

export class Store {
  constructor(options = {}) {
    this._committing = false
    this.strict = options.strict || false
    this._mutations = {}
    this._actions = {}
    this._wrappedGetters = {}
    this._subscribers = []

    // 1. 格式化模块树
    this._modules = new ModuleCollection(options)

    // 2. 递归安装模块
    const state = this._modules.root.state
    installModule(this, state, [], this._modules.root)

    // 3. 响应式化 state + getters 缓存
    resetStoreVM(this, state)

    // 4. 初始化插件
    if (options.plugins) {
      options.plugins.forEach(plugin => plugin(this))
    }
  }

  get state() {
    return this._vm._data.$$state
  }

  // 箭头函数确保解构后 this 不丢失
  commit = (type, payload) => {
    const handlers = this._mutations[type]
    if (!handlers) {
      console.error(`[vuex-mini] 未找到 mutation: ${type}`)
      return
    }
    handlers.forEach(fn => fn(payload))
  }

  dispatch = (type, payload) => {
    const handlers = this._actions[type]
    if (!handlers) {
      return Promise.reject(new Error(`[vuex-mini] 未找到 action: ${type}`))
    }
    return handlers.length > 1
      ? Promise.all(handlers.map(fn => fn(payload)))
      : handlers[0](payload)
  }

  subscribe(fn) {
    this._subscribers.push(fn)
    // 返回取消订阅函数
    return () => {
      const idx = this._subscribers.indexOf(fn)
      if (idx > -1) this._subscribers.splice(idx, 1)
    }
  }

  replaceState(newState) {
    this._withCommitting(() => {
      this._vm._data.$$state = newState
    })
  }

  _withCommitting(fn) {
    const prev = this._committing
    this._committing = true
    fn()
    this._committing = prev
  }
}

export const install = (_Vue) => {
  if (_Vue === _Vue) {}  // 防止重复安装可在此加版本检查
  _Vue = _Vue
  applyMixin(_Vue)
}
```

```javascript
// 持久化插件：将指定路径的 state 保存到 localStorage
function createPersistPlugin(options = {}) {
  const { key = 'vuex-mini', paths = [] } = options

  return function(store) {
    // 初始化时从 localStorage 恢复
    const saved = localStorage.getItem(key)
    if (saved) {
      try {
        const savedState = JSON.parse(saved)
        // 深度合并恢复的状态
        store.replaceState(deepMerge(store.state, savedState))
      } catch (e) {
        console.warn('[persist] 恢复状态失败', e)
      }
    }

    // 每次 mutation 后保存指定 paths
    store.subscribe((mutation, state) => {
      const stateToSave = paths.length
        ? pick(state, paths)
        : state
      localStorage.setItem(key, JSON.stringify(stateToSave))
    })
  }
}

// 按点号路径提取嵌套值
function pick(obj, paths) {
  const result = {}
  paths.forEach(path => {
    const keys = path.split('.')
    let src = obj
    let dst = result
    keys.forEach((key, i) => {
      if (src == null) return
      if (i === keys.length - 1) {
        dst[key] = src[key]
      } else {
        dst[key] = dst[key] || {}
        src = src[key]
        dst = dst[key]
      }
    })
  })
  return result
}

// 深度合并（恢复状态时不丢弃初始结构）
function deepMerge(target, source) {
  if (!source) return target
  const result = { ...target }
  Object.keys(source).forEach(key => {
    if (source[key] && typeof source[key] === 'object' && !Array.isArray(source[key])) {
      result[key] = deepMerge(target[key] || {}, source[key])
    } else {
      result[key] = source[key]
    }
  })
  return result
}

  strict: true,
  plugins: [
    createPersistPlugin({
      key: 'medai-store',
      paths: ['user.token', 'user.currentUser', 'prescription.draft']  // 只持久化登录态和处方草稿
    })
  ],
```

> 💬 **面试官**：讲一下你手写 Vuex 时遇到的最大难点？
>
> ✅ 标准答案：命名空间路径拼接和 `installModule` 递归安装是最复杂的部分——子模块的 state 要用 `Vue.set` 动态挂载到父 state 上才能保持响应式；getters 需要在 `resetStoreVM` 时一次性全部传入 Vue 实例的 `computed`，之后再修改不会生效。
>
> 🎁 加分答案：action 的 context 对象中的 `state` 要用 `getState(store, path)` 动态取，而不是 capture 初始值——因为子模块 state 是动态挂载的，闭包捕获的引用可能不是最新的。

```javascript
export const mapGetters = getterList => {
  let obj = {};
  for (let i = 0; i < getterList.length; i++) {
    let getterName = getterList[i]
    obj[getterName] = function() {
      return this.$store.getters[getterName];
    };
  }
  return obj;
};

export const mapMutations = mutationList => {
  let obj = {}
  for (let i = 0; i < mutationList.length; i++) {
    const type = mutationList[i];
    obj[type] = function(payload) {
      return this.$store.commit(type, payload)
    }
  }
  return obj
}

export const mapActions = actionList => {
  let obj = {}
  for (let i = 0; i < actionList.length; i++) {
    const type = actionList[i];
    obj[type] = function(payload) {
      return this.$store.dispatch(type, payload)
    }
  }
  return obj
}
```

### 核心知识点速查表

| 知识点 | 一句话核心 | 面试考察频率 |
|--------|-----------|------------|
| 状态管理模式 | 共享状态抽到全局单例，单向数据流 + devtools 追踪 | ⭐⭐⭐ |
| mutation 必须同步 | devtools 时间旅行快照依赖同步，`sync: true` watcher 强制 | ⭐⭐⭐⭐⭐ |
| state 响应式原理 | `new Vue({ data: { $$state } })`，借用 Vue 响应式系统 | ⭐⭐⭐⭐ |
| getters 缓存 | getter 挂载为 computed，dirty flag，依赖不变不重算 | ⭐⭐⭐⭐ |
| action vs mutation | action 可异步，不能直接改 state；mutation 同步，直接改 state | ⭐⭐⭐⭐⭐ |
| 命名空间路径拼接 | `getNamespaced` reduce 拼 `moduleName + '/'`，支持嵌套 | ⭐⭐⭐ |
| 插件 subscribe | mutation 执行后回调，`replaceState` 替换状态 | ⭐⭐⭐ |
| 严格模式 | `_withCommitting` + `$watch sync` 同步 watcher 断言 | ⭐⭐⭐⭐ |
| 表单处理 | computed setter 方案，`:value` + `@input` 方案 | ⭐⭐⭐ |
| mapState/mapGetters | 遍历 key 列表生成 computed 函数，访问 `$store.state/getters` | ⭐⭐⭐ |
| Vuex vs Pinia | Pinia 无 Mutation，TS 友好，包体积小，Vue 3 推荐 | ⭐⭐⭐⭐ |
