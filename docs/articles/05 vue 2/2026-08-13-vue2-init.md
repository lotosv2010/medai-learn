在看细节之前，先把整条主线摆出来：

```text
① 选版本
   vue.js（含编译器，~91KB）
   vue.runtime.js（不含编译器，~63KB）← 生产首选
   vue.esm.js（ES Module 版）← Vite 默认

② Vue 构造函数定义
   function Vue(options) { this._init(options) }
   ├─ initMixin      → Vue.prototype._init
   ├─ stateMixin     → $data / $props / $set / $delete / $watch
   ├─ eventsMixin    → $on / $off / $once / $emit
   ├─ lifecycleMixin → _update / $forceUpdate / $destroy
   └─ renderMixin    → _render / $nextTick
   initGlobalAPI(Vue) → Vue.use / Vue.mixin / Vue.extend / Vue.component...

③ new Vue(options) → _init 序列
   mergeOptions → initLifecycle → initEvents → initRender

   → created
   → 有 el？→ $mount
```

记住三条：**① 版本决定 bundle 大小，② Mixin 分治让原型干净可维护，③ _init 序列决定了「哪个钩子能用哪些数据」。**

## 🏗️ 一、三个构建版本：选错了要多 30KB

### 为什么要分这么多版本

**维度一：是否含编译器**

| 版本 | 文件 | 大小（gzip 前） | 能不能用 `template` 字符串 |
|------|------|:---:|:---:|
| Runtime+Compiler | `vue.js` | ~91KB | ✅ |
| Runtime-only | `vue.runtime.js` | ~63KB | ❌（需构建时编译） |

差的这 28KB，就是 `template → render` 的编译器。

**维度二：模块格式**

| 后缀 | 格式 | 使用场景 |
|------|------|---------|
| 无后缀 | UMD | `<script>` 标签直接引入 |
| `.common.js` | CommonJS | Webpack 1 / Node.js |
| `.esm.js` | ES Module | Webpack 2+ / Rollup / Vite |
| `.min.js` | 压缩版 | CDN 生产使用 |

**dist/ 目录命名规律**：两个维度两两组合。`vue.runtime.esm.js` = 无编译器 + ES Module；`vue.common.js` = 含编译器 + CommonJS。`vue.esm.js` 是含编译器的 ESM 版，适合直接在 Webpack 里引入并在浏览器里运行时编译（开发调试场景）。

### vue-cli / Vite 默认选哪个

**vue-cli（Webpack）**：默认用 `vue.runtime.esm.js`，Runtime-only 的 ESM 版。`vue-loader` 在构建时把 `.vue` 文件的 `<template>` 编译成 `render` 函数，运行时不再需要编译器。

**Vite**：`@vitejs/plugin-vue` 同样在构建时处理模板，默认 Runtime-only。

```javascript
// ❌ 运行时报错！Runtime-only 没有 compiler，无法解析 template 字符串
new Vue({
  template: '<div>{{ msg }}</div>',
  data() { return { msg: 'hello' } }
})

// ✅ 手写 render 函数，不依赖编译器
new Vue({
  render(h) { return h('div', this.msg) },
  data() { return { msg: 'hello' } }
})

// ✅ .vue 单文件组件（构建时已编译，运行时只执行 render）
// <template><div>{{ msg }}</div></template>
```

### Vue.config 全局配置

```javascript
Vue.config.productionTip = false  // 关闭生产提示
Vue.config.silent = false         // 取消所有日志和警告

Vue.config.errorHandler = function(err, vm, info) {
  // info 是 Vue 提供的错误位置信息，如 "mounted hook"、"v-on handler"
  console.error(`[ErrorHandler] ${info}:`, err)
  // 对接 Sentry：Sentry.captureException(err)
}

Vue.config.warnHandler = function(msg, vm, trace) {
  if (process.env.NODE_ENV === 'test') {
    throw new Error(msg) // 测试环境将警告转为异常，提前暴露问题
  }
}
```

> 💬 **面试官**：Vue 2 有哪几个构建版本？runtime-only 和 runtime+compiler 的区别？
>
> ✅ 标准答案：按「是否含编译器」分两类：`vue.runtime.js`（~63KB）和 `vue.js`（~91KB）。runtime-only 不能在运行时解析 `template` 字符串，必须配合 `vue-loader` 构建时编译，好处是省 ~28KB。
> 🎁 加分答案：编译器本质是 `template → AST → render function` 转换链。生产环境 `.vue` 文件构建时已编译完，运行时只执行 render 函数，所以编译器可以安全排除。两个维度（是否含编译器 × 模块格式）组合出 dist/ 下所有文件名。

## 🔧 二、Vue 构造函数：分治设计的艺术

### 构建入口路径链

Vue 2 的入口文件路径链展示了「层层增强」的设计：

```text
src/platforms/web/entry-runtime-with-compiler.js
  └─ 覆盖 $mount，添加运行时模板编译能力
     └─ src/platforms/web/entry-runtime.js
          └─ 注册平台相关指令和组件（v-model / v-show / transition）
             └─ src/core/index.js
                  └─ initGlobalAPI(Vue)，挂载全局静态 API
                     └─ src/core/instance/index.js
                          └─ Vue 构造函数本体 + 5 个 xxxMixin
```

runtime-only 版本从 `entry-runtime.js` 起，跳过编译器增强那一层。

### 5 个 xxxMixin 各挂了什么

```javascript
// src/core/instance/index.js
function Vue(options) {
  this._init(options)  // 只做一件事：调用 _init
}

initMixin(Vue)       // 挂载 _init
stateMixin(Vue)      // 挂载 $data / $props / $set / $delete / $watch
eventsMixin(Vue)     // 挂载 $on / $off / $once / $emit
lifecycleMixin(Vue)  // 挂载 _update / $forceUpdate / $destroy
renderMixin(Vue)     // 挂载 _render / $nextTick

export default Vue
```

| Mixin | 挂载到原型的方法/属性 | 职责 |
|-------|---------------------|------|
| `initMixin` | `_init` | 初始化流程入口 |
| `stateMixin` | `$data` / `$props` / `$set` / `$delete` / `$watch` | 数据操作 API |
| `eventsMixin` | `$on` / `$off` / `$once` / `$emit` | 事件系统 |
| `lifecycleMixin` | `_update` / `$forceUpdate` / `$destroy` | 生命周期操作 |
| `renderMixin` | `_render` / `$nextTick` | 渲染相关 |

拆开的原因：每个 Mixin 对应一个职责文件，单独维护、单独测试，不会形成一个几百行的大文件。Vue 故意用普通函数而非 ES6 class，正是为了让多个文件都能灵活操作 `prototype`。

### initGlobalAPI 静态 API

```javascript
// src/core/global-api/index.js
export function initGlobalAPI(Vue) {
  Vue.config = config
  Vue.set = set
  Vue.delete = del
  Vue.nextTick = nextTick
  Vue.observable = (obj) => { observe(obj); return obj }
  Vue.options = Object.create(null)
  Vue.options._base = Vue
  initUse(Vue)            // Vue.use
  initMixin(Vue)          // Vue.mixin
  initExtend(Vue)         // Vue.extend
  initAssetRegisters(Vue) // Vue.component / Vue.directive / Vue.filter
}
```

> 💬 **面试官**：5 个 xxxMixin 分别挂载了什么？为什么要拆开？
>
> ✅ 标准答案：按职责划分——initMixin 挂 `_init`，stateMixin 挂数据 API，eventsMixin 挂事件 API，lifecycleMixin 挂 `_update`，renderMixin 挂 `_render`。拆开是按职责切分，每个文件单独负责一块逻辑，方便维护和测试。
> 🎁 加分答案：用普通函数不用 class，是为了让多个 Mixin 文件都能自由操作 `Vue.prototype`，class 的方法定义语法在这里反而不如直接赋值灵活。

## ⚙️ 三、\_init 完整初始化序列（10 个阶段）

### 阶段 1-4：关系建立（beforeCreate 之前）

```javascript
Vue.prototype._init = function(options) {
  const vm = this
  vm._uid = uid++       // 每个实例唯一 ID，递增
  vm._isVue = true      // 标记为 Vue 实例，避免被响应式系统观测
  vm.$options = mergeOptions(vm.constructor.options, options)

  initLifecycle(vm)  // 建立 $parent/$root/$children/$refs，初始化 _watcher/_isMounted 等
  initEvents(vm)     // vm._events = Object.create(null)，同步父组件事件监听器
  initRender(vm)     // 绑定 vm._c / vm.$createElement；响应式化 $attrs / $listeners

  callHook(vm, 'beforeCreate') // 👈 此时：没有 data / props / computed / watch
}
```

`initLifecycle` 建立父子关系的核心逻辑：

```javascript
export function initLifecycle(vm) {
  const options = vm.$options
  let parent = options.parent
  if (parent && !options.abstract) {
    // abstract 是抽象组件标记（如 keep-alive / transition），不参与父子关系
    while (parent.$options.abstract && parent.$parent) {
      parent = parent.$parent
    }
    parent.$children.push(vm)       // 把自己注册到父组件的 $children
  }
  vm.$parent = parent
  vm.$root = parent ? parent.$root : vm  // 根实例指向自己或父链的根
  vm.$children = []
  vm.$refs = {}
  vm._watcher = null
  vm._isMounted = false
  vm._isDestroyed = false
}
```

### 阶段 5-9：数据初始化（beforeCreate → created）

```javascript
  initInjections(vm)  // 先解析 inject，让 data() 里能用 inject 值
  initState(vm)       // props → methods → data → computed → watch
  initProvide(vm)     // 后初始化 provide（可引用 data/computed）

  callHook(vm, 'created') // 👈 data/props/computed/watch 全部就绪

  if (vm.$options.el) { vm.$mount(vm.$options.el) }
```

### initState 内部顺序的意义

```javascript
export function initState(vm) {
  const opts = vm.$options
  if (opts.props)    initProps(vm)    // 1. 最先：子组件依赖父传值
  if (opts.methods)  initMethods(vm)  // 2. data() 里可能调用 methods
  if (opts.data)     initData(vm)     // 3. 响应式化 data
  if (opts.computed) initComputed(vm) // 4. 依赖 data/props
  if (opts.watch)    initWatch(vm)    // 5. 最后：依赖 computed/data
}
```

顺序不是随意的：`props` 必须最先，因为 `data()` 函数里可能用到 `this.someProp`；`methods` 在 `data` 之前，因为 `data()` 函数里可能调用 `this.someMethod()`；`computed` 依赖 `data/props`；`watch` 可以监听 `computed`，自然最后。

### mergeOptions 策略

| 选项类型 | 合并策略 |
|---------|---------|
| 生命周期钩子 | 数组合并（mixin/父在前，组件自身在后） |
| `data` | 递归合并，组件自身 data 优先 |
| `methods` / `computed` / `components` | 后者覆盖前者 |
| `watch` | 合并成数组，都会执行 |

生命周期合并的核心逻辑：

```javascript
function mergeHook(parentVal, childVal) {
  if (childVal) {
    if (parentVal) { return parentVal.concat(childVal) }
    return Array.isArray(childVal) ? childVal : [childVal]
  }
  return parentVal
  // 结果是一个数组，callHook 时遍历执行
}
```

> 💬 **面试官**：`_init` 执行顺序？`beforeCreate` 和 `created` 之间做了什么？`initInjections` 为什么在 `initState` 之前？
>
> ✅ 标准答案：mergeOptions 和关系建立后触发 `beforeCreate`，然后 initInjections → initState → initProvide，最后触发 `created`。`initInjections` 在前，是为了让 inject 的值能在 `data()` 函数里直接用。
> 🎁 加分答案：`initProvide` 在 `initState` 之后，因为 provide 的值通常来自 `data` 或 `computed`，需要它们先初始化。inject 先消费、provide 后生产，顺序构成完整闭环。

### _init 骨架（src/core/instance/init.js）

```javascript
export function initMixin(Vue) {
  Vue.prototype._init = function(options) {
    const vm = this
    vm._uid = uid++
    vm._isVue = true

    if (options && options._isComponent) {
      // 子组件走快速路径，避免 mergeOptions 的动态枚举开销
      initInternalComponent(vm, options)
    } else {
      vm.$options = mergeOptions(
        resolveConstructorOptions(vm.constructor),
        options || {},
        vm
      )
    }

    vm._renderProxy = vm  // 生产环境直接用 vm；开发环境用 Proxy 做属性访问警告
    vm._self = vm

    initLifecycle(vm)
    initEvents(vm)
    initRender(vm)
    callHook(vm, 'beforeCreate')
    initInjections(vm)   // resolve injections before data/props
    initState(vm)
    initProvide(vm)      // resolve provide after data/props
    callHook(vm, 'created')

    if (vm.$options.el) {
      vm.$mount(vm.$options.el)
    }
  }
}
```

`_isComponent` 优化：子组件（通过 `Vue.extend` 创建的）走 `initInternalComponent` 快速路径，避免 `mergeOptions` 的全量处理开销，是 Vue 2 的一处重要性能优化。

### initState（src/core/instance/state.js）

```javascript
export function initState(vm) {
  vm._watchers = []
  const opts = vm.$options
  if (opts.props) initProps(vm, opts.props)
  if (opts.methods) initMethods(vm, opts.methods)
  if (opts.data) {
    initData(vm)
  } else {
    observe(vm._data = {}, true /* asRootData */)
  }
  if (opts.computed) initComputed(vm, opts.computed)
  if (opts.watch && opts.watch !== nativeWatch) {
    initWatch(vm, opts.watch)
  }
}

function initData(vm) {
  let data = vm.$options.data
  data = vm._data = typeof data === 'function'
    ? getData(data, vm)   // 调用 data() 函数，同时捕获内部错误
    : data || {}

  const keys = Object.keys(data)
  let i = keys.length
  while (i--) {
    const key = keys[i]
    if (!isReserved(key)) {
      proxy(vm, '_data', key)  // vm.xxx → vm._data.xxx 的属性代理
    }
  }
  observe(data, true /* asRootData */)  // 启动响应式观测
}
```

### callHook 实现（src/core/instance/lifecycle.js）

```javascript
export function callHook(vm, hook) {
  // 暂停依赖收集，避免钩子函数里访问响应式数据触发意外的依赖
  pushTarget()
  const handlers = vm.$options[hook]
  const info = `${hook} hook`
  if (handlers) {
    for (let i = 0, j = handlers.length; i < j; i++) {
      invokeWithErrorHandling(handlers[i], vm, null, vm, info)
    }
  }
  if (vm._hasHookEvent) {
    vm.$emit('hook:' + hook)  // 支持父组件用 @hook:mounted 监听子组件钩子
  }
  popTarget()
}
```

`_hasHookEvent` 是一个优化标记：只有父组件确实监听了 `hook:xxx` 事件时才为 `true`，避免无意义的 `$emit` 开销。`invokeWithErrorHandling` 会把钩子里的错误冒泡到 `Vue.config.errorHandler`。

### $mount 入口（src/platforms/web/runtime/index.js）

```javascript
Vue.prototype.$mount = function(el, hydrating) {
  el = el && inBrowser ? query(el) : undefined
  return mountComponent(this, el, hydrating)
}

// src/core/instance/lifecycle.js
export function mountComponent(vm, el, hydrating) {
  vm.$el = el
  callHook(vm, 'beforeMount')

  const updateComponent = () => {
    vm._update(vm._render(), hydrating)
    // vm._render() → 执行 render 函数，生成 VNode 树
    // vm._update() → 调用 patch，将 VNode 更新到真实 DOM
  }

  // 渲染 Watcher：数据变化时重新执行 updateComponent
  new Watcher(vm, updateComponent, noop, {
    before() {
      if (vm._isMounted && !vm._isDestroyed) {
        callHook(vm, 'beforeUpdate')
      }
    }
  }, true /* isRenderWatcher */)

  if (vm.$vnode == null) {
    // $vnode 为 null 说明是根实例，根实例在这里触发 mounted
    // 子组件的 mounted 在 patch 插入真实 DOM 后触发，所以子先父后
    vm._isMounted = true
    callHook(vm, 'mounted')
  }
  return vm
}
```

这段代码解释了一个经典面试题：**父子组件 mounted 为什么是子先父后**——根实例的 `mounted` 在 `mountComponent` 末尾触发，子组件的 `mounted` 在 `patch` 过程中子组件 VNode 插入真实 DOM 时触发，必然先于父组件完成。

**src/init.js** — _init 完整序列：

```javascript
import { initState } from './state'
import { callHook, initLifecycle } from './lifecycle'
import { mergeOptions } from './util'

let uid = 0

export function initMixin(Vue) {
  Vue.prototype._init = function(options) {
    const vm = this
    vm._uid = uid++
    vm._isVue = true
    vm.$options = mergeOptions(Vue.options || {}, options)

    initLifecycle(vm)
    callHook(vm, 'beforeCreate')
    resolveInjections(vm)   // initInjections：先于 initState
    initState(vm)
    resolveProvide(vm)      // initProvide：后于 initState
    callHook(vm, 'created')

    if (vm.$options.el) {
      vm.$mount(vm.$options.el)
    }
  }
}

// 向上遍历 $parent 链，查找 provide 数据
function resolveInjections(vm) {
  const inject = vm.$options.inject
  if (!inject) return
  const result = Object.create(null)
  let source = vm.$parent
  while (source) {
    if (source._provided) {
      Object.keys(inject).forEach(key => {
        if (key in source._provided && !(key in result)) {
          result[key] = source._provided[key]
        }
      })
    }
    source = source.$parent
  }
  Object.keys(result).forEach(key => {
    Object.defineProperty(vm, key, {
      enumerable: true,
      configurable: true,
      get: () => result[key],
      set: () => { console.warn(`Avoid mutating an injected value directly: "${key}"`) }
    })
  })
}

function resolveProvide(vm) {
  const provide = vm.$options.provide
  if (provide) {
    vm._provided = typeof provide === 'function' ? provide.call(vm) : provide
  }
}
```

**src/lifecycle.js** — initLifecycle + callHook + $mount：

```javascript
export function initLifecycle(vm) {
  const options = vm.$options
  vm.$parent = options.parent || null
  vm.$root = vm.$parent ? vm.$parent.$root : vm
  vm.$children = []
  vm.$refs = {}
  vm._isMounted = false
  vm._isDestroyed = false
  if (vm.$parent) { vm.$parent.$children.push(vm) }
}

export function callHook(vm, hook) {
  const handlers = vm.$options[hook]
  if (handlers) {
    for (let i = 0; i < handlers.length; i++) {
      try { handlers[i].call(vm) }
      catch (e) { console.error(`Error in ${hook} hook:`, e) }
    }
  }
}

export function initLifecycleMixin(Vue) {
  Vue.prototype.$mount = function(el) {
    const vm = this
    vm.$el = typeof el === 'string' ? document.querySelector(el) : el
    callHook(vm, 'beforeMount')
    vm._isMounted = true
    callHook(vm, 'mounted')
    return vm
  }
}
```

**src/state.js** — initState + 数据响应式 + 属性代理：

```javascript
import { observe } from './observer/index'

export function initState(vm) {
  const opts = vm.$options
  if (opts.props)    initProps(vm)
  if (opts.methods)  initMethods(vm)
  if (opts.data)     initData(vm)
  if (opts.computed) initComputed(vm)
  if (opts.watch)    initWatch(vm)
}

function initProps(vm) {
  const propsData = vm.$options.propsData || {}
  vm.$props = {}
  Object.keys(vm.$options.props || {}).forEach(key => {
    vm.$props[key] = propsData[key]
    proxy(vm, '$props', key)
  })
}

function initMethods(vm) {
  const methods = vm.$options.methods || {}
  Object.keys(methods).forEach(key => {
    vm[key] = typeof methods[key] === 'function' ? methods[key].bind(vm) : () => {}
  })
}

function initData(vm) {
  let data = vm.$options.data
  vm._data = data = typeof data === 'function' ? data.call(vm) : data
  Object.keys(data).forEach(key => proxy(vm, '_data', key))
  observe(data)
}

function initComputed(vm) {
  const computed = vm.$options.computed || {}
  Object.keys(computed).forEach(key => {
    const userDef = computed[key]
    const getter = typeof userDef === 'function' ? userDef : userDef.get
    Object.defineProperty(vm, key, {
      enumerable: true,
      configurable: true,
      get: () => getter.call(vm),
      set: typeof userDef === 'object' && userDef.set ? userDef.set.bind(vm) : () => {}
    })
  })
}

function initWatch(vm) {
  const watch = vm.$options.watch || {}
  Object.keys(watch).forEach(key => {
    const handler = watch[key]
    vm.$watch(key, typeof handler === 'string' ? vm[handler] : handler)
  })
}

export function initStateMixin(Vue) {
  Vue.prototype.$watch = function(key, cb) {
    const vm = this
    if (!vm._watchers) vm._watchers = []
    vm._watchers.push({ key, cb })
  }
}

function proxy(vm, source, key) {
  Object.defineProperty(vm, key, {
    get() { return vm[source][key] },
    set(newValue) { vm[source][key] = newValue }
  })
}
```

**src/observer/index.js** — 数据劫持（第02篇会深入展开）：

```javascript
class Observer {
  constructor(value) {
    Object.defineProperty(value, '__ob__', {
      enumerable: false, configurable: false, value: this
    })
    if (Array.isArray(value)) {
      this.observeArray(value)
    } else {
      this.walk(value)
    }
  }
  walk(data) {
    Object.keys(data).forEach(key => defineReactive(data, key, data[key]))
  }
  observeArray(data) { data.forEach(item => observe(item)) }
}

function defineReactive(data, key, value) {
  observe(value)
  Object.defineProperty(data, key, {
    get() { return value },
    set(newValue) {
      if (newValue === value) return
      observe(newValue)
      value = newValue
    }
  })
}

export function observe(data) {
  if (typeof data !== 'object' || data == null) return
  if (data.__ob__) return data.__ob__
  return new Observer(data)
}
```

**src/util.js** — mergeOptions（生命周期合并核心）：

```javascript
export const LIFECYCLE_HOOKS = [
  'beforeCreate', 'created', 'beforeMount', 'mounted',
  'beforeUpdate', 'updated', 'beforeDestroy', 'destroyed'
]

const strats = {}

function mergeHook(parentVal, childVal) {
  if (childVal) {
    if (parentVal) return parentVal.concat(childVal)
    return Array.isArray(childVal) ? childVal : [childVal]
  }
  return parentVal
}

LIFECYCLE_HOOKS.forEach(hook => { strats[hook] = mergeHook })

export function mergeOptions(parent, child) {
  const options = {}
  Object.keys(parent).forEach(key => mergeField(key))
  Object.keys(child).forEach(key => {
    if (!Object.prototype.hasOwnProperty.call(parent, key)) mergeField(key)
  })
  function mergeField(key) {
    const strat = strats[key]
    options[key] = strat ? strat(parent[key], child[key]) :
      (child[key] !== undefined ? child[key] : parent[key])
  }
  return options
}
```

**src/global-api/index.js** — Vue.mixin + Vue.observable：

```javascript
import { mergeOptions } from '../util'
import { observe } from '../observer/index'

export function initGlobalApi(Vue) {
  Vue.options = Object.create(null)

  Vue.mixin = function(mixin) {
    Vue.options = mergeOptions(Vue.options, mixin)
    return Vue
  }

  Vue.observable = function(obj) {
    observe(obj)
    return obj
  }
}
```

## 💡 六、生产级最佳实践

### 始终选 runtime-only 版本

```javascript
// vue.config.js（vue-cli 项目）
module.exports = {
  runtimeCompiler: false  // 默认值，保持 runtime-only，省 ~28KB
}
```

项目里出现 `[Vue warn]: You are using the runtime-only build of Vue`，说明某处用了 `template` 字符串而非 `.vue` 文件，找到并改成 `render` 函数或迁移进 `.vue` 文件即可。

### errorHandler 对接监控平台

```javascript
Vue.config.errorHandler = function(err, vm, info) {
  // info：Vue 错误位置，如 "mounted hook"、"v-on handler"、"render"
  reportError({
    message: err.message,
    stack: err.stack,
    component: vm.$options.name || vm.$options._componentTag || 'anonymous',
    lifecycleHook: info,
    url: window.location.href
  })
}
```

没有 `errorHandler`，组件内的错误在生产环境完全静默，监控平台感知不到。这是上线必配的项。

### warnHandler 在测试环境转异常

```javascript
if (process.env.NODE_ENV === 'test') {
  Vue.config.warnHandler = function(msg, vm, trace) {
    throw new Error(`[Vue warn]: ${msg}${trace}`)
  }
}
```

这样 CI 跑测试时，任何 Vue 警告都会让测试用例失败，迫使开发者在合并前修复。

### initInjections 先于 initState 的实际价值

```javascript
// 顶层组件：门诊系统，提供全局患者上下文
provide() {
  return { patientId: this.currentPatientId }
}

// 子组件：处方单
inject: ['patientId'],
data() {
  return {
    // ✅ 可以用！inject 已在 data() 执行前初始化
    form: { patientId: this.patientId, drugList: [] }
  }
}
```

如果 `initInjections` 在 `initState` 之后，`data()` 里的 `this.patientId` 就是 `undefined`，form 初始值就是错的。这个看似微小的顺序决定，在实际业务中极其常用。

### Vue.observable 轻量全局状态（Vue 2.6+）

适合替代简单 Vuex 场景，底层直接调用 `observe()`：

```javascript
// store.js
import Vue from 'vue'

export const store = Vue.observable({
  currentPatient: null,
  consultQueue: []
})

export const mutations = {
  setPatient(patient) { store.currentPatient = patient },
  addToQueue(item) { store.consultQueue.push(item) }
}

// 组件里用 computed 追踪（自动响应）
computed: {
  patient() { return store.currentPatient }
}
```
