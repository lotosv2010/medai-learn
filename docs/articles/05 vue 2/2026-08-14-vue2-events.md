# Vue 2 事件绑定原理：$on/$emit 存在哪里？DOM 事件和组件事件有什么本质区别（面试收藏级）

> 面试官推过来一道判断题：「`$emit` 触发的事件会冒泡吗？」你沉默了两秒……冒泡是 DOM 的行为，`$emit` 是 Vue 自己的发布订阅，但你又不确定。今天彻底搞清楚：Vue 的组件事件和 DOM 事件从存储到触发都是两套完全不同的机制。

---

在看细节之前，先把整条主线摆出来。**全文章节顺序就是这条事件链路的展开**：

```text
【事件绑定完整链路】

① 自定义组件事件（vm._events）
   父组件模板 @submit="handler"
     → 编译为 { on: { submit: handler } }
     → 子组件 initEvents：监听器挂到 vm._events['submit']
     → 子组件 $emit('submit', data) → 遍历 vm._events['submit']，逐个调用

② 原生 DOM 事件（addEventListener）
   原生元素 @click="handler"
     → 编译为 { on: { click: handler } }
     → patch 时 updateDOMListeners → el.addEventListener('click', handler)
   组件 @click.native="handler"
     → 编译为 { nativeOn: { click: handler } }
     → createComponent → componentVNodeHooks.init → 绑到组件根元素真实 DOM

③ 事件修饰符（编译阶段展开为代码）
   .stop    → $event.stopPropagation()
   .prevent → $event.preventDefault()
   .passive → addEventListener 第三参数 { passive: true }
   .once    → createOnceHandler 包装函数 / addEventListener { once: true }

④ $listeners（父→子事件透传）
   initRender → 响应式化 vm.$listeners
   子组件 v-on="$listeners" → 把父组件监听器全部透传给下一层
```

记住一句话：**组件事件存在 `vm._events`，DOM 事件存在真实 DOM 节点，两套机制，互不干扰**。

---

## 🎯 这篇文章解决什么问题

写了三年 Vue，很多人仍然混淆三件事：`$emit` 触发的事件存在哪里、`.native` 为什么能监听组件的原生点击、事件修饰符到底是运行时判断还是编译时展开。

这篇文章沿「vm._events → DOM 事件绑定 → 修饰符编译 → $listeners 透传」这条主线，把 Vue 2 的事件系统从存储到触发逐环拆开：**懂原理，也懂面试怎么答**。读完你能在白板上画出完整事件链路，并答全五大核心追问。

## 🔌 一、基本使用：六种场景一次摸清

> 链路位置：父组件模板书写阶段（编译前）

### 组件自定义事件：$emit + @event

子组件通过 `$emit` 向父组件发送事件，父组件用 `v-on` / `@` 监听：

```html
<!-- 子组件 PrescriptionForm.vue -->
<template>
  <form @submit.native.prevent="handleSubmit">
    <button type="submit">提交处方</button>
  </form>
</template>

<script>
export default {
  methods: {
    handleSubmit() {
      const data = { drugName: '布洛芬缓释胶囊', dosage: '0.3g' }
      this.$emit('approved', data)   // 👈 自定义事件
    }
  }
}
</script>
```

```html
<!-- 父组件 -->
<PrescriptionForm @approved="onApproved" />

<script>
export default {
  methods: {
    onApproved(data) {
      console.log('处方通过审核：', data.drugName)
    }
  }
}
</script>
```

### $on / $off / $once：手动监听 API

除了模板语法，Vue 实例本身就是一个事件总线，可以手动操作：

```javascript
// 注册
this.$on('approved', handler)

// 注销（三种形式）
this.$off()                  // 清空所有事件的所有监听器
this.$off('approved')        // 清空 approved 事件的所有监听器
this.$off('approved', handler)  // 精确移除某一个监听器

// 只触发一次
this.$once('approved', handler)
```

### 原生 DOM 事件：.native 修饰符

在组件标签上监听事件时，默认走的是自定义事件机制（存入 `vm._events`）。如果想监听组件根元素的真实 DOM 事件，需要加 `.native`：

```html
<!-- 监听组件根元素的原生 click 事件 -->
<PrescriptionForm @click.native="handleClick" />

<!-- 没有 .native：监听的是子组件 $emit('click') 触发的自定义事件 -->
<PrescriptionForm @click="handleClick" />
```

### 事件修饰符速览

```html
<button @click.stop="fn">阻止冒泡</button>
<form @submit.prevent="fn">阻止默认行为</form>
<div @click.capture="fn">捕获阶段监听</div>
<div @click.self="fn">只有 target===currentTarget 才触发</div>
<button @click.once="fn">只触发一次</button>

<!-- .passive：告知浏览器此处理器不调用 preventDefault，不等 JS 执行直接滚动 -->
<div @scroll.passive="fn">长处方列表滚动</div>

<!-- 修饰符可链式组合 -->
<a @click.stop.prevent="fn">阻止冒泡 + 阻止默认</a>
```

**⚠️ 注意**：`.passive` 和 `.prevent` 不能同时使用，前者声明「不调用 preventDefault」，后者调用它，两者矛盾。

### 按键修饰符

```html
<input @keyup.enter="submit" />      <!-- 回车键 -->
<input @keyup.13="submit" />         <!-- keyCode 写法（已废弃，了解即可） -->
<input @keyup.ctrl.enter="submit" /> <!-- 组合键：Ctrl + Enter -->
```

### $listeners：透传监听器对象

`$listeners` 包含父组件绑定的所有事件监听器（`.native` 修饰的除外），可以整体透传给下层组件：

```html
<!-- 父组件 -->
<DrugInput @input="onInput" @focus="onFocus" @blur="onBlur" />

<!-- DrugInput.vue：透传所有监听器给原生 input -->
<template>
  <div class="drug-input-wrapper">
    <input v-bind="$attrs" v-on="$listeners" />  <!-- 👈 透传 -->
  </div>
</template>
<script>
export default { inheritAttrs: false }
</script>
```

> 💬 **面试官**：组件事件和 DOM 事件有什么本质区别？
>
> ✅ 标准答案：组件事件（`$emit`）存储在 `vm._events` 对象里，通过 Vue 自己的发布订阅机制触发，纯 JS 函数调用，**不冒泡、不经过 DOM**。DOM 事件通过 `addEventListener` 绑定到真实 DOM 节点，走浏览器的事件系统，**会冒泡、可以捕获**。两套机制完全独立。
>
> 🎁 想加分：在组件上用 `@click` 监听的是组件自定义事件，必须子组件 `$emit('click')` 才触发；想监听组件根元素的真实 click 事件，要用 `@click.native`，它最终走 `addEventListener`。

## 📦 二、vm._events：自定义事件的四个方法

> 链路位置：① 自定义组件事件（vm._events）

### vm._events 的存储结构

Vue 实例初始化时，`initEvents` 会在实例上挂一个空对象：

```javascript
vm._events = Object.create(null)   // key: 事件名，value: fn 数组
vm._hasHookEvent = false           // 是否有 hook:xxx 监听器（性能优化标志）
```

`Object.create(null)` 没有原型链，比 `{}` 更安全（不会误命中 `toString`、`hasOwnProperty` 等内置属性名作为事件名）。

### $on：注册监听器

```javascript
// src/core/instance/events.js
Vue.prototype.$on = function(event, fn) {
  const vm = this

  // 支持数组事件名：$on(['a', 'b'], fn) 批量注册
  if (Array.isArray(event)) {
    for (let i = 0; i < event.length; i++) {
      vm.$on(event[i], fn)
    }
  } else {
    // 向数组 push，同一事件可以注册多个监听器
    (vm._events[event] || (vm._events[event] = [])).push(fn)

    // hook:xxx 事件标记（如 $on('hook:beforeDestroy', fn)）
    if (hookRE.test(event)) {
      vm._hasHookEvent = true
    }
  }
  return vm
}
```

**关键**：同一事件可以注册多个监听器，存在数组里，`$emit` 时全部遍历调用。

### $emit：触发事件

```javascript
Vue.prototype.$emit = function(event, ...args) {
  const vm = this
  let cbs = vm._events[event]

  if (cbs) {
    cbs = cbs.length > 1 ? toArray(cbs) : cbs  // 拷贝一份，防止 $off 时数组变动
    for (let i = 0; i < cbs.length; i++) {
      cbs[i].apply(vm, args)  // 👈 this 指向 vm，纯 JS 函数调用，不经过 DOM
    }
  }
  return vm
}
```

**关键**：`cbs[i].apply(vm, args)` 是纯函数调用，和 DOM 事件没有任何关系，不冒泡。

🔧 **真实案例**：在医疗系统的处方审核流程里，`<PrescriptionForm>` 审核通过后 `$emit('approved', result)`，父页面监听后更新处方状态、记录操作日志、跳转详情页——多个业务动作可以在父组件里灵活组合，子组件只管发信号，不关心后续。

### $off：注销监听器

`$off` 支持三种调用形式：

```javascript
Vue.prototype.$off = function(event, fn) {
  const vm = this

  // 情形1：无参数 → 清空所有事件
  if (!arguments.length) {
    vm._events = Object.create(null)
    return vm
  }

  // 支持数组事件名
  if (Array.isArray(event)) {
    for (let i = 0; i < event.length; i++) {
      vm.$off(event[i], fn)
    }
    return vm
  }

  const cbs = vm._events[event]
  if (!cbs) return vm

  // 情形2：只传 event → 清空该事件所有监听器
  if (!fn) {
    vm._events[event] = null
    return vm
  }

  // 情形3：传 event + fn → 精确移除
  let cb, i = cbs.length
  while (i--) {
    cb = cbs[i]
    if (cb === fn || cb.fn === fn) {  // cb.fn 用于识别 $once 包装的函数
      cbs.splice(i, 1)
      break
    }
  }
  return vm
}
```

注意 `cb.fn === fn` 这个判断：`$once` 注册的是一个包装函数，原始 fn 存在包装函数的 `.fn` 属性上，这样 `$off(event, originalFn)` 也能精确移除 `$once` 注册的监听器。

### $once：只触发一次

```javascript
Vue.prototype.$once = function(event, fn) {
  const vm = this

  function on() {
    vm.$off(event, on)   // 👈 执行前先注销自己
    fn.apply(vm, arguments)  // 再调用原始 fn
  }
  on.fn = fn   // 存原始引用，供 $off 精确移除使用

  vm.$on(event, on)   // 注册的是包装函数
  return vm
}
```

**`$once` 的实现思路**：注册一个包装函数 `on`，`on` 被调用时先把自己从 `_events` 中移除，再调用原始 `fn`。这样无论 `fn` 内部抛不抛异常，都能保证只触发一次（抛异常时 `fn.apply` 会中断，但 `$off` 已经在前面执行了）。

> 💬 **面试官**：`$once` 是怎么实现「只触发一次后自动移除」的？
>
> ✅ 标准答案：`$once` 内部创建一个包装函数 `on`，在 `on` 的函数体里先调用 `$off` 移除自身，再调用原始 `fn`。注册时把 `on` 存入 `_events`，同时把原始 `fn` 存在 `on.fn` 上，方便 `$off` 精确识别和移除。
>
> 🎁 想加分：注意执行顺序——是先 `$off` 再调用 `fn`，这样即使 `fn` 内部再次 `$emit` 同名事件也不会再次触发（因为已经移除了）。`cb.fn === fn` 的判断让手动 `$off(event, fn)` 也能移除 `$once` 注册的监听器，这是一个很细的设计。

> 💬 **面试官**：`$emit` 触发的事件存在哪里？和 DOM 的 addEventListener 有什么本质区别？
>
> ✅ 标准答案：存在 `vm._events` 对象里，key 是事件名，value 是回调函数数组。`$emit` 时遍历数组逐个调用，是纯 JS 的发布订阅，不经过 DOM，所以**不冒泡、不能在父 DOM 上捕获**。而 `addEventListener` 绑定的是真实 DOM 节点，走浏览器事件系统，会冒泡。
>
> 🎁 想加分：`vm._events` 用 `Object.create(null)` 而不是 `{}`，避免事件名和原型链上的属性冲突。另外 `$emit` 里会拷贝 `cbs` 数组再遍历（`toArray(cbs)`），防止在回调中调用 `$off` 时修改了正在遍历的数组。

## 🌐 三、DOM 事件 vs 组件事件：从编译产物到绑定机制

> 链路位置：② 原生 DOM 事件（addEventListener）

### 原生元素上的 v-on：编译 → addEventListener

在普通 HTML 元素上写 `@click`，编译产物是 `{ on: { click: fn } }`：

```html
<!-- 模板 -->
<button @click="handleClick">提交</button>
```

```javascript
// 编译产物（render 函数）
_c('button', { on: { click: handleClick } }, [_v("提交")])
```

patch 阶段执行 `createElm` 创建真实 DOM 后，模块系统中的 `events` 模块会调用 `updateDOMListeners`：

```javascript
// src/platforms/web/runtime/modules/events.js
function updateDOMListeners(oldVnode, vnode) {
  const on = vnode.data.on || {}
  const oldOn = oldVnode.data.on || {}
  // 差量更新：新增 + 移除
  updateListeners(on, oldOn, add, remove, createOnceHandler, vnode.context)
}

function add(name, handler, capture, passive) {
  el.addEventListener(name, handler, { capture, passive })  // 👈 真正绑定到 DOM
}
```

### 组件上的 @event（无 .native）：进入 vm._events

```html
<PrescriptionForm @approved="onApproved" />
```

编译产物同样是 `{ on: { approved: onApproved } }`，但组件的 patch 流程不同：`createComponent` 阶段会把 `on` 对象解析出来，在子组件实例化时通过 `initEvents` 注入到 `vm._events`：

```javascript
// src/core/instance/events.js
function initEvents(vm) {
  vm._events = Object.create(null)
  const listeners = vm.$options._parentListeners  // 父组件传来的 { approved: fn }
  if (listeners) {
    updateComponentListeners(vm, listeners)  // 遍历调用 $on
  }
}
```

### .native 修饰符原理：绑到组件根元素的真实 DOM

```html
<PrescriptionForm @click.native="handleClick" />
```

编译产物是 `{ nativeOn: { click: handleClick } }`（注意是 `nativeOn` 不是 `on`）。

在 `createComponent` 阶段，`componentVNodeHooks.init` 执行时：

```javascript
// src/core/vdom/create-component.js（简化）
const componentVNodeHooks = {
  init(vnode) {
    const child = vnode.componentInstance = createComponentInstanceForVnode(vnode, activeInstance)
    child.$mount(vnode.elm)  // 挂载到真实 DOM

    // 处理 nativeOn：把监听器绑到组件根元素
    if (isDef(vnode.data.nativeOn)) {
      updateDOMListeners(emptyNode, vnode, vnode.elm)
      //                                   👆 用的是组件根元素的真实 DOM
    }
  }
}
```

**`.native` 的本质**：让父组件能够绕过 Vue 的自定义事件系统，直接在子组件的根 DOM 元素上绑定原生事件监听器。

| 写法 | 编译产物 | 触发机制 | 使用场景 |
|------|---------|---------|---------|
| `@click` on 原生元素 | `on.click` | addEventListener | 普通 DOM 点击 |
| `@click` on 组件 | `on.click` → `vm._events` | $emit('click') | 子组件主动触发 |
| `@click.native` on 组件 | `nativeOn.click` | addEventListener | 监听组件根元素原生点击 |

> 💬 **面试官**：`.native` 修饰符的原理是什么？它是如何绑定到组件根元素 DOM 的？
>
> ✅ 标准答案：`.native` 让编译器把事件写进 `nativeOn` 而不是 `on`，`createComponent` 执行时读取 `nativeOn`，在子组件根元素上调用 `addEventListener` 绑定。整个过程绕过了 `vm._events`，走的是真实 DOM 的原生事件绑定。
>
> 🎁 想加分：Vue 3 移除了 `.native` 修饰符，因为 `v-on` 的语义改为「在组件上监听父组件传入的事件，子组件在 `emits` 中未声明的事件自动绑到根元素」，不再需要显式写 `.native`。

## 🎛️ 四、事件修饰符的编译实现

> 链路位置：③ 事件修饰符（编译阶段展开为代码）

Vue 的事件修饰符不是运行时判断，**全部在编译阶段展开为代码**，由 `src/compiler/codegen/events.js` 的 `genHandler` 函数处理。

### .stop 和 .prevent：注入防卫代码

```html
<button @click.stop.prevent="fn">提交</button>
```

编译产物（handler 字符串）：

```javascript
// genHandler 生成的代码
function($event) {
  $event.stopPropagation();   // 👈 .stop 展开
  $event.preventDefault();    // 👈 .prevent 展开
  return fn($event)
}
```

`.stop` 展开为 `$event.stopPropagation()`，`.prevent` 展开为 `$event.preventDefault()`。这两个方法调用都是在 handler 包装函数里执行的，**和浏览器事件系统配合**，而不是 Vue 自己实现的冒泡/默认行为控制。

### .capture 和 .self：特殊标记

**`.capture`**：事件名前加 `!` 前缀，`updateDOMListeners` 识别后用 `addEventListener(name, fn, true)` 注册捕获阶段监听器：

```javascript
// updateDOMListeners 中
const capture = name.charAt(0) === '!'  // 识别 capture 标记
if (capture) name = name.slice(1)
el.addEventListener(name, fn, capture)
```

**`.self`**：注入 `if ($event.target !== $event.currentTarget) return` 判断，只有事件发生在元素自身时才执行：

```javascript
function($event) {
  if ($event.target !== $event.currentTarget) return  // 👈 .self 展开
  return fn($event)
}
```

### .once：createOnceHandler 包装

对于 DOM 事件，`.once` 有两条路径：
- 浏览器支持 `{ once: true }` 选项（现代浏览器）：直接传给 `addEventListener`
- 不支持时：用 `createOnceHandler` 包一层，手动调用后 `removeEventListener`

```javascript
// 简化版 createOnceHandler
function createOnceHandler(event, fn) {
  return function onceHandler() {
    const res = fn.apply(null, arguments)
    if (res !== null) {
      el.removeEventListener(event, onceHandler)
    }
  }
}
```

### .passive：性能优化标记

```html
<!-- 医疗场景：长处方列表触摸滚动 -->
<div @scroll.passive="onScroll">...</div>
```

编译产物：事件名前加 `&` 前缀，`updateDOMListeners` 识别后以 `{ passive: true }` 传给 `addEventListener`：

```javascript
el.addEventListener('scroll', fn, { passive: true })
```

`passive: true` 告知浏览器「此回调不会调用 `preventDefault()`」，浏览器无需等待 JS 执行完毕即可滚动，**大幅提升触摸滚动流畅度**。这是处理长列表（长处方、药品目录）时的必选优化。

**⚠️ .passive 不能与 .prevent 同用**：两者语义矛盾，Vue 会在控制台打出警告。

### 按键修饰符：_k 辅助函数过滤

```html
<input @keyup.enter="submit" />
```

编译产物：

```javascript
function($event) {
  // _k 是运行时辅助函数，负责 keyCode/keyName 的标准化匹配
  if (!$event.type.indexOf('key') && _k($event.keyCode, 'enter', 13, $event.key, 'Enter')) return
  return submit($event)
}
```

`_k` 负责抹平浏览器间 keyCode 的差异，支持 keyCode 数字写法和名称写法双重匹配。

> 💬 **面试官**：事件修饰符 `.stop / .prevent / .passive` 分别是如何编译实现的？
>
> ✅ 标准答案：修饰符在**编译阶段**由 `genHandler` 展开为代码，不是运行时判断。`.stop` → 在 handler 包装函数里插入 `$event.stopPropagation()`；`.prevent` → 插入 `$event.preventDefault()`；`.passive` → 事件名加 `&` 前缀，`addEventListener` 时传 `{ passive: true }` 第三参数。
>
> 🎁 想加分：`.capture` 是事件名加 `!` 前缀，`.once` 是加 `~` 前缀，`updateDOMListeners` 通过解析这些前缀来决定 `addEventListener` 的参数。`.passive` 和 `.prevent` 不能同时使用，因为两者语义矛盾：passive 声明不会阻止默认行为，prevent 要阻止默认行为。

## 📡 五、$listeners：父组件事件的透传机制

> 链路位置：④ $listeners（父→子事件透传）

### $listeners 的来源

在子组件初始化的 `initRender` 阶段，Vue 把父组件传入的事件监听器对象响应式化，挂到 `vm.$listeners`：

```javascript
// src/core/instance/render.js（initRender 简化）
defineReactive(vm, '$listeners', options._parentListeners || emptyObject, null, true)
```

`$listeners` 是响应式的，父组件更新事件监听器时，子组件 `$listeners` 自动同步。`.native` 修饰的事件**不在 `$listeners` 里**，它们在 `nativeOn` 里单独处理。

### v-on="$listeners" + inheritAttrs: false：完整透传方案

封装二次组件（如对 Element UI 的 `<el-input>` 再封装），需要把父组件的所有事件透传给内部组件：

```html
<!-- 医疗系统的 DrugInput 二次封装 -->
<template>
  <div class="drug-input">
    <label>{{ label }}</label>
    <!-- v-bind="$attrs" 透传非 prop 属性；v-on="$listeners" 透传所有事件 -->
    <el-input v-bind="$attrs" v-on="$listeners" />
  </div>
</template>

<script>
export default {
  name: 'DrugInput',
  props: ['label'],
  inheritAttrs: false   // 👈 阻止 $attrs 自动挂到根元素 <div>
}
</script>
```

父组件可以像使用原始 `<el-input>` 一样使用 `<DrugInput>`：

```html
<DrugInput
  label="药品名称"
  placeholder="请输入"
  clearable
  @input="onInput"
  @focus="onFocus"
  @blur="onBlur"
/>
```

所有的 `@input / @focus / @blur` 都通过 `$listeners` 透传到了内部的 `<el-input>`，不需要在 `DrugInput` 里逐一 `$emit`。

### $listeners vs $attrs

| 属性 | 包含内容 | 不包含 | 典型用途 |
|------|---------|--------|---------|
| `$attrs` | 父组件传入的非 prop 属性（含 class/style 除外） | props 中声明的属性 | 透传 HTML 属性到深层元素 |
| `$listeners` | 父组件绑定的所有事件监听器 | `.native` 修饰的事件 | 透传事件到深层元素 |

🔧 **真实案例**：在医疗系统里，`<PatientSearch>` 组件内部封装了 `<el-autocomplete>`，但业务方需要监听 `@select`、`@input`、`@clear` 等事件。如果逐一 `$emit` 会有遗漏，用 `v-on="$listeners"` 直接透传，封装成本接近零，且父组件的新增监听器也自动生效。

> 💬 **面试官**：`$listeners` 是什么？如何用它实现完整的事件透传？
>
> ✅ 标准答案：`$listeners` 是 Vue 在 `initRender` 阶段挂到实例上的响应式对象，包含父组件绑定的所有自定义事件监听器（`.native` 修饰的除外）。配合 `v-on="$listeners"` 可以把全部监听器透传给内部组件，再加 `inheritAttrs: false` + `v-bind="$attrs"` 就能实现属性和事件的完整透传。
>
> 🎁 想加分：Vue 3 移除了 `$listeners`，因为所有监听器都合并进了 `$attrs`，不再需要单独的 `$listeners`。迁移时注意这个变化。

```javascript
// 完整版 $on
Vue.prototype.$on = function(event, fn) {
  const vm = this
  if (Array.isArray(event)) {
    for (let i = 0, l = event.length; i < l; i++) {
      vm.$on(event[i], fn)
    }
  } else {
    (vm._events[event] || (vm._events[event] = [])).push(fn)
    if (hookRE.test(event)) {
      vm._hasHookEvent = true
    }
  }
  return vm
}

// 完整版 $emit
Vue.prototype.$emit = function(event) {
  const vm = this
  let cbs = vm._events[event]
  if (cbs) {
    cbs = cbs.length > 1 ? toArray(cbs) : cbs  // 拷贝防止遍历中修改
    const args = toArray(arguments, 1)          // 取出除 event 外的所有参数
    for (let i = 0, l = cbs.length; i < l; i++) {
      try {
        cbs[i].apply(vm, args)
      } catch (e) {
        handleError(e, vm, `event handler for "${event}"`)
      }
    }
  }
  return vm
}

// 完整版 $off
Vue.prototype.$off = function(event, fn) {
  const vm = this
  if (!arguments.length) {
    vm._events = Object.create(null)
    return vm
  }
  if (Array.isArray(event)) {
    for (let i = 0, l = event.length; i < l; i++) {
      vm.$off(event[i], fn)
    }
    return vm
  }
  const cbs = vm._events[event]
  if (!cbs) return vm
  if (!fn) {
    vm._events[event] = null
    return vm
  }
  let cb
  let i = cbs.length
  while (i--) {
    cb = cbs[i]
    if (cb === fn || cb.fn === fn) {
      cbs.splice(i, 1)
      break
    }
  }
  return vm
}

// 完整版 $once
Vue.prototype.$once = function(event, fn) {
  const vm = this
  function on() {
    vm.$off(event, on)
    fn.apply(vm, arguments)
  }
  on.fn = fn
  vm.$on(event, on)
  return vm
}
```

### genHandler（src/compiler/codegen/events.js）

```javascript
// 修饰符到代码的映射表
const modifierCode = {
  stop:    '$event.stopPropagation();',
  prevent: '$event.preventDefault();',
  self:    genGuard(`$event.target !== $event.currentTarget`),
  ctrl:    genGuard(`!$event.ctrlKey`),
  shift:   genGuard(`!$event.shiftKey`),
  alt:     genGuard(`!$event.altKey`),
  meta:    genGuard(`!$event.metaKey`),
  left:    genGuard(`'button' in $event && $event.button !== 0`),
  middle:  genGuard(`'button' in $event && $event.button !== 1`),
  right:   genGuard(`'button' in $event && $event.button !== 2`),
}

function genHandler(handler) {
  if (!handler) return 'function(){}'

  // 多个 handler（数组）
  if (Array.isArray(handler)) {
    return `[${handler.map(h => genHandler(h)).join(',')}]`
  }

  const isMethodPath = simplePathRE.test(handler.value)  // 是否是方法引用：如 "handleClick"
  const isFunctionExpression = fnExpRE.test(handler.value)  // 是否是函数表达式：如 "() => fn()"

  if (!handler.modifiers) {
    // 无修饰符，直接返回
    return isMethodPath || isFunctionExpression ? handler.value : `function($event){${handler.value}}`
  }

  // 有修饰符，生成包装函数
  let code = ''
  let genModifierCode = ''
  const keys = []
  for (const key in handler.modifiers) {
    if (modifierCode[key]) {
      genModifierCode += modifierCode[key]  // 👈 拼接防卫代码
    } else if (key !== 'exact') {
      keys.push(key)  // 按键修饰符
    }
  }
  if (keys.length) {
    code += genKeyFilter(keys)
  }
  if (genModifierCode) {
    code += genModifierCode
  }

  // 生成最终的包装函数
  const handlerCode = isMethodPath ? `return ${handler.value}($event)` : handler.value
  return `function($event){${code}${handlerCode}}`
}
```

```javascript
// src/events.js — 约 90 行，手写 Vue 2 事件系统核心

// ── 常量 ──────────────────────────────────────────────────────────
const hookRE = /^hook:/

// ── EventMixin：挂到 Vue 实例原型 ───────────────────────────────────
export function initEvents(vm) {
  vm._events = Object.create(null)
  vm._hasHookEvent = false
}

export function eventsMixin(Vue) {
  // $on
  Vue.prototype.$on = function(event, fn) {
    const vm = this
    if (Array.isArray(event)) {
      event.forEach(e => vm.$on(e, fn))
    } else {
      ;(vm._events[event] || (vm._events[event] = [])).push(fn)
      if (hookRE.test(event)) vm._hasHookEvent = true
    }
    return vm
  }

  // $emit
  Vue.prototype.$emit = function(event, ...args) {
    const vm = this
    const cbs = vm._events[event]
    if (cbs) {
      // 拷贝一份，防止回调中调用 $off 修改正在遍历的数组
      const list = cbs.length > 1 ? [...cbs] : cbs
      list.forEach(cb => {
        try { cb.apply(vm, args) }
        catch (e) { console.error(`[event error] ${event}:`, e) }
      })
    }
    return vm
  }

  // $off
  Vue.prototype.$off = function(event, fn) {
    const vm = this
    // 无参：清空所有
    if (!arguments.length) {
      vm._events = Object.create(null)
      return vm
    }
    // 数组形式
    if (Array.isArray(event)) {
      event.forEach(e => vm.$off(e, fn))
      return vm
    }
    const cbs = vm._events[event]
    if (!cbs) return vm
    // 只传 event：清空该事件
    if (!fn) { vm._events[event] = null; return vm }
    // 精确移除
    let i = cbs.length
    while (i--) {
      const cb = cbs[i]
      if (cb === fn || cb.fn === fn) { cbs.splice(i, 1); break }
    }
    return vm
  }

  // $once
  Vue.prototype.$once = function(event, fn) {
    const vm = this
    function on() {
      vm.$off(event, on)
      fn.apply(vm, arguments)
    }
    on.fn = fn  // 存原始引用，$off 可精确移除
    vm.$on(event, on)
    return vm
  }
}

// ── updateDOMListeners：简版 DOM 事件绑定 ────────────────────────────
const modifierMap = {
  '!': { capture: true },   // .capture
  '~': { once: true },      // .once
  '&': { passive: true },   // .passive
}

function parseModifiers(name) {
  const mods = { capture: false, once: false, passive: false }
  let clean = name
  for (const prefix of ['~&', '&~', '!~', '~!', '!', '~', '&']) {
    if (clean.startsWith(prefix)) {
      for (const char of prefix) Object.assign(mods, modifierMap[char] || {})
      clean = clean.slice(prefix.length)
      break
    }
  }
  return { name: clean, ...mods }
}

export function updateDOMListeners(el, oldOn, on) {
  // 移除旧的
  for (const rawName in oldOn) {
    if (!on[rawName]) {
      const { name } = parseModifiers(rawName)
      el.removeEventListener(name, oldOn[rawName])
    }
  }
  // 添加新的
  for (const rawName in on) {
    if (!oldOn[rawName]) {
      const { name, capture, once, passive } = parseModifiers(rawName)
      const handler = on[rawName]
      el.addEventListener(name, handler, { capture, once, passive })
    }
  }
}
```

## 🛠️ 八、生产级最佳实践

> 链路位置：最佳实践沉淀

### $once + hook:beforeDestroy：自动清理的优雅写法

手写 `$off` 清理的传统写法繁琐且易遗漏：

```javascript
// ❌ 传统写法：需要在 beforeDestroy 里手写 $off
export default {
  mounted() {
    eventBus.$on('drugUpdated', this.onDrugUpdated)
  },
  beforeDestroy() {
    eventBus.$off('drugUpdated', this.onDrugUpdated)  // 容易忘
  }
}

// ✅ 优雅写法：$once 监听 hook:beforeDestroy，自动清理
export default {
  mounted() {
    eventBus.$on('drugUpdated', this.onDrugUpdated)
    this.$once('hook:beforeDestroy', () => {
      eventBus.$off('drugUpdated', this.onDrugUpdated)
    })
  }
  // 不再需要 beforeDestroy 钩子
}
```

**原理**：Vue 在执行生命周期钩子时，会同时 `$emit('hook:beforeDestroy')`。`hook:beforeDestroy` 是 Vue 内部预留的 hook 事件名，`$once` 监听它后，组件销毁时自动触发清理逻辑，且只触发一次，完全不需要手写 `beforeDestroy`。

同理，定时器、WebSocket、ResizeObserver 等的清理都可以用这个模式：

```javascript
mounted() {
  const timer = setInterval(this.polling, 5000)
  this.$once('hook:beforeDestroy', () => clearInterval(timer))

  const ws = new WebSocket('wss://api.hospital.com/realtime')
  this.$once('hook:beforeDestroy', () => ws.close())
}
```

### EventBus 内存泄漏防范

EventBus 是组件间通信的常用方案，但**最容易引发内存泄漏**——组件销毁后，`$on` 注册的监听器若未移除，回调函数持有组件实例的引用，导致组件无法被 GC 回收。

```javascript
// 创建 EventBus（独立 Vue 实例）
export const eventBus = new Vue()

// ❌ 有内存泄漏风险
export default {
  created() {
    eventBus.$on('prescriptionReady', this.handlePrescription)
    // 组件销毁后监听器仍在 eventBus._events 里
  }
}

// ✅ 正确写法：$once + hook:beforeDestroy 自动清理
export default {
  created() {
    eventBus.$on('prescriptionReady', this.handlePrescription)
    this.$once('hook:beforeDestroy', () => {
      eventBus.$off('prescriptionReady', this.handlePrescription)
    })
  }
}
```

大型项目中推荐用 Vuex 替代 EventBus，减少事件管理负担。

### .passive 滚动优化

```html
<!-- 医疗场景：长处方列表（可能有几十条药品）的触摸滚动 -->
<div class="prescription-list" @scroll.passive="onScroll" @touchmove.passive="onTouchMove">
  <div v-for="drug in drugs" :key="drug.id" class="drug-item">...</div>
</div>
```

不加 `.passive` 时，浏览器在每次 scroll/touchmove 事件前都必须等待 JS 执行完毕，确认是否有 `preventDefault()`——即使没有也要等。加上 `.passive` 后，浏览器直接滚动，无需等待，**触摸滚动帧率可从 30fps 提升到 60fps**。

### 组件封装透传 $listeners 的完整写法

```html
<!-- 完整的二次封装模板 -->
<template>
  <div class="my-input-wrapper">
    <input
      v-bind="$attrs"
      v-on="listenersWithoutNative"
      class="my-input"
    />
  </div>
</template>

<script>
export default {
  inheritAttrs: false,
  computed: {
    listenersWithoutNative() {
      // 过滤掉不需要透传给 input 的事件
      const { click, ...rest } = this.$listeners
      return rest
    }
  }
}
</script>
```

Vue 2 的 `$listeners` 是整体对象，可以通过解构过滤部分事件再透传，灵活控制哪些事件穿透、哪些在本层消费。

## 💡 一张图总结（面试速记）

| 事件类型 | 存储位置 | 触发方式 | 会冒泡 | 绑定时机 | 面试频率 |
|---------|---------|---------|-------|---------|---------|
| 组件自定义事件（`$emit`） | `vm._events` | `$emit` | ❌ | `initEvents` | ⭐⭐⭐⭐⭐ |
| 原生元素 `@event` | 真实 DOM 节点 | 浏览器触发 | ✅ | `patch → updateDOMListeners` | ⭐⭐⭐⭐ |
| 组件 `@event.native` | 组件根 DOM 节点 | 浏览器触发 | ✅ | `createComponent → init` | ⭐⭐⭐⭐ |
| `$listeners` 透传 | 父组件 `_events` | `$emit` | ❌ | `initRender` 响应式化 | ⭐⭐⭐ |
| 事件修饰符 | 无（编译展开） | 代码内联执行 | — | 编译阶段 `genHandler` | ⭐⭐⭐⭐ |

**记住这一句**：`$emit` 是发布订阅，DOM 事件是浏览器机制——修饰符在编译阶段就展开成代码，运行时没有额外开销。

## 📝 留个问题

`$once + hook:beforeDestroy` 模式里，有一个细节值得思考：如果一个组件在 `mounted` 里注册了 EventBus 监听器，但在 `beforeDestroy` 之前组件被 `keep-alive` 缓存了（进入 `deactivated` 状态而非真正销毁），`hook:beforeDestroy` 不会触发——监听器会一直存在，直到组件真正销毁。

**问题**：在 `keep-alive` 场景下，应该怎么管理 EventBus 监听器，才能既避免内存泄漏，又能在组件再次激活时正常工作？
